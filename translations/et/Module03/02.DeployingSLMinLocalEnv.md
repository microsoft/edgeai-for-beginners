# Section 2: Kohalik keskkonna juurutamine - privaatsust esikohale seadvad lahendused

Väikeste keelemudelite (SLM) lokaalne juurutamine tähistab paradigmanihket privaatsust säästvate ja kulutõhusate tehisintellektilahenduste suunas. See põhjalik juhend uurib kahte võimsat raamistiku—Ollama ja Microsoft Foundry Local—mis võimaldavad arendajatel täiel määral kasutada SLM-ide potentsiaali ja samal ajal säilitada täielik kontroll oma juurutuskeskkonna üle.

## Sissejuhatus

Selles õppetükis uurime edasijõudnud juurutamisstrateegiaid väikeste keelemudelite jaoks kohalikus keskkonnas. Käsitleme kohaliku tehisintellekti juurutamise põhikontseptsioone, vaatleme kahte juhtivat platvormi (Ollama ja Microsoft Foundry Local) ning anname praktilist juhendit tootmiskasutuseks valmis lahenduste rakendamiseks.

## Õpieesmärgid

Selle õppetüki lõpuks saate:

- Mõista kohalike SLM juurutamisraamistike arhitektuuri ja eeliseid.
- Rakendada tootmiskõlblikke juurutusi kasutades Ollamat ja Microsoft Foundry Localit.
- Võrrelda ja valida sobiv platvorm vastavalt konkreetsetele nõuetele ja piirangutele.
- Optimeerida kohalikke juurutusi jõudluse, turvalisuse ja mastaapsuse tagamiseks.

## Kohalike SLM juurutamisarhitektuuride mõistmine

Kohalik SLM juurutamine tähistab fundamentaalset muutust pilvepõhistest tehisintellektiteenustest kohapealseteks, privaatsust säilitavateks lahendusteks. See lähenemisviis võimaldab organisatsioonidel hoida täielikku kontrolli oma tehisintellektitaristu üle ning tagab andmete suveräänsuse ja operatiivse sõltumatuse.

### Juurutamisraamistike klassifikatsioonid

Erinevate juurutamisviiside mõistmine aitab valida õige strateegia konkreetsete kasutusjuhtude jaoks:

- **Arendusele orienteeritud**: sujuv seadistus katsetamiseks ja prototüüpimiseks
- **Ettevõtte-tasemel**: tootmiskõlblikud lahendused ettevõtte integratsioonivõimalustega  
- **Platvormideülene**: universaalne ühilduvus erinevate opsüsteemide ja riistvaraga

### Kohaliku SLM juurutamise peamised eelised

Kohalik SLM juurutamine pakub mitmeid olulisi eeliseid, mis muudavad selle ideaalseks ettevõtte- ja privaatsustundlike rakenduste jaoks:

**Privaatsus ja turvalisus**: Kohalik töötlemine tagab, et tundlikud andmed ei lahku kunagi organisatsiooni taristust, võimaldades vastavust GDPR, HIPAA ja teistele regulatiivsetele nõuetele. Klassifitseeritud keskkondade jaoks on võimalikud õhukeeruga lahendused ning täielikud auditeerijäljed säilitavad turvaülevaate.

**Kulutõhusus**: Tokenipõhiste hindamismudelite elimineerimine vähendab märkimisväärselt tegevuskulusid. Madalam andmemaht ja vähendatud pilvesõltuvus tagavad ettevõtte eelarve jaoks ennustatavad kuluarhitektuurid.

**Jõudlus ja töökindlus**: Kiirem üldistulemuste arvutus ilma võrgu latentsuseta võimaldab reaalajas rakendusi. Võrguühenduseta funktsionaalsus tagab katkestusteta töö olenemata internetiühendusest, samas kui kohalik ressursside optimeerimine varustab stabiilse jõudlusega.

## Ollama: universaalne kohaliku juurutamise platvorm

### Põhiarhitektuur ja filosoofia

Ollama on loodud universaalseks, arendajasõbralikuks platvormiks, mis demokratiseerib kohaliku LLM juurutamise mitmekesistes riistvara konfiguratsioonides ja opsüsteemides.

**Tehniline alus**: Ollama põhineb tugeval llama.cpp raamistikul ja kasutab efektiivset GGUF mudeliformaati optimaalseks jõudluseks. Platvormi platvormideülene ühildumine tagab ühtlase käitumise Windowsi, macOSi ja Linuxi keskkondades ning nutikas ressursside haldus optimeerib CPU, GPU ja mälu kasutust.

**Disainifilosoofia**: Ollama seab prioriteediks lihtsuse ilma funktsionaalsusest loobumata, pakkudes nullkonfiguratsiooniga juurutust kohe tootlikuks tööks. Platvorm hoiab laia mudelite ühilduvust ja ühtseid API-sid erinevate mudeli arhitektuuride vahel.

### Täiustatud funktsioonid ja võimekused

**Mudelite halduse tipptase**: Ollama pakub mudelite elutsükli täielikku haldust automaatse tõmbamise, vahemällu salvestamise ja versioonihaldusega. Platvorm toetab ulatuslikku mudelite ökosüsteemi, kaasa arvatud Llama 3.2, Google Gemma 2, Microsoft Phi-4, Qwen 2.5, DeepSeek, Mistral ja spetsiaalsed sisestusmudelid.

**Kohandamine Modelfailide kaudu**: Edasijõudnud kasutajad saavad luua kohandatud mudelikonfiguratsioone, mis sisaldavad spetsiifilisi parameetreid, süsteemipäringuid ja käitumise muutmisi. See võimaldab domeenipõhiseid optimeerimisi ja spetsiaalseid rakendusnõudeid.

**Jõudluse optimeerimine**: Ollama tuvastab ja kasutab automaatselt olemasolevaid riistvara kiirendusi, sealhulgas NVIDIA CUDA, Apple Metali ja OpenCLI. Nutikas mäluhaldus tagab optimaalsete ressursside kasutuse erinevate riistvarakonfiguratsioonide vahel.

import json

# API lõpp-punkti konfiguratsioon
OLLAMA_ENDPOINT = "http://localhost:11434/api/generate"

params = {
    "model": "phi4:mini",
    "prompt": "Write a function to calculate the Fibonacci sequence in Python",
    "system": "You are a helpful Python programming assistant. Provide clean, efficient code with comments.",
    "stream": False,
    "options": {
        "temperature": 0.2,
        "top_p": 0.95,
        "num_predict": 1024
    }
}

# Tee API päring
response = requests.post(OLLAMA_ENDPOINT, json=params)
result = response.json()

# Töötle ja kuva vastus
print(result["response"])

# Voogedastuse näide (reaalajas vastuste jaoks)
def stream_response():
    params["stream"] = True
    response = requests.post(OLLAMA_ENDPOINT, json=params, stream=True)
    
    for line in response.iter_lines():
        if line:
            chunk = json.loads(line)
            if "response" in chunk:
                print(chunk["response"], end="", flush=True)
            if chunk.get("done", False):
                print()
                break

**JavaScript/TypeScript integratsioon (Node.js)**:

```javascript
const axios = require('axios');

// API konfiguratsioon
const OLLAMA_API = 'http://localhost:11434/api';

// Funktsioon teksti genereerimiseks Ollama abil
async function generateText(model, prompt, systemPrompt = '') {
  try {
    const response = await axios.post(`${OLLAMA_API}/generate`, {
      model: model,
      prompt: prompt,
      system: systemPrompt,
      stream: false,
      options: {
        temperature: 0.7,
        top_k: 40,
        top_p: 0.9,
        num_predict: 1024
      }
    });
    
    return response.data.response;
  } catch (error) {
    console.error('Error generating text:', error.message);
    throw error;
  }
}

// Näidiskasutus Express API-s
const express = require('express');
const app = express();
app.use(express.json());

app.post('/api/chat', async (req, res) => {
  const { message } = req.body;
  
  try {
    const response = await generateText(
      'phi4:mini',
      message,
      'You are a helpful AI assistant.'
    );
    
    res.json({ response });
  } catch (error) {
    res.status(500).json({ error: 'Failed to generate response' });
  }
});

app.listen(3000, () => {
  console.log('API server running on port 3000');
});
```

## Microsoft Foundry Local: ettevõtte ääre AI platvorm

### Ettevõtte-tasemel arhitektuur

Microsoft Foundry Local on kõikehõlmav ettevõttelahendus, mis on loodud spetsiaalselt tootmisääre AI juurutamiseks sügava integreeritusega Microsofti ökosüsteemi.

**ONNX-põhine alus**: Põhineb tööstusharu standardil ONNX Runtime'il, Foundry Local tagab optimeeritud jõudluse erinevates riistvara arhitektuurides. Platvorm kasutab Windows ML integratsiooni natiivseks Windowsi optimeerimiseks, hoides samas platvormideülest ühilduvust.

**Riistvara kiirenduse tipptase**: Foundry Localil on intelligentne riistvara tuvastus ja optimeerimine CPU-de, GPU-de ja NPU-de jaoks. Sügav koostöö riistvaratarnijatega (AMD, Intel, NVIDIA, Qualcomm) tagab optimaalse jõudluse ettevõtte riistvarakonfiguratsioonidel.

### Täiustatud arendajakogemus

**Mitme liidesega ligipääs**: Foundry Local pakub laiaulatuslikke arendusliideseid, sealhulgas võimsat CLI mudelite halduseks ja juurutuseks, mitme keele SDKsid (Python, NodeJS) natiivseks integratsiooniks ning RESTful API-sid OpenAI ühilduvusega sujuvaks migratsiooniks.

**Visual Studio integratsioon**: Platvorm ühildub sujuvalt AI Toolkitiga VS Code'is, pakkudes mudelite konverteerimise, kvantisatsiooni ja optimeerimise tööriistu arenduskeskkonnas. See integratsioon kiirendab arendusprotsesse ja vähendab juurutamise keerukust.

**Mudeli optimeerimise torujuhe**: Microsoft Olive integratsioon võimaldab keerukaid mudeli optimeerimise töövooge, sealhulgas dünaamilist kvantisatsiooni, graafi optimeerimist ja riistvaraspetsiifilist seadistust. Pilvepõhised konverteerimisvõimalused läbi Azure ML tagavad mastaapse optimeerimise suurtele mudelitele.

### Tootmisrakenduse strateegiad

**Paigaldus ja konfiguratsioon**:

## Võrdlev analüüs: Ollama vs Foundry Local

### Tehnilise arhitektuuri võrdlus

| **Aspekt** | **Ollama** | **Foundry Local** |
|------------|------------|-------------------|
| **Mudeli formaat** | GGUF (llama.cpp kaudu) | ONNX (ONNX Runtime'i kaudu) |
| **Platvormifookus** | Universaalne platvormideülene | Windows/Ettevõtte optimeerimine |
| **Riistvaraintegraatsioon** | Üldine GPU/CPU tugi | Sügav Windows ML, NPU tugi |
| **Optimeerimine** | llama.cpp kvantisatsioon | Microsoft Olive + ONNX Runtime |
| **Ettevõtte funktsioonid** | Ühiskondlikult juhitud | Ettevõtte-tasemel koos SLA-dega |

### Jõudluse omadused

**Ollama jõudlus tugevused**:
- Silmapaistev CPU jõudlus tänu llama.cpp optimeerimisele
- Ühtlane käitumine erinevatel platvormidel ja riistvaral
- Tõhus mälu kasutamine nutika mudelilaadimisega
- Kiired külmkäivituse ajad arendus- ja testimisskenaarioides

**Foundry Local jõudluse eelised**:
- Üleolev NPU kasutus kaasaegsel Windowsi riistvaral
- Optimeeritud GPU kiirendus tarnijate partnerluste kaudu
- Ettevõtte-taseme jõudluse järelevalve ja optimeerimine
- Mastaapne juurutamisvõimekus tootmiskeskkondades

### Arendajakogemuse analüüs

**Ollama arendajakogemus**:
- Minimaalsed seadistusnõuded ja kohene tootlikkus
- Intuitiivne käsurealiides kõigi toimingute jaoks
- Ulatuslik kogukonna tugi ja dokumentatsioon
- Paindlik kohandamine Modelfailide kaudu

**Foundry Local arendajakogemus**:
- Kõikehõlmav IDE integratsioon Visual Studio ökosüsteemis
- Ettevõtte arendusvood koos meeskonnatöö funktsioonidega
- Professionaalsed tugikanalid Microsofti toetusega
- Täiustatud silumis- ja optimeerimistööriistad

### Kasutusjuhtude optimeerimine

**Vali Ollama, kui**:
- Arendad platvormideüleseid rakendusi, mis nõuavad ühtlast käitumist
- Eelistad avatud lähtekoodiga läbipaistvust ja kogukonna panuseid
- Töötad piiratud ressursside või eelarve tingimustes
- Ehita katse- või teadusuuringutepõhiseid rakendusi
- Vajad laialdast mudelite ühilduvust erinevate arhitektuuride vahel

**Vali Foundry Local, kui**:
- Juurutad ettevõtte rakendusi rangete jõudlusnõuetega
- Kasutad Windows-spetsiifilisi riistvarasüsteeme (NPU, Windows ML)
- Vajad ettevõtte tuge, SLA-sid ja vastavusfunktsioone
- Ehita tootmisrakendusi Microsofti ökosüsteemi integreerimisega
- Vajad arenenud optimeerimisvahendeid ja professionaalseid arendusvooge

## Tulevikutrendid ja kaalutlused

### Tekkivad tehnoloogiad

Kohaliku SLM juurutamise maastik areneb edasi mitmete oluliste trendidega:

**Täiustatud mudeli arhitektuurid**: Ilmuvad järgmise põlvkonna SLM-id, millel on parem efektiivsus ja võimekuse suhe, sealhulgas eksperdidööningute mudelid dünaamiliseks mastaapimiseks ja spetsialiseeritud arhitektuurid äärejuurutuseks.

**Riistvaraintegraatsioon**: Sügavam integreerimine spetsialiseeritud AI riistvaraga, sh NPU-d, kohandatud kiibistik ja äärearvutuse kiirendid parandavad veelgi jõudlusvõimekust.

**Ökosüsteemi evolutsioon**: Juurutamisplatvormide standardiseerimise jõupingutused ja paremad koostalitlussuutlikkused erinevate raamistikude vahel lihtsustavad mitmeplatvormilist juurutamist.

### Tööstuse kasutuselevõtu mustrid

**Ettevõtte kasutuselevõtt**: Kasvav kasutuselevõtt, mida ajendab privaatsuse nõuete, kulude optimeerimise ja regulatiivse vastavuse vajadused. Valitsus- ja kaitsesektorid keskenduvad eriti õhukeeruga juurutustele.

**Globaalne kontekst**: Rahvusvahelised andmesuvereniteedi nõuded soodustavad kohaliku juurutamise laialdasemat kasutuselevõttu, eriti regioonides, kus kehtivad ranged andmekaitsenõuded.

## Väljakutsed ja kaalutlused

### Tehnilised väljakutsed

**Taristu nõuded**: Kohalik juurutamine vajab hoolikat mahtude planeerimist ja riistvara valikut. Organisatsioonid peavad tasakaalustama jõudlusnõudeid kulupiirangutega ja tagama kasvava töökoormuse jaoks skaleeritavuse.

**🔧 Hooldus ja uuendused**: Regulaarseid mudeli uuendusi, turvapaiku ja jõudluse optimeerimist nõuab pühendunud ressursse ja ekspertiisi. Automaatiseeritud juurutustorud on tootmiskeskkondades vältimatud.

### Turvalisuse kaalutlused

**Mudeli turvalisus**: Omavaraliste mudelite kaitsmiseks volitamata juurdepääsu või ärakatsumise eest on vaja ulatuslikke turvameetmeid, sealhulgas krüpteerimist, ligipääsukontrolle ja auditeerimise logimist.

**Andmekaitse**: Tagada turvaline andmetöötlus kogu üldistuse torujuhtmes, säilitades jõudlus- ja kasutatavuse standardid.

## Kokkuvõte

Valik Ollama ja Microsoft Foundry Local vahel sõltub konkreetsetest organisatsiooni nõuetest, tehnilistest piirangutest ja strateegilistest eesmärkidest. Mõlemad platvormid pakuvad köitvaid eeliseid kohaliku SLM juurutamise jaoks, kus Ollama paistab silma platvormideülene ühilduvuse ja kasutusmugavusega, samas kui Foundry Local pakub ettevõtte-tasemelist optimeerimist ja Microsofti ökosüsteemi integreerimist.

AI juurutamise tulevik seisneb hübriidlähenemistes, mis ühendavad kohaliku töötlemise eelised pilvemastaapsete võimalustega. Organisatsioonid, kes valdavad kohaliku SLM juurutamise, on hästi positsioneeritud AI tehnoloogiate kasutamiseks, säilitades samas kontrolli oma andmete ja taristu üle.

Kohaliku SLM juurutamise edu nõuab tehniliste nõuete, turvariskide ja operatiivsete protseduuride hoolikat kaalumist. Parimate tavade järgimise ja nende platvormide tugevuste kasutamisega saavad organisatsioonid ehitada vastupidavaid, mastaapseid ja turvalisi tehisintellektilahendusi, mis vastavad nende konkreetsetele vajadustele ja piirangutele.
