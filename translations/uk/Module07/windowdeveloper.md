# Керівництво з розробки Windows Edge AI

## Вступ

Ласкаво просимо до Windows Edge AI Development — вашого всеосяжного керівництва з побудови інтелектуальних додатків, які використовують потужність штучного інтелекту на пристрої за допомогою платформи Windows AI Foundry від Microsoft. Це керівництво спеціально розроблене для розробників Windows, які хочуть інтегрувати передові можливості Edge AI у свої додатки, використовуючи повний спектр апаратного прискорення Windows.

### Переваги Windows AI

Windows AI Foundry представляє єдину, надійну та безпечну платформу, яка підтримує повний життєвий цикл розробника ШІ — від вибору та тонкого налаштування моделей до оптимізації та розгортання на процесорах CPU, GPU, NPU та гібридних хмарних архітектурах. Ця платформа демократизує розробку ШІ, надаючи:

- **Апаратна абстракція**: Безшовне розгортання на кремнії AMD, Intel, NVIDIA та Qualcomm
- **Інтелект на пристрої**: Приватний ШІ, що працює повністю на локальному обладнанні
- **Оптимізована продуктивність**: Моделі, попередньо оптимізовані для конфігурацій апаратного забезпечення Windows
- **Готовність до підприємств**: Забезпечення безпеки та відповідності виробничого рівня

### Windows ML 
Windows Machine Learning (ML) дозволяє розробникам на C#, C++ та Python запускати моделі ШІ ONNX локально на ПК з Windows через ONNX Runtime з автоматичним керуванням провайдерами виконання для різного обладнання (CPU, GPU, NPU). [ONNX Runtime](https://onnxruntime.ai/docs/) може використовуватися з моделями з PyTorch, Tensorflow/Keras, TFLite, scikit-learn та інших фреймворків.


![WindowsML A diagram illustrating an ONNX model going through Windows ML to then reach NPUs, GPUs, and CPUs.l](https://learn.microsoft.com/en-us/windows/ai/images/winml-diagram.png)

Windows ML надає спільну копію ONNX Runtime в межах Windows, а також можливість динамічно завантажувати провайдерів виконання (EP).

### Чому Windows для Edge AI?

**Універсальна підтримка апаратного забезпечення**
Windows ML забезпечує автоматичну оптимізацію апаратного забезпечення по всій екосистемі Windows, гарантуючи, що ваші додатки ШІ працюватимуть максимально ефективно незалежно від базової архітектури кремнію.

**Інтегроване середовище виконання ШІ**
Вбудований движок виведення Windows ML усуває складні вимоги налаштування, дозволяючи розробникам зосередитись на логіці додатку, а не на інфраструктурі.

**Оптимізація для Copilot+ ПК**
Цільові API, розроблені спеціально для пристроїв Windows наступного покоління з присвяченими нейронними процесорними блоками (NPU), що забезпечують виняткову продуктивність на ват.

**Екосистема розробників**
Багаті інструменти, включно з інтеграцією Visual Studio, повною документацією та прикладами додатків, що прискорюють цикли розробки.

## Навчальні цілі

Завершивши це керівництво з розробки Windows Edge AI, ви освоїте основні навички для створення готових до виробництва додатків ШІ на платформі Windows.

### Основні технічні компетенції

**Володіння Windows AI Foundry**
- Розуміння архітектури та компонентів платформи Windows AI Foundry
- Навігація по повному життєвому циклу розробки ШІ в екосистемі Windows
- Впровадження найкращих практик безпеки для додатків ШІ на пристрої
- Оптимізація додатків для різних конфігурацій апаратного забезпечення Windows

**Експертиза інтеграції API**
- Володіння API Windows AI для тексту, зору та мультимодальних додатків
- Інтеграція мовної моделі Phi Silica для генерації тексту та логіки
- Розгортання можливостей комп’ютерного зору з використанням вбудованих API обробки зображень
- Налаштування попередньо навчених моделей із застосуванням технік LoRA (адаптація низького рангу)

**Локальна реалізація Foundry**
- Огляд, оцінка і розгортання відкритих мовних моделей за допомогою Foundry Local CLI
- Розуміння оптимізації моделей і квантизації для локального розгортання
- Впровадження офлайн можливостей ШІ, що працюють без підключення до Інтернету
- Керування життєвим циклом моделей і оновленнями у виробничих середовищах

**Розгортання Windows ML**
- Впровадження користувацьких моделей ONNX в додатки Windows із Windows ML
- Використання автоматичного апаратного прискорення на архітектурах CPU, GPU, NPU
- Впровадження виведення в реальному часі з оптимальним використанням ресурсів
- Проєктування масштабованих додатків ШІ для різних категорій пристроїв Windows

### Навички розробки додатків

**Кросплатформна розробка Windows**
- Створення додатків із підтримкою ШІ за допомогою .NET MAUI для універсального розгортання на Windows
- Інтеграція можливостей ШІ у Win32, UWP та Progressive Web Applications
- Реалізація адаптивних UI, що підлаштовуються під стан обробки ШІ
- Обробка асинхронних операцій ШІ із застосуванням відповідних паттернів UX

**Оптимізація продуктивності**
- Профілювання та оптимізація продуктивності виведення ШІ на різних апаратних конфігураціях
- Впровадження ефективного керування пам’яттю для великих мовних моделей
- Проєктування додатків з плавним зниженням якості відповідно до доступних апаратних можливостей
- Застосування стратегій кешування для часто використовуваних операцій ШІ

**Готовність до виробництва**
- Впровадження комплексної обробки помилок та механізмів відкату
- Проєктування телеметрії та моніторингу продуктивності додатків ШІ
- Застосування найкращих практик безпеки для локального зберігання та виконання моделей ШІ
- Планування стратегій розгортання для корпоративних та споживчих додатків

### Бізнес та стратегічне розуміння

**Архітектура додатків ШІ**
- Проєктування гібридних архітектур із оптимізацією між локальною та хмарною обробкою ШІ
- Оцінка компромісів між розміром моделі, точністю та швидкістю виведення
- Планування архітектур потоків даних, що забезпечують приватність і інтелектуальні можливості
- Впровадження економічно ефективних рішень ШІ, що масштабуются відповідно до потреб користувачів

**Позиціонування на ринку**
- Розуміння конкурентних переваг нативних AI-додатків Windows
- Визначення випадків використання, де на пристрої AI забезпечує кращий користувацький досвід
- Розробка стратегій виходу на ринок для додатків Windows із покращеним ШІ
- Позиціонування додатків із використанням переваг екосистеми Windows

### Загальний робочий процес прикладів

Більшість прикладів Windows ML дотримуються такого стандартного шаблону:

1. **Ініціалізація середовища** — створення середовища ONNX Runtime
2. **Реєстрація провайдерів виконання** — виявлення та реєстрація доступних апаратних прискорювачів (CPU, GPU, NPU)
3. **Завантаження моделі** — завантаження моделі ONNX, за потреби компіляція для цільового обладнання
4. **Попередня обробка вхідних даних** — конвертація зображень/даних у формат введення моделі
5. **Запуск виведення** — виконання моделі та отримання прогнозів
6. **Обробка результатів** — застосування softmax і відображення найкращих прогнозів

### Підтримка апаратного забезпечення

Всі приклади автоматично виявляють та використовують доступне обладнання:
- **CPU** — універсальна підтримка на всіх пристроях Windows
- **GPU** — автоматичне виявлення та оптимізація для доступного графічного обладнання
- **NPU** — використання нейронних процесорних блоків на підтримуваних пристроях (Copilot+ ПК)

## Компоненти платформи Windows AI Foundry

### 1. Windows AI APIs

Windows AI APIs надають готові до використання можливості ШІ на основі моделей на пристрої, оптимізовані для ефективності та продуктивності на пристроях Copilot+ ПК з мінімальними вимогами налаштування.

#### Основні категорії API

**Мовна модель Phi Silica**
- Невелика, але потужна мовна модель для генерації та логічного аналізу тексту
- Оптимізована для виведення в реальному часі з мінімальним споживанням енергії
- Підтримка кастомного тонкого налаштування за допомогою технік LoRA
- Інтеграція з семантичним пошуком Windows і пошуком знань

**API комп’ютерного зору**
- **Розпізнавання тексту (OCR)**: Витяг тексту із зображень з високою точністю
- **Покращення роздільної здатності зображень**: Масштабування зображень за допомогою локальних моделей ШІ
- **Сегментація зображень**: Ідентифікація та ізоляція конкретних об'єктів на зображеннях
- **Опис зображень**: Генерація детальних текстових описів візуального вмісту
- **Видалення об'єктів**: Усунення небажаних об'єктів зображень із використанням ШІ та інпейнтингу

**Мультимодальні можливості**
- **Інтеграція зору і мови**: Поєднання розуміння тексту і зображень
- **Семантичний пошук**: Підтримка природних мовних запитів по мультимедійному контенту
- **Пошук знань**: Побудова інтелектуальних пошукових систем з локальними даними

#### Категорії прикладів за випадками використання

**RAG (генерація з підсиленням за допомогою пошуку)**
- **dotNET/rag**: Повна реалізація RAG із використанням Semantic Kernel, векторної бази даних Qdrant та вбудов JINA
- **Архітектура**: Імпорт документів → Розбиття тексту → Векторні вбудови → Пошук подібностей → Відповіді з урахуванням контексту
- **Технології**: Microsoft.SemanticKernel, Qdrant.Client, вбудови BERT ONNX, покрокове потокове завершення чату

**Десктопні додатки**
- **electron/foundry-chat**: Готовий до виробництва чат з можливістю перемикання між локальними та хмарними моделями
- **Особливості**: вибір моделі, потокові відповіді, обробка помилок, кросплатформене розгортання
- **Архітектура**: основний процес Electron, IPC-комунікація, безпечні скрипти preload

## Вирішення проблем та відлагодження

### Загальні проблеми розробки

**Проблеми з конфігурацією збірки**

- Перевірте сумісність версії Windows App SDK (потрібна 1.8.1+)

- Перевірте, що інструменти збірки підтримують цільову версію фреймворку

**Проблеми завантаження моделей**
- Перевірте сумісність моделей ONNX із Windows ML
- Перевірте цілісність файлів моделей та вимоги до формату
- Переконайтесь у вимогах апаратних можливостей для конкретних моделей

- Забезпечте реєстрацію провайдерів виконання для апаратного прискорення

**Питання вибору режиму розгортання**
- **Режим самоочищуваний (Self-Contained)**: повністю підтримується з більшим розміром розгортання
- **Залежний від фреймворку режим (Framework-Dependent)**: менший розмір, але вимагає загального runtime
- **Неупаковані додатки**: більше не підтримуються для Windows AI API
- Використовуйте `dotnet run -p:Platform=ARM64 -p:SelfContained=true` для самостійного ARM64 розгортання

**Проблеми продуктивності**
- Профілюйте продуктивність додатка на різних апаратних конфігураціях
- Виявляйте вузькі місця в AI обробці

- Реалізуйте моніторинг продуктивності та оповіщення

- Реалізуйте безперебійні механізми оновлення моделей
- Проєктуйте додатки для адаптації до покращених можливостей моделей
- Плануйте зворотну сумісність з існуючими моделями
- Реалізуйте A/B тестування для оцінки продуктивності моделей

**Еволюція функціональності**
- Проєктуйте модульні архітектури, що підтримують нові AI можливості
- Плануйте інтеграцію нових API Windows AI
- Реалізуйте функціональні прапорці для поступового впровадження можливостей
- Проєктуйте інтерфейси користувача, що адаптуються до покращених AI функцій

## Висновок

Розробка Windows Edge AI представляє собою поєднання потужних AI можливостей із надійною, безпечною та масштабованою платформою Windows. Опанувавши екосистему Windows AI Foundry, розробники можуть створювати інтелектуальні додатки, що забезпечують винятковий користувацький досвід при збереженні найвищих стандартів конфіденційності, безпеки та продуктивності.

Поєднання Windows AI API, Foundry Local і Windows ML надає неперевершену основу для створення наступного покоління інтелектуальних додатків Windows. Оскільки AI продовжує розвиватися, платформа Windows гарантує, що ваші додатки масштабуватимуться разом із новими технологіями, зберігаючи сумісність та продуктивність у різноманітній екосистемі апаратного забезпечення Windows.

Незалежно від того, чи створюєте ви споживацькі додатки, корпоративні рішення чи спеціалізовані галузеві інструменти, розробка Windows Edge AI дає змогу створювати інтелектуальні, чутливі та глибоко інтегровані рішення, які максимально використовують потенціал сучасних пристроїв Windows.
