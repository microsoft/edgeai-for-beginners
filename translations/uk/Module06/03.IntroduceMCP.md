# Розділ 03 - Інтеграція протоколу контексту моделі (MCP)

## Вступ до MCP (Model Context Protocol)

Протокол контексту моделі (MCP) — це стандарт з відкритим кодом для підключення AI-застосунків до зовнішніх систем. Використовуючи MCP, AI-застосунки, такі як Claude або ChatGPT, можуть підключатися до джерел даних (наприклад, локальні файли, бази даних), інструментів (наприклад, пошукові системи, калькулятори) та робочих процесів (наприклад, спеціалізовані підказки) — що дозволяє їм отримувати ключову інформацію та виконувати завдання.

Уявіть MCP як **USB-C порт для AI-застосунків**. Так само, як USB-C забезпечує стандартизований спосіб підключення електронних пристроїв, MCP забезпечує стандартизований спосіб підключення AI-застосунків до зовнішніх систем.

### Що може забезпечити MCP?

MCP відкриває потужні можливості для AI-застосунків:

- **Персоналізовані AI-асистенти**: Агенти можуть отримувати доступ до вашого Google Календаря та Notion, виступаючи у ролі більш персоналізованого AI-асистента
- **Розвинене генерування коду**: Claude Code може створити весь веб-додаток на основі дизайну у Figma
- **Інтеграція даних підприємства**: Корпоративні чат-боти можуть підключатися до кількох баз даних організації, надаючи користувачам можливість аналізувати дані через чат
- **Креативні робочі процеси**: AI-моделі можуть створювати 3D-дизайни у Blender та друкувати їх на 3D-принтері
- **Доступ до інформації в реальному часі**: Підключення до зовнішніх джерел даних для отримання актуальної інформації
- **Складні багатоетапні операції**: Виконання складних робочих процесів, що поєднують кілька інструментів та систем

### Чому MCP важливий?

MCP забезпечує вигоди для всієї екосистеми:

**Для розробників**: MCP зменшує час розробки та складність при створенні або інтеграції AI-застосунку чи агента.

**Для AI-застосунків**: MCP надає доступ до екосистеми джерел даних, інструментів та додатків, що розширюють можливості та покращують досвід кінцевого користувача.

**Для кінцевих користувачів**: MCP призводить до створення більш спроможних AI-застосунків або агентів, які можуть отримувати доступ до ваших даних та виконувати дії від вашого імені, коли це необхідно.

## Невеликі мовні моделі (SLM) у MCP

Невеликі мовні моделі є ефективним підходом до розгортання AI, пропонуючи кілька переваг:

### Переваги SLM
- **Ефективність ресурсів**: Нижчі обчислювальні вимоги
- **Швидші відповіді**: Знижена затримка для застосунків у реальному часі  
- **Економічність**: Мінімальні потреби у інфраструктурі
- **Конфіденційність**: Можуть запускатися локально без передачі даних
- **Налаштування**: Легше налаштовувати під конкретні домени

### Чому SLM добре працюють з MCP

Поєднання SLM з MCP створює потужний дует, де можливості моделі з логічного мислення підсилюються зовнішніми інструментами, компенсуючи меншу кількість параметрів через розширену функціональність.

## Огляд Python MCP SDK

Python MCP SDK забезпечує основу для створення застосунків із підтримкою MCP. SDK включає:

- **Клієнтські бібліотеки**: Для підключення до MCP серверів
- **Серверний фреймворк**: Для створення власних MCP серверів
- **Обробники протоколу**: Для керування комунікацією
- **Інтеграція інструментів**: Для виконання зовнішніх функцій

## Практична реалізація: Phi-4 MCP клієнт

Розглянемо реальну реалізацію з використанням міні-моделі Phi-4 від Microsoft, інтегрованої з можливостями MCP.

### Огляд архітектури MCP

MCP базується на **архітектурі клієнт-сервер**, де хост MCP (AI-застосунок, такий як Claude Code або Claude Desktop) встановлює з’єднання з одним або кількома MCP серверами. Хост MCP робить це, створюючи одного MCP клієнта для кожного MCP сервера.

#### Ключові учасники

- **MCP Хост**: AI-застосунок, який координує та керує одним або кількома MCP клієнтами
- **MCP Клієнт**: Компонент, який підтримує з’єднання з MCP сервером і отримує контекст від MCP сервера для використання MCP хостом
- **MCP Сервер**: Програма, що надає контекст MCP клієнтам

#### Дворівнева архітектура

MCP складається з двох окремих рівнів:

**Рівень даних**: Визначає протокол JSON-RPC для комунікації клієнт-сервер, включаючи:
- Керування життєвим циклом (ініціалізація з'єднання, узгодження можливостей)
- Основні примітиви (інструменти, ресурси, підказки)
- Клієнтські функції (семплювання, вилучення, логування)
- Утилітні функції (сповіщення, відслідковування прогресу)

**Рівень транспорту**: Визначає механізми та канали комунікації:
- **STDIO транспорт**: Використовує стандартні потоки введення/виведення для локальних процесів (оптимальна продуктивність, відсутність мережевого навантаження)
- **HTTP транспорт із потоковомісткою**: Використовує HTTP POST з опціональними Server-Sent Events для віддалених серверів (підтримка стандартної HTTP-аутентифікації)

```

│           MCP Host                  │
│     (AI Application)                │

└─────────────────────────────────────┘
```

### Основні примітиви MCP

MCP визначає примітиви, які уточнюють типи контекстної інформації, що може бути надана AI-застосункам, та діапазон дій, які можна виконувати.

#### Серверні примітиви

MCP визначає три основні примітиви, які сервери можуть надавати:

**Інструменти**: Виконувані функції, які AI-застосунки можуть викликати для виконання дій
- Приклади: операції з файлами, виклики API, запити до баз даних
- Методи: `tools/list`, `tools/call`
- Підтримка динамічного виявлення та виконання

**Ресурси**: Джерела даних, які надають контекстну інформацію AI-застосункам
- Приклади: вміст файлів, записи баз даних, відповіді API
- Методи: `resources/list`, `resources/read`
- Забезпечують доступ до структурованих даних

**Підказки**: Перероблювані шаблони, які допомагають структурувати взаємодію з мовними моделями
- Приклади: системні підказки, приклади з кількома варіантами
- Методи: `prompts/list`, `prompts/get`
- Стандартизують шаблони взаємодії з AI

#### Клієнтські примітиви

MCP також визначає примітиви, які клієнти можуть надавати для більш глибокої взаємодії:

**Семплювання**: Дозволяє серверам запитувати завершення мовної моделі з AI-застосунку клієнта
- Метод: `sampling/complete`
- Дозволяє розробляти сервери незалежно від моделі
- Надає доступ до мовної моделі хоста

**Вилучення**: Дозволяє серверам запитувати додаткову інформацію у користувачів
- Метод: `elicitation/request`
- Підтримує взаємодію з користувачем та підтвердження
- Підтримує динамічне збирання інформації

**Логування**: Дозволяє серверам надсилати журналювання повідомлень клієнтам
- Використовується для налагодження та моніторингу
- Забезпечує прозорість операцій сервера

### Життєвий цикл протоколу MCP

#### Ініціалізація та узгодження можливостей

MCP — це протокол із збереженням стану, що вимагає керування життєвим циклом. Процес ініціалізації виконує кілька ключових завдань:

1. **Узгодження версії протоколу**: Гарантує, що клієнт і сервер використовують сумісні версії протоколу (наприклад, "2025-06-18")
2. **Виявлення можливостей**: Кожна сторона декларує підтримувані функції та примітиви
3. **Обмін ідентифікацією**: Надає інформацію про ідентифікацію та версію

```python
# Приклад запиту ініціалізації
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # Клієнт підтримує взаємодію з користувачем
      "sampling": {}      # Клієнт може надавати завершення LLM
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### Виявлення та виконання інструментів

Після ініціалізації клієнти можуть виявляти та запускати інструменти:

```python
# Відкрийте доступні інструменти
tools_response = await session.list_tools()

# Виконайте інструмент
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### Сповіщення в реальному часі

MCP підтримує сповіщення в реальному часі для динамічних оновлень:

```python
# Сервер надсилає сповіщення при зміні інструментів
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# Клієнт відповідає оновленням списку інструментів
await session.list_tools()  # Отримати оновлені інструменти
```

### Крок 4: Програмне використання

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # Налаштувати параметри сервера MCP
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # Створити клієнта MCP та інструменти обробки
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # Згенерувати відповідь із можливостями інструментів
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# Виконати автоматизацію
result = asyncio.run(automated_interaction())
print(result)
```

## Розвинені функції

### Підтримка кількох бекендів

Реалізація підтримує обидва бекенди — Ollama та vLLM, що дозволяє обирати залежно від ваших вимог:

- **Ollama**: Краще для локальної розробки та тестування
- **vLLM**: Оптимізований для виробництва та сценаріїв з великою пропускною здатністю

### Гнучкі протоколи з’єднання

Підтримуються два режими підключення:

**STDIO режим**: Пряме спілкування процесів
- Нижча затримка
- Підходить для локальних інструментів
- Просте налаштування

**SSE режим**: HTTP-стрімінг
- Мережеві можливості
- Краще для розподілених систем
- Оновлення в реальному часі

### Можливості інтеграції інструментів

Система може інтегруватися з різними інструментами:
- Веб-автоматизація (Playwright)
- Операції з файлами
- Взаємодія з API
- Системні команди
- Користувацькі функції

## Обробка помилок та найкращі практики

### Всеосяжне управління помилками

Реалізація включає надійну обробку помилок для:

**Помилки виконання інструментів:**
- Відсутні інструменти

**Помилки обробки відповіді:**

2. **Обробка помилок**: Реалізуйте всеохоплюючі блоки try-catch
3. **Логування**: Вмикайте відповідні рівні логування
4. **Безпека**: Перевіряйте вхідні дані та очищуйте вихідні

## Екосистема MCP і розробка

### Обсяг проекту MCP

Екосистема Model Context Protocol включає кілька ключових компонентів:

- **[Специфікація MCP](https://modelcontextprotocol.io/specification/latest)**: Офіційна специфікація з описом вимог до реалізації клієнтів і серверів
- **[SDK MCP](https://modelcontextprotocol.io/docs/sdk)**: SDK для різних мов програмування, що впроваджують MCP
- **Інструменти розробки MCP**: Інструменти для створення MCP серверів і клієнтів, включно з [MCP Inspector](https://github.com/modelcontextprotocol/inspector)
- **[Репозиторії з прикладами серверів MCP](https://github.com/modelcontextprotocol/servers)**: Референсні реалізації MCP серверів

### Початок розробки з MCP

Щоб почати створювати застосунки з MCP:

**Створюйте сервери**: [Створюйте MCP сервери](https://modelcontextprotocol.io/docs/develop/build-server) для надання ваших даних та інструментів

**Створюйте клієнти**: [Розробляйте застосунки](https://modelcontextprotocol.io/docs/develop/build-client), що підключаються до MCP серверів

**Вивчайте концепції**: [Розумійте базові концепції](https://modelcontextprotocol.io/docs/learn/architecture) та архітектуру MCP

## Висновок

Невеликі мовні моделі, інтегровані з MCP, представляють парадигмальний зсув у розробці AI-застосунків. Поєднуючи ефективність малих моделей з силою зовнішніх інструментів, розробники можуть створювати інтелектуальні системи, які ефективні з точки зору ресурсів і водночас дуже функціональні.

Протокол контексту моделі забезпечує стандартизований спосіб підключення AI-застосунків до зовнішніх систем, так само як USB-C забезпечує універсальний стандарт підключення для електронних пристроїв. Ця стандартизація дозволяє:

- **Безшовну інтеграцію**: Підключати AI-моделі до різноманітних джерел даних та інструментів
- **Зростання екосистеми**: Створюйте один раз, використовуйте в кількох AI-застосунках
- **Розширені можливості**: Посилюйте SLM зовнішньою функціональністю
- **Оновлення в реальному часі**: Підтримка динамічних, чуйних AI-застосунків

Основні висновки:
- MCP — це відкритий стандарт, що поєднує AI-застосунки та зовнішні системи
- Протокол підтримує інструменти, ресурси та підказки як основні примітиви
- Сповіщення в реальному часі забезпечують динамічні, адаптивні застосунки
- Правильне керування життєвим циклом і обробка помилок є необхідними для промислового використання
- Екосистема надає комплексні SDK та інструменти для розробки
