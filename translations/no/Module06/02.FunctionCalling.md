## Hva er funksjonskalling?

Funksjonskalling er en kraftfull egenskap som lar Små Språkmodeller (SLMs) samhandle med eksterne verktøy, API-er og tjenester. I stedet for å være begrenset til treningsdataene sine, kan SLM-er nå:

- **Koble til eksterne API-er** (værtjenester, databaser, søkemotorer)
- **Utføre spesifikke funksjoner** basert på brukerforespørsler
- **Hente sanntidsinformasjon** fra ulike kilder
- **Utføre beregningsoppgaver** gjennom spesialiserte verktøy
- **Kjede sammen flere operasjoner** for komplekse arbeidsflyter

Denne evnen forvandler SLM-er fra statiske tekstgeneratorer til dynamiske AI-agenter som kan utføre oppgaver i den virkelige verden.

## Hvordan funksjonskalling fungerer

Funksjonskallingsprosessen følger en systematisk arbeidsflyt:

### 1. Verktøyintegrasjon
- **Eksterne verktøy**: SLM-er kan koble seg til vær-API-er, databaser, webtjenester og andre eksterne systemer
- **Funksjonsdefinisjoner**: Hvert verktøy defineres med spesifikke parametere, input/output-formater og beskrivelser
- **API-kompatibilitet**: Verktøy integreres via standardiserte grensesnitt (REST API-er, SDK-er osv.)

### 2. Funksjonsdefinisjon
Funksjoner defineres med tre nøkkelkomponenter:
```json
{
  "name": "function_name",
  "description": "Clear description of what the function does",
  "parameters": {
    "parameter_name": {
      "description": "What this parameter represents",
      "type": "data_type",
      "default": "default_value"
    }
  }
}
```

### 3. Intensjonsdeteksjon
- **Naturlig språkbehandling**: SLM analyserer brukerens input for å forstå intensjonen
- **Funksjonssamsvar**: Avgjør hvilke funksjon(er) som trengs for å oppfylle forespørselen
- **Parameterekstraksjon**: Identifiserer og henter ut nødvendige parametere fra brukerens melding

### 4. JSON-utgangsgenerering
SLM genererer strukturert JSON som inneholder:
- Funksjonsnavn å kalle
- Nødvendige parametere med passende verdier
- Utførelseskontekst og metadata

### 5. Ekstern utførelse
- **Parameterbekreftelse**: Sikrer at alle nødvendige parametere er til stede og riktig formatert
- **Funksjonsutførelse**: Applikasjonen utfører den spesifiserte funksjonen med angitte parametere
- **Feilhåndtering**: Håndterer feil, tidsavbrudd og ugyldige svar

### 6. Responsintegrasjon
- **Resultatbehandling**: Funksjonsutdata returneres til SLM
- **Kontekstintegrasjon**: SLM inkorporerer resultatene i sitt svar
- **Brukerkommunikasjon**: Presenterer informasjonen i et naturlig, samtaleformat

## Bruksscenarier

### Datahenting
Oversett naturlige språkspørringer til strukturerte API-kall:
- **"Vis mine siste bestillinger"** → Database-spørring med bruker-ID og datofiltre
- **"Hvordan er været i Tokyo?"** → Vær-API-kall med lokasjonsparameter
- **"Finn e-poster fra John forrige uke"** → E-posttjenestespørring med avsender- og datofiltre

### Operasjonsutførelse
Omform brukerforespørsler til spesifikke funksjonskall:
- **"Planlegg et møte i morgen kl. 14"** → Kalender-API-integrasjon
- **"Send en melding til teamet"** → Kommunikasjonsplattform-API
- **"Lag en sikkerhetskopi av filene mine"** → Filoperasjonssystem

### Beregningsoppgaver
Håndter komplekse matematiske eller logiske operasjoner:
- **"Beregn rentes rente på 10 000 $ med 5 % i 10 år"** → Finansiell beregningsfunksjon
- **"Analyser dette datasettet for trender"** → Statistiske analyserverktøy
- **"Optimaliser denne ruten for levering"** → Ruteoptimaliseringsalgoritmer

### Arbeidsflyter for databehandling
Kjede sammen flere funksjonskall for komplekse operasjoner:
1. **Hent data** fra flere kilder
2. **Tolke og validere** informasjonen
3. **Transformer** data til nødvendig format
4. **Lagre resultater** i passende systemer
5. **Generer rapporter** eller visualiseringer

### UI/UX-integrasjon
Muliggjør dynamiske grensesnittoppdateringer:
- **"Vis salgsdata på dashbordet"** → Diagramgenerering og visning
- **"Oppdater kartet med nye steder"** → Geospatiale data-integrasjoner
- **"Oppdater lagerdisplayet"** → Sanntidssynkronisering av data

### Egendefinert funksjonsimplementering

Du kan også definere egendefinerte funksjoner for Qwen3:

```python
import json
from qwen_agent.tools.base import BaseTool

class WeatherTool(BaseTool):
    description = 'Get weather information for a specific location'
    parameters = [
        {
            'name': 'location',
            'type': 'string', 
            'description': 'City or location name',
            'required': True
        },
        {
            'name': 'units',
            'type': 'string',
            'description': 'Temperature units (celsius or fahrenheit)',
            'required': False,
            'default': 'celsius'
        }
    ]
    
    def call(self, params: str, **kwargs) -> str:
        """Execute the weather lookup"""
        params_dict = json.loads(params)
        location = params_dict.get('location')
        units = params_dict.get('units', 'celsius')
        
        # Simuler vær-API-anrop
        weather_data = {
            'location': location,
            'temperature': '22°C' if units == 'celsius' else '72°F',
            'condition': 'Partly cloudy',
            'humidity': '65%'
        }
        
        return json.dumps(weather_data)

# Bruk det tilpassede verktøyet
tools = [WeatherTool()]
bot = Assistant(llm=llm_cfg, function_list=tools)

messages = [{'role': 'user', 'content': 'What\'s the weather in Tokyo?'}]
response = bot.run(messages=messages)
print(list(response)[-1])
```

### Vanlige problemer og løsninger

#### Problem 1: Funksjonen blir ikke kalt
**Symptomer**: Modellen svarer med tekst i stedet for å kalle funksjonen

**Løsninger**:
1. **Sjekk funksjonsbeskrivelsen**: Sørg for at den klart matcher brukerens intensjon
2. **Verifiser parameterdefinisjoner**: Sørg for at alle nødvendige parametere er riktig definert
3. **Gjennomgå systemprompt**: Inkluder klare instruksjoner om når funksjoner skal brukes
4. **Test med eksplisitte forespørsler**: Prøv "Vennligst bruk værfunksjonen for å hente data for London"

#### Problem 2: Feil parametere
**Symptomer**: Funksjon kalles med feil eller manglende parametere

**Løsninger**:
1. **Legg til parameter-eksempler**: Inkluder eksempler på verdier i parameterbeskrivelser
2. **Bruk enum-begrensninger**: Begrens parametere til spesifikke alternativer når mulig
3. **Implementer fallback-verdier**: Gi fornuftige standardverdier for valgfrie parametere

```python
{
    "name": "book_restaurant",
    "parameters": {
        "cuisine": {
            "type": "string",
            "enum": ["italian", "chinese", "mexican", "american", "french"],
            "description": "Type of cuisine (example: 'italian' for Italian food)"
        },
        "party_size": {
            "type": "integer",
            "minimum": 1,
            "maximum": 20,
            "description": "Number of people (example: 4 for a family of four)"
        }
    }
}
```

#### Problem 3: Feil ved parallell funksjonskalling
**Symptomer**: Bare én funksjon kjøres når flere skulle kjøres parallelt

**Løsninger**:
1. **Sjekk modellstøtte**: Sørg for at din modell støtter parallell funksjonskalling
2. **Oppdater systemprompt**: Inkluder “noen verktøy” eller “flere verktøy” i systemmeldingen
3. **Bruk passende modellversjoner**: Phi-4-mini:3.8b-fp16 anbefales for Ollama

#### Problem 4: Malproblemer med Ollama
**Symptomer**: Funksjonskalling fungerer ikke med standard Ollama-oppsett

**Løsninger**:
1. **Bruk egendefinert ModelFile**: Bruk den korrigerte malen gitt i denne veiledningen
2. **Oppdater Ollama**: Sørg for at du bruker versjon 0.5.13 eller høyere
3. **Sjekk modellkvantisering**: Høyere kvantiseringsnivåer (Q8_0, fp16) fungerer bedre enn sterkt kvantiserte versjoner

### Ytelsesoptimalisering

#### 1. Effektiv funksjonsdesign
- **Hold funksjonene fokuserte**: Hver funksjon bør ha ett klart formål
- **Minimer eksterne avhengigheter**: Reduser API-kall og nettverksforespørsler der det er mulig
- **Cache resultater**: Lagre ofte forespurte data for å forbedre svartider

#### 2. Batching og asynkrone operasjoner
```python
import asyncio
import aiohttp

async def batch_function_calls(function_calls):
    """Execute multiple function calls concurrently"""
    async with aiohttp.ClientSession() as session:
        tasks = []
        for call in function_calls:
            if call["name"] == "fetch_url":
                task = fetch_url_async(session, call["parameters"]["url"])
                tasks.append(task)
        
        results = await asyncio.gather(*tasks)
        return results

async def fetch_url_async(session, url):
    async with session.get(url) as response:
        return await response.text()
```

#### 3. Ressursstyring
- **Connection pooling**: Gjenbruk database- og API-tilkoblinger
- **Ratebegrensning**: Implementer riktig ratebegrensning for eksterne API-er
- **Timeout-håndtering**: Sett fornuftige tidsavbrudd for alle eksterne kall

            'call_count': 0,

        }
    
    async def execute_function(self, function_name: str, parameters: Dict) -> FunctionResult:
        """Execute a function with comprehensive error handling and logging"""
        start_time = datetime.now()
        
        try:
            # Valider at funksjonen finnes
            if function_name not in self.functions:
                return FunctionResult(
                    success=False,
                    error=f"Function '{function_name}' not found",
                    timestamp=start_time
                )
            
            # Sjekk ratebegrensninger
            if not self._check_rate_limit(function_name):
                return FunctionResult(
                    success=False,
                    error=f"Rate limit exceeded for function '{function_name}'",
                    timestamp=start_time
                )
            
            # Valider parametere
            validation_result = self._validate_parameters(function_name, parameters)
            if not validation_result.success:
                return validation_result
            
            # Utfør funksjon
            func_info = self.functions[function_name]
            handler = func_info['handler']
            
            if asyncio.iscoroutinefunction(handler):
                result_data = await handler(**parameters)
            else:
                result_data = handler(**parameters)
            
            execution_time = (datetime.now() - start_time).total_seconds()
            
            result = FunctionResult(
                success=True,
                data=result_data,
                execution_time=execution_time,
                timestamp=start_time
            )
            
            # Logg vellykket utførelse
            self._log_function_call(function_name, parameters, result)
            
            return result
            
        except Exception as e:
            execution_time = (datetime.now() - start_time).total_seconds()
            result = FunctionResult(
                success=False,
                error=str(e),
                execution_time=execution_time,
                timestamp=start_time
            )
            
            # Logg mislykket utførelse
            self._log_function_call(function_name, parameters, result)
            
            return result
    
    def _check_rate_limit(self, function_name: str) -> bool:
        """Check if function call is within rate limits"""
        func_info = self.functions[function_name]
        now = datetime.now()
        
        # Tilbakestill teller hvis en minutt har gått
        if (now - func_info['last_reset']).seconds >= 60:
            func_info['call_count'] = 0
            func_info['last_reset'] = now
        
        # Sjekk om under grensen
        if func_info['call_count'] >= func_info['rate_limit']:
            return False
        
        func_info['call_count'] += 1
        return True
    
    def _validate_parameters(self, function_name: str, parameters: Dict) -> FunctionResult:
        """Validate function parameters"""
        func_params = self.functions[function_name]['parameters']
        
        # Sjekk nødvendige parametere
        for param_name, param_info in func_params.items():
            if param_info.get('required', False) and param_name not in parameters:
                return FunctionResult(
                    success=False,
                    error=f"Missing required parameter: {param_name}"
                )
        
        # Valider parametertyper og begrensninger
        for param_name, value in parameters.items():
            if param_name in func_params:
                param_info = func_params[param_name]
                
                # Typevalidering
                expected_type = param_info.get('type')
                if expected_type == 'string' and not isinstance(value, str):

                        error=f"Parameter '{param_name}' must be a string"

                        success=False,
                        error=f"Parameter '{param_name}' must be a number"
                    )
                elif expected_type == 'boolean' and not isinstance(value, bool):

                        success=False,
                        error=f"Parameter '{param_name}' must be a boolean"
                    )

                    return FunctionResult(
                        success=False,
                        error=f"Parameter '{param_name}' must be one of: {param_info['enum']}"
                    )

## Konklusjon

Funksjonskalling i Små Språkmodeller representerer et paradigmeskifte fra statiske AI-assistenter til dynamiske, kapable agenter som kan samhandle med den virkelige verden. Denne veiledningen har dekket:

### Viktige punkter

1. **Grunnleggende forståelse**: Funksjonskalling gjør at SLM-er kan utvide seg utover treningsdata ved å koble til eksterne verktøy og tjenester.

2. **Implementeringsfleksibilitet**: Flere tilnærminger finnes, fra lavnivåimplementeringer med egendefinerte maler til høynivårammeverk som Qwen-Agent og Foundry Local.

3. **Produksjonshensyn**: Bedriftsdistribusjoner krever oppmerksomhet på feilhåndtering, ratebegrensning, sikkerhet og revisjonslogging.

4. **Ytelsesoptimalisering**: Riktig funksjonsdesign, effektiv utførelse og smart caching kan betydelig forbedre svartider.

### Fremtidige retninger

Etter hvert som SLM-teknologien utvikler seg videre, kan vi forvente:

- **Forbedret nøyaktighet for funksjonskalling**: Bedre intensjonsgjenkjenning og parameterekstraksjon
- **Forbedret parallell behandling**: Mer sofistikert orkestrering av flere funksjoner
- **Bedre integrasjonsstandarder**: Standardiserte protokoller for verktøyintegrasjon
- **Avanserte sikkerhetsfunksjoner**: Forbedrede autentiserings- og autorisasjonsmekanismer
- **Utvidet økosystem**: Voksende bibliotek av ferdige funksjoner og integrasjoner

### Komme i gang

For å begynne å implementere funksjonskalling i dine prosjekter:

1. **Start enkelt**: Begynn med grunnleggende enkeltfunksjonsscenarier
2. **Velg rammeverk**: Velg mellom direkte implementering (Ollama/Phi-4) eller rammeverk-hjelpet (Qwen-Agent)
3. **Design funksjoner nøye**: Fokuser på klare, godt dokumenterte funksjonsdefinisjoner
4. **Implementer feilhåndtering**: Bygg robust feilhåndtering fra starten av
5. **Skaler gradvis**: Gå fra enkle til komplekse scenarier etter hvert som du får erfaring

Funksjonskalling forvandler SLM-er fra imponerende tekstgeneratorer til praktiske AI-agenter som kan løse virkelige problemer. Ved å følge mønstrene og praksisene som er skissert i denne veiledningen, kan du bygge kraftfulle, pålitelige AI-systemer som strekker seg langt utover tradisjonelle chattegrensesnitt.
