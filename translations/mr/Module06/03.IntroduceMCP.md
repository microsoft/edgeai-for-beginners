# विभाग 03 - मॉडेल संदर्भ प्रोटोकॉल (MCP) एकत्रीकरण

## MCP (मॉडेल संदर्भ प्रोटोकॉल) परिचय

मॉडेल संदर्भ प्रोटोकॉल (MCP) हा AI अनुप्रयोगांना बाह्य प्रणालींशी जोडण्यासाठी एक मुक्त-स्रोत मानक आहे. MCP वापरून, क्लॉड किंवा ChatGPT सारख्या AI अनुप्रयोगांना डेटा स्त्रोत (उदा., स्थानिक फाइल्स, डेटाबेस), साधने (उदा., सर्च इंजिन्स, कॅल्क्युलेटर) आणि कार्यप्रवाह (उदा., विशेषज्ञ प्रम्प्ट्स) शी जोडता येते - ज्यामुळे ते आवश्यक माहिती प्राप्त करून कार्ये पार पाडू शकतात.

MCP ला **AI अनुप्रयोगांसाठी USB-C पोर्ट** म्हणून विचार करा. जसे USB-C इलेक्ट्रॉनिक उपकरणांना जोडण्यासाठी एक प्रमाणित मार्ग प्रदान करते, तसेच MCP AI अनुप्रयोगांना बाह्य प्रणालींशी जोडण्यासाठी एक प्रमाणित मार्ग प्रदान करते.

### MCP काय सक्षम करू शकतो?

MCP AI अनुप्रयोगांसाठी शक्तिशाली क्षमता मुक्त करतो:

- **वैयक्तिकृत AI सहाय्यक**: एजंट्स तुमच्या Google Calendar आणि Notion शी जोडू शकतात, ज्यामुळे ते अधिक वैयक्तिकृत AI सहाय्यक बनतात
- **प्रगत कोड निर्मिती**: Claude Code Figma डिझाइन वापरून संपूर्ण वेब अॅप तयार करू शकतो
- **एंटरप्राइज डेटा एकत्रीकरण**: एंटरप्राइज चॅटबॉट्स अनेक डेटाबेसशी जोडून वापरकर्त्यांना चॅटद्वारे डेटा विश्लेषण करण्यास सक्षम करतात
- **सर्जनशील कार्यप्रवाह**: AI मॉडेल्स Blender मध्ये 3D डिझाईन्स तयार करू शकतात आणि 3D प्रिंटर वापरून मुद्रित करू शकतात
- **रिअल-टाइम माहिती प्रवेश**: अद्ययावत माहितींसाठी बाह्य डेटा स्त्रोतांशी कनेक्ट करा
- **जटिल बहु-स्तरीय ऑपरेशन्स**: अनेक साधने आणि प्रणाली एकत्र करून प्रगत कार्यप्रवाह पार पाडा

### MCP का महत्त्वाचा आहे?

MCP संपूर्ण परिसंस्थेमध्ये फायदे देते:

**विकसकांसाठी**: MCP AI अनुप्रयोग किंवा एजंट तयार करताना किंवा एकत्रित करताना विकास वेळ आणि गुंतागुंत कमी करतो.

**AI अनुप्रयोगांसाठी**: MCP डेटा स्त्रोत, साधने आणि अॅप्सच्या परिसंस्थेचा प्रवेश देते ज्यामुळे क्षमता वाढतात आणि अंतिम वापरकर्ता अनुभव सुधारतो.

**अंतिम वापरकर्त्यांसाठी**: MCP अधिक सक्षम AI अनुप्रयोग किंवा एजंट तयार करतो जे तुमचा डेटा प्रवेश करू शकतात आणि आवश्यकतेनुसार तुमच्या वतीने क्रियेतील.

## MCP मधील लहान भाषा मॉडेल्स (SLMs)

लहान भाषा मॉडेल्स हे AI तैनातीसाठी एक कार्यक्षम दृष्टिकोन दर्शवतात, जे अनेक फायदे देतात:

### SLM चे फायदे
- **संसाधन कार्यक्षमता**: कमी संगणकीय आवश्यकता
- **जलद प्रतिसाद वेळ**: रिअल-टाइम अनुप्रयोगांसाठी कमी विलंब
- **किंमत कार्यक्षमता**: कमी पायाभूत सुविधा गरजा
- **गोपनीयता**: डेटा ट्रान्समिशन न करता स्थानिकरित्या चालवता येतात
- **सानुकूलन**: विशिष्ट क्षेत्रांसाठी सुलभ फाईन-ट्यूनिंग

### SLM का MCP सोबत चांगले कार्य करतात

SLMs MCP सोबत जोडले जातात तेव्हा मॉडेलच्या तर्कशक्तीला बाह्य साधनांनी वाढ दिली जाते, ज्यामुळे त्यांच्या कमी पॅरामिटर मोजणीची भरपाई होते आणि कार्यक्षमता वाढते.

## Python MCP SDK आढावा

Python MCP SDK हे MCP-सक्षम अनुप्रयोग तयार करण्यासाठी पाया प्रदान करते. SDK मध्ये समाविष्ट आहेत:

- **क्लायंट लायब्ररी**: MCP सर्व्हर्सशी कनेक्ट होण्यासाठी
- **सर्व्हर फ्रेमवर्क**: सानुकूल MCP सर्व्हर्स तयार करण्यासाठी
- **प्रोटोकॉल हँडलर्स**: संवाद व्यवस्थापनासाठी
- **साधन इंटिग्रेशन**: बाह्य फंक्शन्स कार्यान्वित करण्यासाठी

चला Microsoft च्या Phi-4 मिनी मॉडेलसह MCP क्षमतांशी जोडलेल्या वास्तविक अंमलबजावणीचा अभ्यास करूया.

### MCP आर्किटेक्चर आढावा

MCP हे **क्लायंट-सर्व्हर आर्किटेक्चर** आहे जिथे एक MCP होस्ट (Claude Code किंवा Claude Desktop सारखा AI अनुप्रयोग) एक किंवा अधिक MCP सर्व्हर्सशी कनेक्शन स्थापन करतो. MCP होस्ट प्रत्येक MCP सर्व्हरसाठी एक MCP क्लायंट तयार करून हे साध्य करतो.

#### मुख्य सहभागी

- **MCP होस्ट**: एखादा AI अनुप्रयोग जो एक किंवा अधिक MCP क्लायंट्सचे समन्वय आणि व्यवस्थापन करतो
- **MCP क्लायंट**: असा घटक जो MCP सर्व्हरशी कनेक्शन राखतो आणि MCP होस्टसाठी संदर्भ प्राप्त करतो
- **MCP सर्व्हर**: असा प्रोग्राम जो MCP क्लायंट्सना संदर्भ पुरवतो

#### दोन-स्तरीय आर्किटेक्चर

MCP दोन वेगवेगळ्या स्तरांवर बनलेला आहे:

**डेटा स्तर**: क्लायंट-सर्व्हर संवादासाठी JSON-RPC आधारित प्रोटोकॉल परिभाषित करतो, ज्यात समाविष्ट आहे:
- जीवनचक्र व्यवस्थापन (कनेक्शन प्रारंभ, क्षमता वाटाघाटी)
- मुख्य मूळ घटक (साधने, संसाधने, प्रम्प्ट्स)
- क्लायंट वैशिष्ट्ये (नमुना घेणे, उमज, नोंदणी)
- उपयुक्त वैशिष्ट्ये (सूचना, प्रगती ट्रॅकिंग)

**ट्रान्सपोर्ट स्तर**: संवादासाठी यंत्रणा आणि चॅनेल्स परिभाषित करतो:
- **STDIO ट्रान्सपोर्ट**: स्थानिक प्रक्रियांसाठी मानक इनपुट/आउटपुट प्रवाह वापरतो (सर्वोत्तम कार्यक्षमतेसाठी, कोणताही नेटवर्क ओव्हरहेड नाही)
- **स्ट्रीमबल HTTP ट्रान्सपोर्ट**: दूरस्थ सर्व्हर्ससाठी HTTP POST वापरतो, पर्यायी सर्व्हर-सेंट इव्हेंट्ससह (मानक HTTP प्रमाणीकरण समर्थित)

```
┌─────────────────────────────────────┐
│           MCP Host                  │
│     (AI Application)                │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Client 1                │
│  ┌─────────────────────────────────┐ │
│  │        Data Layer               │ │
│  │  ├── Lifecycle Management       │ │
│  │  ├── Primitives (Tools/Resources)│ │
│  │  └── Notifications              │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │      Transport Layer           │ │
│  │  ├── STDIO Transport           │ │
│  │  └── HTTP Transport            │ │
│  └─────────────────────────────────┘ │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Server 1                │
│    (Local/Remote Context Provider)  │
└─────────────────────────────────────┘
```

### MCP मुख्य मूळ घटक

MCP मूळ घटक परिभाषित करतो जे AI अनुप्रयोगांसोबत कोणत्या प्रकारची संदर्भ माहिती शेअर केली जाऊ शकते आणि कोणत्या क्रिया पार पाडल्या जाऊ शकतात.

#### सर्व्हर मूळ घटक

MCP तीन मुख्य मूळ घटक परिभाषित करतो जे सर्व्हर्स उघड करू शकतात:

**साधने**: executable functions ज्यांना AI अनुप्रयोग क्रिया पार पाडण्यासाठी कॉल करू शकतात
- उदाहरणे: फाइल ऑपरेशन्स, API कॉल्स, डेटाबेस क्वेरीज
- मेथड्स: `tools/list`, `tools/call`
- डायनॅमिक शोध व कार्यवाहीस समर्थन

**संसाधने**: डेटा स्त्रोत जे AI अनुप्रयोगांस संदर्भ माहिती पुरवतात
- उदाहरणे: फाइल सामग्री, डेटाबेस रेकॉर्डस्, API प्रतिसाद
- मेथड्स: `resources/list`, `resources/read`
- संरचित डेटाच्या प्रवेशास अनुमती

**प्रम्प्ट्स**: पुन्हा वापरता येणारे टेम्पलेट्स जे भाषा मॉडेल्सशी संवादरचना करण्यात मदत करतात
- उदाहरणे: सिस्टम प्रम्प्ट्स, फ्यू-शॉट उदाहरणे
- मेथड्स: `prompts/list`, `prompts/get`
- AI संवाद स्वरूपांचे प्रमाणितीकरण

#### क्लायंट मूळ घटक

MCP क्लायंट्स देखील मूळ घटक परिभाषित करतो जे भरघोस संवाद सक्षम करतात:

**नमुना घेणे**: सर्व्हर्सना क्लायंटच्या AI अनुप्रयोगाकडून भाषा मॉडेल पूर्णता मागवण्याची परवानगी देते
- मेथड: `sampling/complete`
- मॉडेल-स्वतंत्र सर्व्हर विकास सक्षम करतो
- होस्टच्या भाषा मॉडेलचा प्रवेश देते

**विकसित करणे**: सर्व्हर्सना वापरकर्त्यांकडून अतिरिक्त माहिती मागवण्याची परवानगी देते
- मेथड: `elicitation/request`
- वापरकर्ता संवाद व पुष्टीकरण सक्षम करतो
- डायनॅमिक माहिती गोळा करण्यासाठी समर्थन

**नोंदणी**: सर्व्हर्सना क्लायंट्सकडे लॉग संदेश पाठवण्याची अनुमती देते
- डिबगिंग आणि मॉनिटरिंगसाठी उपयोग
- सर्व्हर ऑपरेशन्सची दृश्यमानता पुरवते

### MCP प्रोटोकॉल जीवनचक्र

#### प्रारंभ व क्षमता वाटाघाटी

MCP हा एक स्थिरस्थिती प्रोटोकॉल आहे ज्याला जीवनचक्र व्यवस्थापन आवश्यक आहे. प्रारंभ प्रक्रियेचा उद्देश काही महत्त्वाचा आहे:

1. **प्रोटोकॉल आवृत्ती वाटाघाटी**: सुनिश्चित करते की क्लायंट आणि सर्व्हर सुसंगत प्रोटोकॉल आवृत्ती वापरतात (उदा., "2025-06-18")
2. **क्षमता शोध**: प्रत्येक पार्टी समर्थित वैशिष्ट्ये आणि मूळ घटक घोषित करते
3. **ओळख देवाणघेवाण**: ओळख व आवृत्ती माहिती प्रदान करते

```python
# उदाहरण प्रारंभिक विनंती
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # क्लायंट वापरकर्ता संवादाला समर्थन देतो
      "sampling": {}      # क्लायंट LLM पूर्णता प्रदान करू शकतो
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### साधन शोध व अंमलबजावणी

प्रारंभानंतर, क्लायंट साधने शोधू आणि कार्यान्वित करू शकतात:

```python
# उपलब्ध साधने शोधा
tools_response = await session.list_tools()

# साधन चालवा
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### रिअल-टाइम नोटिफिकेशन्स

MCP डायनॅमिक अद्यतनेसाठी रिअल-टाइम नोटिफिकेशन्स समर्थित करतो:

```python
# टूल्स बदलल्यावर सर्व्हर सूचना पाठवतो
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# क्लायंट टूल यादी रिफ्रेश करून प्रतिसाद देतो
await session.list_tools()  # अद्ययावत टूल्स मिळवा
```

### टप्पा 4: प्रोग्रामॅटिक वापर

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # MCP सर्व्हर पॅरामीटर्स कॉन्फिगर करा
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # MCP क्लायंट तयार करा आणि टूल्स प्रक्रिया करा
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # टूल क्षमतांसह प्रतिसाद तयार करा
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# स्वयंचलन कार्यान्वित करा
result = asyncio.run(automated_interaction())
print(result)
```

## प्रगत वैशिष्ट्ये

### मल्टि-बॅकएंड समर्थन

अंमलबजावणीत Ollama व vLLM बॅकएंड दोन्हीचा समर्थन आहे, ज्यामुळे तुम्ही तुमच्या गरजांनुसार निवड करू शकता:

- **Ollama**: स्थानिक विकास आणि चाचणीसाठी चांगले
- **vLLM**: उत्पादन व उच्च-प्रवाहासाठी अनुकूलित

### लवचिक कनेक्शन प्रोटोकॉल्स

दोन कनेक्शन मोड्स समर्थित आहेत:

**STDIO मोड**: थेट प्रक्रियांचे संवाद
- कमी विलंब
- स्थानिक साधनांसाठी उपयुक्त
- सोपे सेटअप

**SSE मोड**: HTTP आधारित स्ट्रीमिंग
- नेटवर्क समर्थित
- वितरित प्रणालींसाठी चांगले
- रिअल-टाइम अपडेट्स

### साधन एकत्रीकरण क्षमता

सिस्टिम विविध साधनांशी एकत्र होऊ शकते:
- वेब ऑटोमेशन (Playwright)
- फाइल ऑपरेशन्स
- API संवाद
- सिस्टम आदेश
- सानुकूल फंक्शन्स

## त्रुटी हाताळणी व सर्वोत्तम प्रथा

### सर्वसमावेशक त्रुटी व्यवस्थापन

अंमलबजावणीत मजबूत त्रुटी हाताळणी अंतर्भूत आहे:

**कनेक्शन त्रुटी:**
- MCP सर्व्हर अयशस्वी
- नेटवर्क टाइमआउट्स
- कनेक्टिव्हिटी समस्या

**साधन कार्यान्वयन त्रुटी:**
- साधने गायब
- पॅरामिटर व्हॅलिडेशन
- कार्यान्वयन अयशस्वी

**प्रतिक्रिया प्रक्रिया त्रुटी:**
- JSON पार्सिंग समस्या
- स्वरूप विसंगती
- LLM प्रतिसाद विचित्रता

### सर्वोत्तम प्रथा

1. **संसाधन व्यवस्थापन**: async संदर्भ व्यवस्थापक वापरा
2. **त्रुटी हाताळणी**: व्यापक try-catch ब्लॉक्स लागू करा
3. **नोंदणी**: योग्य लॉगिंग पातळ्या सक्षम करा
4. **सुरक्षा**: इनपुट्सचे प्रमाणीकरण करा आणि आउटपुट्स स्वच्छ करा
5. **कार्यक्षमता**: कनेक्शन पूलिंग आणि कॅशिंग वापरा

- **[MCP SDKs](https://modelcontextprotocol.io/docs/sdk)**: विविध प्रोग्रामिंग भाषांसाठी MCP अंमलबजावण करणारे SDKs
- **MCP विकास साधने**: MCP सर्व्हर्स आणि क्लायंट्स विकसित करण्यासाठी साधने, ज्यात [MCP इंस्पेक्टर](https://github.com/modelcontextprotocol/inspector) समाविष्ट आहे
- **[MCP संदर्भ सर्व्हर अंमलबजावणी](https://github.com/modelcontextprotocol/servers)**: MCP सर्व्हर्सच्या संदर्भ अंमलबजावणी

**सर्व्हर्स तयार करा**: [तुमचे डेटा व साधने उघडण्यासाठी MCP सर्व्हर्स तयार करा](https://modelcontextprotocol.io/docs/develop/build-server)

**क्लायंट तयार करा**: [MCP सर्व्हर्सशी कनेक्ट होणारे अनुप्रयोग विकसित करा](https://modelcontextprotocol.io/docs/develop/build-client)

**तत्त्वे शिका**: [MCP चे मुख्य संकल्पना आणि आर्किटेक्चर समजून घ्या](https://modelcontextprotocol.io/docs/learn/architecture)

## निष्कर्ष

MCP सह एकत्रित SLMs AI अनुप्रयोग विकासात एक मोठा बदल दर्शवतात. लहान मॉडेल्सच्या कार्यक्षमतेला बाह्य साधनांच्या सामर्थ्याने जोडून, विकसक कार्यक्षम आणि अत्यंत सक्षम बुद्धिमान प्रणाली तयार करू शकतात.

मॉडेल संदर्भ प्रोटोकॉल AI अनुप्रयोगांना बाह्य प्रणालींशी जोडण्याचा प्रमाणित मार्ग देतो, जसे USB-C इलेक्ट्रॉनिक उपकरणांसाठी सार्वत्रिक कनेक्शन मानक प्रदान करते. या प्रमाणीकरणामुळे खालील गोष्टी शक्य होतात:

- **सगळी एकत्रीकरण**: विविध डेटा स्त्रोत व साधने AI मॉडेल्सशी जोडा
- **परिसंस्थेचा वाढ**: एकदा तयार करा, अनेक AI अनुप्रयोगांमध्ये वापरा
- **वाढीव क्षमता**: बाह्य कार्यक्षमतेसह SLMs मध्ये वाढ करा
- **रिअल-टाइम अपडेट्स**: गतिशील, प्रतिसादक्षम AI अनुप्रयोगांना समर्थन द्या

मुख्य मुद्दे:
- MCP हा AI अनुप्रयोग व बाह्य प्रणाली यांच्यात पूल असलेला मुक्त मानक आहे
- प्रोटोकॉल साधने, संसाधने व प्रम्प्ट्स मूळ घटक म्हणून समर्थन करतो
- रिअल-टाइम नोटिफिकेशन्स गतिशील, प्रतिसादक्षम अनुप्रयोगांना सक्षम करतात
- योग्य जीवनचक्र व्यवस्थापन व त्रुटी हाताळणी उत्पादन वापरासाठी आवश्यक आहे
- परिसंस्था विस्तृत SDKs व विकास साधने पुरवते
