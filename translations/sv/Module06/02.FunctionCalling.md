## Vad är Funktionsanrop?

Funktionsanrop är en kraftfull funktion som gör det möjligt för Små Språkmodeller (SLMs) att interagera med externa verktyg, API:er och tjänster. Istället för att vara begränsade till sin träningsdata kan SLM nu:

- **Ansluta till externa API:er** (vädertjänster, databaser, sökmotorer)
- **Utföra specifika funktioner** baserat på användarförfrågningar
- **Hämta realtidsinformation** från olika källor
- **Utföra beräkningsuppgifter** via specialiserade verktyg
- **Kedja ihop flera operationer** för komplexa arbetsflöden

Denna funktion förändrar SLM från statiska textgeneratorer till dynamiska AI-agenter som kan utföra verkliga uppgifter.

## Hur Funktionsanrop Fungerar

Funktionsanropsprocessen följer ett systematiskt arbetsflöde:

### 1. Verktygsintegration
- **Externa Verktyg**: SLM kan ansluta till väder-API:er, databaser, webbtjänster och andra externa system
- **Funktionsdefinitioner**: Varje verktyg definieras med specifika parametrar, in-/utdataformat och beskrivningar
- **API-kompatibilitet**: Verktyg integreras genom standardiserade gränssnitt (REST-API:er, SDK:er etc.)

### 2. Funktionsdefinition
Funktioner definieras med tre viktiga komponenter:
```json
{
  "name": "function_name",
  "description": "Clear description of what the function does",
  "parameters": {
    "parameter_name": {
      "description": "What this parameter represents",
      "type": "data_type",
      "default": "default_value"
    }
  }
}
```

### 3. Avsiktsigenkänning
- **Naturlig Språkbehandling**: SLM analyserar användarens input för att förstå avsikten
- **Funktionsmatchning**: Avgör vilken/vilka funktioner som behövs för att uppfylla förfrågan
- **Parameterekstraktion**: Identifierar och extraherar nödvändiga parametrar från användarens meddelande

### 4. JSON-Utdatagenerering
SLM genererar strukturerad JSON som innehåller:
- Funktionsnamnet som ska anropas
- Nödvändiga parametrar med korrekta värden
- Utförandekontext och metadata

### 5. Extern Utförande
- **Parameterkontroll**: Säkerställer att alla nödvändiga parametrar finns och är korrekt formaterade
- **Funktionsexekvering**: Applikationen utför den specificerade funktionen med givna parametrar
- **Felhanteirng**: Hanterar fel, timeout och ogiltiga svar

### 6. Responsintegration
- **Resultatbearbetning**: Funktionsresultatet returneras till SLM
- **Kontextintegration**: SLM införlivar resultaten i sitt svar
- **Användarkommunikation**: Presenterar informationen i ett naturligt, konversationellt format

## Användningsscenarier

### Datahämtning
Omvandla naturliga språkfrågor till strukturerade API-anrop:
- **"Visa mina senaste beställningar"** → Databasfråga med användar-ID och datumfilter
- **"Hur är vädret i Tokyo?"** → Väder-API-anrop med platsparameter
- **"Hitta e-post från John förra veckan"** → E-posttjänstfråga med avsändare och datumfilter

### Utförande av Operationer
Omvandla användarförfrågningar till specifika funktionsanrop:
- **"Schemalägg ett möte imorgon klockan 14:00"** → Kalender-API-integration
- **"Skicka ett meddelande till teamet"** → Kommunikationsplattform-API
- **"Skapa en säkerhetskopia av mina filer"** → Filsystemoperation

### Beräkningsuppgifter
Hantera komplexa matematiska eller logiska operationer:
- **"Beräkna ränta-på-ränta på 10 000 $ med 5 % i 10 år"** → Finansiell beräkningsfunktion
- **"Analysera denna datamängd för trender"** → Statistiska analysverktyg
- **"Optimera denna rutt för leverans"** → Ruttoptimeringsalgoritmer

### Datahanteringsarbetsflöden
Kedja ihop flera funktionsanrop för komplexa operationer:
1. **Hämta data** från flera källor
2. **Analysera och verifiera** informationen
3. **Omvandla** data till önskat format
4. **Spara resultat** i lämpliga system
5. **Generera rapporter** eller visualiseringar

### UI/UX Integration
Möjliggör dynamiska gränssnittsuppdateringar:
- **"Visa försäljningsdata på instrumentpanelen"** → Diagramgenerering och visning
- **"Uppdatera kartan med nya platser"** → Geospatial dataintegration
- **"Uppdatera lagersaldovisning"** → Realtidssynkronisering av data

### Anpassad Funktionsimplementering

Du kan också definiera egna funktioner för Qwen3:

```python
import json
from qwen_agent.tools.base import BaseTool

class WeatherTool(BaseTool):
    description = 'Get weather information for a specific location'
    parameters = [
        {
            'name': 'location',
            'type': 'string', 
            'description': 'City or location name',
            'required': True
        },
        {
            'name': 'units',
            'type': 'string',
            'description': 'Temperature units (celsius or fahrenheit)',
            'required': False,
            'default': 'celsius'
        }
    ]
    
    def call(self, params: str, **kwargs) -> str:
        """Execute the weather lookup"""
        params_dict = json.loads(params)
        location = params_dict.get('location')
        units = params_dict.get('units', 'celsius')
        
        # Simulera väder-API-anrop
        weather_data = {
            'location': location,
            'temperature': '22°C' if units == 'celsius' else '72°F',
            'condition': 'Partly cloudy',
            'humidity': '65%'
        }
        
        return json.dumps(weather_data)

# Använd det anpassade verktyget
tools = [WeatherTool()]
bot = Assistant(llm=llm_cfg, function_list=tools)

messages = [{'role': 'user', 'content': 'What\'s the weather in Tokyo?'}]
response = bot.run(messages=messages)
print(list(response)[-1])
```

### Vanliga Problem och Lösningar

#### Problem 1: Funktion Kallas Inte
**Symptom**: Modellen svarar med text istället för att anropa funktionen

**Lösningar**:
1. **Kontrollera funktionsbeskrivningen**: Säkerställ att den tydligt matchar användarens avsikt
2. **Verifiera parameterdefinitioner**: Se till att alla nödvändiga parametrar är korrekt definierade
3. **Granska systemprompt**: Inkludera tydliga instruktioner om när funktioner ska användas
4. **Testa med explicita förfrågningar**: Prova "Använd väderfunktionen för att hämta data för London"

#### Problem 2: Felaktiga Parametrar
**Symptom**: Funktion anropas med felaktiga eller saknade parametrar

**Lösningar**:
1. **Lägg till parameterexempel**: Inkludera exempelvärden i parameterbeskrivningar
2. **Använd enum-begränsningar**: Begränsa parametervärden till specifika alternativ när möjligt
3. **Implementera reservvärden**: Erbjud rimliga standardvärden för valfria parametrar

```python
{
    "name": "book_restaurant",
    "parameters": {
        "cuisine": {
            "type": "string",
            "enum": ["italian", "chinese", "mexican", "american", "french"],
            "description": "Type of cuisine (example: 'italian' for Italian food)"
        },
        "party_size": {
            "type": "integer",
            "minimum": 1,
            "maximum": 20,
            "description": "Number of people (example: 4 for a family of four)"
        }
    }
}
```

#### Problem 3: Fel vid Parallellt Funktionsanrop
**Symptom**: Endast en funktion exekveras när flera borde köras

**Lösningar**:
1. **Kontrollera stöd i modellen**: Säkerställ att din modell stödjer parallellt funktionsanrop
2. **Uppdatera systemprompt**: Inkludera "några verktyg" eller "flera verktyg" i systemmeddelandet
3. **Använd rätt modellversioner**: Phi-4-mini:3.8b-fp16 rekommenderas för Ollama

#### Problem 4: Mallproblem med Ollama
**Symptom**: Funktionsanrop fungerar inte med standardkonfigurationen av Ollama

**Lösningar**:
1. **Använd anpassad ModelFile**: Använd den korrigerade mallen som ges i denna handledning
2. **Uppdatera Ollama**: Se till att du använder version 0.5.13 eller högre
3. **Kontrollera modellkvantisering**: Höga kvantiseringsnivåer (Q8_0, fp16) fungerar bättre än kraftigt kvantiserade versioner

### Prestandaoptimering

#### 1. Effektiv Funktionsdesign
- **Håll funktioner fokuserade**: Varje funktion bör ha ett enda, tydligt syfte
- **Minimera externa beroenden**: Minska API-anrop och nätverksförfrågningar där det är möjligt
- **Cachelagra resultat**: Spara ofta efterfrågad data för att förbättra svarstider

#### 2. Batchning och Asynkrona Operationer
```python
import asyncio
import aiohttp

async def batch_function_calls(function_calls):
    """Execute multiple function calls concurrently"""
    async with aiohttp.ClientSession() as session:
        tasks = []
        for call in function_calls:
            if call["name"] == "fetch_url":
                task = fetch_url_async(session, call["parameters"]["url"])
                tasks.append(task)
        
        results = await asyncio.gather(*tasks)
        return results

async def fetch_url_async(session, url):
    async with session.get(url) as response:
        return await response.text()
```

#### 3. Resurshantering
- **Återanvänd anslutningar**: Återanvänd databaskommunikation och API-anslutningar
- **Begränsningar av hastighet**: Implementera lämplig hastighetsbegränsning för externa API:er
- **Timeout-hantering**: Sätt rimliga timeout-gränser för alla externa anrop

    async def execute_function(self, function_name: str, parameters: Dict) -> FunctionResult:
        """Execute a function with comprehensive error handling and logging"""
        start_time = datetime.now()
        
        try:
            # Validera att funktionen finns
            if function_name not in self.functions:
                return FunctionResult(
                    success=False,
                    error=f"Function '{function_name}' not found",
                    timestamp=start_time
                )
            
            # Kontrollera hastighetsbegränsningar
            if not self._check_rate_limit(function_name):
                return FunctionResult(
                    success=False,
                    error=f"Rate limit exceeded for function '{function_name}'",
                    timestamp=start_time
                )
            
            # Validera parametrar
            validation_result = self._validate_parameters(function_name, parameters)
            if not validation_result.success:
                return validation_result
            
            # Utför funktion
            func_info = self.functions[function_name]
            handler = func_info['handler']
            
            if asyncio.iscoroutinefunction(handler):
                result_data = await handler(**parameters)
            else:
                result_data = handler(**parameters)
            
            execution_time = (datetime.now() - start_time).total_seconds()
            
            result = FunctionResult(
                success=True,
                data=result_data,
                execution_time=execution_time,
                timestamp=start_time
            )
            
            # Logga lyckad körning
            self._log_function_call(function_name, parameters, result)
            
            return result
            
        except Exception as e:
            execution_time = (datetime.now() - start_time).total_seconds()
            result = FunctionResult(
                success=False,
                error=str(e),
                execution_time=execution_time,
                timestamp=start_time
            )

            self._log_function_call(function_name, parameters, result)
            
            return result

        """Check if function call is within rate limits"""
        func_info = self.functions[function_name]

        if (now - func_info['last_reset']).seconds >= 60:
            func_info['call_count'] = 0
            func_info['last_reset'] = now
        
        # Kontrollera om under gräns
        if func_info['call_count'] >= func_info['rate_limit']:
            return False
        
        func_info['call_count'] += 1
        return True
    
    def _validate_parameters(self, function_name: str, parameters: Dict) -> FunctionResult:
        """Validate function parameters"""
        func_params = self.functions[function_name]['parameters']
        
        # Kontrollera nödvändiga parametrar
        for param_name, param_info in func_params.items():
            if param_info.get('required', False) and param_name not in parameters:
                return FunctionResult(

                    error=f"Missing required parameter: {param_name}"

## Slutsats

Funktionsanrop i Små Språkmodeller innebär ett paradigmskifte från statiska AI-assistenter till dynamiska, kapabla agenter som kan interagera med verkliga världen. Denna handledning har täckt:

### Viktiga Insikter

1. **Grundläggande Förståelse**: Funktionsanrop möjliggör för SLM att gå bortom sin träningsdata genom att koppla till externa verktyg och tjänster.

2. **Implementeringsflexibilitet**: Flera angreppssätt finns, från låg-nivå implementeringar med anpassade mallar till hög-nivå ramverk som Qwen-Agent och Foundry Local.

3. **Produktionsöverväganden**: Företagsutplaceringar kräver fokus på felhantering, hastighetsbegränsning, säkerhet och revisionsloggning.

4. **Prestandaoptimering**: Korrekt funktionsdesign, effektiv exekvering och smart cachelagring kan avsevärt förbättra svarstider.

### Framtida Riktningar

Allteftersom SLM-teknologin fortsätter utvecklas kan vi förvänta oss:

- **Förbättrad Noggrannhet i Funktionsanrop**: Bättre avsiktsigenkänning och parameterekstraktion
- **Förstärkt Parallell Bearbetning**: Mer sofistikerad orkestrering av multifunktionsanrop
- **Bättre Integrationsstandarder**: Standardiserade protokoll för verktygsintegration
- **Avancerade Säkerhetsfunktioner**: Förbättrad autentisering och auktorisationsmekanismer
- **Utökad Ekosystem**: Växande bibliotek av färdiga funktioner och integrationer

### Komma Igång

För att börja implementera funktionsanrop i dina projekt:

1. **Börja Enkelt**: Starta med grundläggande enkelfunktionsscenarier
2. **Välj Ramverk**: Välj mellan direkt implementation (Ollama/Phi-4) eller ramverksassisterad (Qwen-Agent)
