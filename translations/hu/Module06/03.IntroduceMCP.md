# 03. szekció – Model Context Protocol (MCP) integráció

## Bevezetés az MCP-be (Model Context Protocol)

A Model Context Protocol (MCP) egy nyílt forráskódú szabvány az MI-alkalmazások külső rendszerekhez történő csatlakoztatására. Az MCP segítségével olyan MI-alkalmazások, mint a Claude vagy a ChatGPT, adatforrásokhoz (például helyi fájlokhoz, adatbázisokhoz), eszközökhöz (például keresőmotorokhoz, számológépekhez) és munkafolyamatokhoz (például speciális parancsokhoz) csatlakozhatnak, lehetővé téve számukra a kulcsfontosságú információk elérését és feladatok végrehajtását.

Gondolj az MCP-re úgy, mint az **AI-alkalmazások USB-C portjára**. Ahogyan az USB-C szabványos módot biztosít az elektronikus eszközök csatlakoztatására, úgy az MCP is szabványos módot nyújt az MI-alkalmazások külső rendszerekhez történő kapcsolódásához.

### Mit tesz lehetővé az MCP?

Az MCP erőteljes képességeket nyit meg az MI-alkalmazások számára:

- **Személyre szabott MI asszisztensek**: Az ügynökök hozzáférhetnek a Google Naptáradhoz és Notion-ödhöz, így személyre szabottabb MI asszisztensként működhetnek
- **Fejlett kódgenerálás**: A Claude Code egy egész webalkalmazást generálhat egy Figma-terv alapján
- **Vállalati adat integráció**: Vállalati chatbotok több adatbázishoz csatlakozhatnak egy szervezeten belül, így a felhasználók csevegésen keresztül elemezhetik az adatokat
- **Kreatív munkafolyamatok**: MI modellek 3D terveket készíthetnek Blenderben, majd azokat 3D nyomtatón kinyomtathatják
- **Valós idejű információ-hozzáférés**: Csatlakozás külső adatforrásokhoz az aktuális információkért
- **Összetett többlépéses műveletek**: Több eszköz és rendszer kombinációjával összetett munkafolyamatok végrehajtása

### Miért fontos az MCP?

Az MCP előnyöket kínál az egész ökoszisztéma számára:

**Fejlesztőknek**: Az MCP csökkenti a fejlesztési időt és komplexitást MI-alkalmazás vagy ügynök építése vagy integrálása során.

**MI-alkalmazásoknak**: Az MCP hozzáférést biztosít adatforrások, eszközök és alkalmazások ökoszisztémájához, amelyek növelik a képességeket és javítják a végfelhasználói élményt.

**Végfelhasználóknak**: Az MCP hatékonyabb MI-alkalmazásokat vagy ügynököket eredményez, amelyek hozzáférnek az adataidhoz és szükség esetén cselekednek a nevedben.

## Kis Nyelvi Modellek (SLM-ek) az MCP-ben

A Kis Nyelvi Modellek hatékony megközelítést jelentenek az MI telepítésében, több előnnyel:

### Az SLM-ek előnyei
- **Erőforrás-hatékonyság**: Alacsonyabb számítási igények
- **Gyorsabb válaszidő**: Csökkentett késleltetés valós idejű alkalmazásoknál  
- **Költséghatékonyság**: Minimális infrastruktúra szükséglet
- **Adatvédelem**: Lokálisan futtatható adatküldés nélkül
- **Testreszabhatóság**: Könnyebben finomhangolható specifikus területekre

### Miért működnek jól az SLM-ek az MCP-vel

Az SLM-ek és az MCP párosítása erőteljes kombinációt alkot, ahol a modell érvelési képességeit külső eszközök egészítik ki, ezzel kompenzálva a kisebb paraméterszámot a funkciók kiterjesztésével.

### MCP architektúra áttekintése

Az MCP **kliens-szerver architektúrát** követ, ahol egy MCP fogadó (egy MI-alkalmazás, mint a Claude Code vagy Claude Desktop) egy vagy több MCP szerverhez csatlakozik. Az MCP fogadó mindegyik MCP szerverhez egy MCP kliens létrehozásával valósítja ezt meg.

#### Fő szereplők

- **MCP Fogadó**: Az MI-alkalmazás, amely koordinálja és kezeli az egy vagy több MCP kliens működését
- **MCP Kliens**: Egy komponens, amely kapcsolatot tart fenn egy MCP szerverrel és kontextust szerez az MCP szervertől az MCP fogadó számára
- **MCP Szerver**: Egy program, amely kontextust biztosít MCP klienseknek

#### Kétrétegű architektúra

Az MCP két külön rétegből áll:

**Adatréteg**: Meghatározza a kliens-szerver kommunikáció JSON-RPC alapú protokollját, beleértve:
- Élettartam-kezelés (kapcsolat inicializálása, képességek egyeztetése)
- Alapvető primitívek (eszközök, erőforrások, parancsok)
- Kliens funkciók (mintavételezés, információkérés, naplózás)
- Hasznossági funkciók (értesítések, folyamatkövetés)

**Szállítási réteg**: Meghatározza a kommunikációs mechanizmusokat és csatornákat:
- **STDIO szállítás**: Helyi folyamatok esetén szabványos bemenet/kimenet adatfolyamokat használ (optimális teljesítmény, hálózati terhelés nélkül)
- **Streamelhető HTTP szállítás**: Távoli szerverek esetén HTTP POST-ot használ, opcionális Server-Sent Events támogatással (támogatja a szabványos HTTP hitelesítést)

```
┌─────────────────────────────────────┐
│           MCP Host                  │
│     (AI Application)                │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Client 1                │
│  ┌─────────────────────────────────┐ │
│  │        Data Layer               │ │
│  │  ├── Lifecycle Management       │ │
│  │  ├── Primitives (Tools/Resources)│ │
│  │  └── Notifications              │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │      Transport Layer           │ │
│  │  ├── STDIO Transport           │ │
│  │  └── HTTP Transport            │ │
│  └─────────────────────────────────┘ │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Server 1                │
│    (Local/Remote Context Provider)  │
└─────────────────────────────────────┘
```

### MCP alapvető primitívek

Az MCP meghatározza azokat a primitíveket, amelyek megadják, milyen típusú kontextuális információkat lehet megosztani MI-alkalmazásokkal és milyen műveleteket lehet végrehajtani.

#### Szerver primitívek

Az MCP három alapvető primitívet határoz meg, amelyeket a szerverek kibocsáthatnak:

**Eszközök**: Végrehajtható funkciók, amelyeket MI-alkalmazások hívhatnak meg műveletek végrehajtására
- Példák: fájlműveletek, API-hívások, adatbázis-lekérdezések
- Módszerek: `tools/list`, `tools/call`
- Támogatják a dinamikus felfedezést és végrehajtást

**Erőforrások**: Adatforrások, amelyek kontextuális információt szolgáltatnak MI-alkalmazásoknak
- Példák: fájl tartalmak, adatbázis rekordok, API válaszok
- Módszerek: `resources/list`, `resources/read`
- Lehetővé teszik a strukturált adatokhoz való hozzáférést

**Parancsok**: Újrahasználható sablonok, amelyek segítik a nyelvi modellekkel való interakciók struktúrálását
- Példák: rendszerparancsok, néhány mintapélda
- Módszerek: `prompts/list`, `prompts/get`
- Standardizálják az MI-interakciós mintákat

#### Kliens primitívek

Az MCP meghatároz olyan primitíveket is, amelyeket a kliensek kibocsáthatnak a gazdagabb interakciók érdekében:

**Mintavételezés**: Lehetővé teszi, hogy a szerverek kérjenek nyelvi modell befejezéseket a kliens MI-alkalmazásától
- Módszer: `sampling/complete`
- Támogatja a modellfüggetlen szerverfejlesztést
- Hozzáférést biztosít a gazda nyelvi modelljéhez

**Információ kérés**: Lehetővé teszi, hogy a szerverek további információkat kérjenek a felhasználóktól
- Módszer: `elicitation/request`
- Engedélyezi a felhasználói interakciót és megerősítést
- Támogatja a dinamikus információgyűjtést

**Naplózás**: Lehetővé teszi, hogy a szerverek naplóüzeneteket küldjenek a klienseknek
- Hibakeresési és megfigyelési célokra használják
- Átláthatóságot biztosít a szerver műveletekhez

### MCP protokoll életciklusa

#### Inicializálás és képesség egyeztetés

Az MCP állapotfüggő protokoll, amely élettartam-kezelést igényel. Az inicializációs folyamat több fontos célt szolgál:

1. **Protokollverzió egyeztetés**: Biztosítja, hogy a kliens és a szerver kompatibilis protokollverziókat használjon (például "2025-06-18")
2. **Képességek felfedezése**: Mindkét fél deklarálja a támogatott funkciókat és primitíveket
3. **Identitás-csere**: Azonosítási és verzió információk biztosítása

```python
# Példa inicializációs kérés
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # Az ügyfél támogatja a felhasználói interakciót
      "sampling": {}      # Az ügyfél képes LLM kiegészítéseket biztosítani
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### Eszköz felfedezés és végrehajtás

Az inicializáció után a kliensek felfedezhetik és végrehajthatják az eszközöket:

```python
# Fedezd fel az elérhető eszközöket
tools_response = await session.list_tools()

# Futtass egy eszközt
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### Valós idejű értesítések

Az MCP támogatja a valós idejű értesítéseket a dinamikus frissítésekhez:

```python
# A szerver értesítést küld, amikor az eszközök változnak
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# A kliens válaszként frissíti az eszközlistát
await session.list_tools()  # Frissített eszközök lekérése
```

**Alap Ollama beállítás:**

```bash
python ghmodel_mcp_demo.py --env vllm
```

**Server-Sent Events kapcsolat:**
```bash
python ghmodel_mcp_demo.py --run sse
```

**Egyedi MCP szerver:**
```bash
python ghmodel_mcp_demo.py --server /path/to/server.py
```

### 4. lépés: Programozott használat

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # MCP szerver paramétereinek konfigurálása
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # MCP kliens létrehozása és eszközök feldolgozása
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # Válasz generálása az eszközök képességeivel
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# Az automatizálás végrehajtása
result = asyncio.run(automated_interaction())
print(result)
```

## Fejlett funkciók

### Több háttér támogatás

A megvalósítás támogatja az Ollama és vLLM háttéreket is, lehetővé téve az igények szerinti választást:

Két kapcsolódási mód támogatott:

**STDIO mód**: Közvetlen folyamatkommunikáció

**SSE mód**: HTTP alapú streamelés

## Összefoglalás

Az MCP-vel integrált SLM-ek paradigmaváltást jelentenek az MI-alkalmazás fejlesztésében. A kis modellek hatékonyságának és a külső eszközök erejének kombinálásával a fejlesztők olyan intelligens rendszereket hozhatnak létre, amelyek mind erőforrás-hatékonyak, mind magas képességűek.

A Model Context Protocol szabványos módot nyújt az MI-alkalmazások külső rendszerekhez való kapcsolódására, hasonlóan ahhoz, ahogy az USB-C univerzális csatlakozási szabványt biztosít az elektronikus eszközök számára. Ez a szabványosítás lehetővé teszi:

- **Zökkenőmentes integráció**: MI modellek összekapcsolása különféle adatforrásokkal és eszközökkel
- **Ökoszisztéma növekedés**: Egyszer kell fejleszteni, több MI alkalmazásban használható
- **Fokozott képességek**: SLM-ek bővítése külső funkciókkal
- **Valós idejű frissítések**: Dinamikus, reagáló MI alkalmazások támogatása

Kulcsfontosságú tanulságok:
- Az MCP egy nyílt szabvány, amely összekapcsolja az MI-alkalmazásokat és külső rendszereket
- A protokoll támogatja az eszközöket, erőforrásokat és parancsokat mint alapvető primitíveket
- A valós idejű értesítések dinamikus, reagáló alkalmazásokat tesznek lehetővé
- A megfelelő életciklus-kezelés és hibakezelés elengedhetetlen a gyártási használathoz
- Az ökoszisztéma átfogó SDK-kat és fejlesztői eszközöket biztosít
