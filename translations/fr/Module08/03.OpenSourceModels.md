Cette session porte sur la découverte pratique de modèles et la gestion avec Foundry Local. ## Partie 1 : Découverte de Modèles avec la CLI Foundry

### Commandes de Gestion de Modèles de Base

La CLI Foundry fournit des commandes simples pour la découverte et la gestion de modèles :

```cmd
REM List all available models in the catalog
foundry model list

REM List cached (downloaded) models
foundry cache list

REM Check cache directory location
foundry cache ls
```

### Utiliser Vos Premiers Modèles

Commencez avec des modèles populaires et bien testés pour comprendre les caractéristiques de performance :

```cmd
REM Run Phi-4-Mini (lightweight, fast)
foundry model run phi-4-mini --verbose

REM Run Qwen 2.5 7B (larger, more capable)
foundry model run qwen2.5-7b --verbose

REM Run DeepSeek (specialized for coding)
foundry model run deepseek-r1-7b --verbose
```

**Note :** Le flag `--verbose` fournit des informations détaillées au démarrage, incluant :
- Progression du téléchargement du modèle (à la première exécution)
- Détails d’allocation mémoire
- Informations de liaison des services
- Metrics d’initialisation de performance

### Comprendre les Catégories de Modèles

**Petits Modèles de Langage (SLM) :**
- `phi-4-mini` : Rapide, efficace, idéal pour le chat général
- `phi-4` : Version plus capable avec un meilleur raisonnement

**Modèles Moyens :**
- `qwen2.5-7b` : Excellent raisonnement et contexte plus long
- `deepseek-r1-7b` : Optimisé pour la génération de code

**Modèles Plus Grands :**
- `llama-3.2` : Dernier modèle open-source de Meta
- `qwen2.5-14b` : Raisonnement de qualité entreprise

## Partie 3 : Cache des Modèles et Gestion du Stockage

### Comprendre le Cache des Modèles

Foundry Local gère automatiquement les téléchargements et la mise en cache des modèles :

```cmd
REM Check cache directory and contents
foundry cache ls

REM View cache location
foundry cache cd

REM Clean up unused models (if needed)
foundry cache clean
```

### Considérations sur le Stockage des Modèles

**Tailles Typiques des Modèles :**
- `phi-4-mini` : ~2,5 Go
- `qwen2.5-7b` : ~4,1 Go  
- `deepseek-r1-7b` : ~4,3 Go
- `llama-3.2` : ~4,9 Go
- `qwen2.5-14b` : ~8,2 Go

**Bonnes Pratiques de Stockage :**
- Gardez 2-3 modèles en cache pour un changement rapide
- Supprimez les modèles inutilisés pour libérer de l’espace : `foundry cache clean`
- Surveillez l’utilisation du disque, surtout sur de petits SSD
- Considérez les compromis entre taille et capacité du modèle

### Surveillance des Performances des Modèles

Pendant que les modèles fonctionnent, surveillez les ressources système :

**Gestionnaire des Tâches Windows :**
- Surveillez l’utilisation mémoire (les modèles restent chargés en RAM)
- Contrôlez l’utilisation CPU pendant l’inférence
- Vérifiez les E/S disque pendant le chargement initial du modèle

**Surveillance en Ligne de Commande :**
```cmd
REM Check memory usage (PowerShell)
Get-Process | Where-Object {$_.ProcessName -like "*foundry*"} | Select-Object ProcessName, WorkingSet64

REM Monitor running models
foundry service ps
```

## Partie 4 : Directives Pratiques pour la Sélection de Modèles

### Choisir les Modèles par Cas d'Usage

**Pour le Chat Général et Q&R :**
- Commencez avec : `phi-4-mini` (rapide, efficace)
- Passez à : `phi-4` (meilleur raisonnement)
- Avancé : `qwen2.5-7b` (contexte plus long)

**Pour la Génération de Code :**
- Recommandé : `deepseek-r1-7b`
- Alternative : `qwen2.5-7b` (également efficace pour le code)

**Pour le Raisonnement Complexe :**
- Meilleur choix : `qwen2.5-7b` ou `qwen2.5-14b`
- Option économique : `phi-4`

### Guide des Exigences Matérielles

**Exigences minimales du système :**
```
phi-4-mini:     8GB RAM,  entry-level CPU
phi-4:         12GB RAM,  mid-range CPU
qwen2.5-7b:    16GB RAM,  mid-range CPU
deepseek-r1:   16GB RAM,  mid-range CPU
qwen2.5-14b:   24GB RAM,  high-end CPU
```

**Recommandations pour une Meilleure Performance :**
- 32 Go+ de RAM pour un changement confortable entre modèles
- Stockage SSD pour un chargement plus rapide
- CPU moderne avec bonne performance mono-thread
- Support NPU (PC Windows 11 Copilot+ ) pour l’accélération

### Workflow pour le Changement de Modèles

```cmd
REM Stop current model (if needed)
foundry service stop

REM Start different model
foundry model run qwen2.5-7b

REM Verify model is running
foundry service status
```

## Partie 5 : Benchmark Simple des Modèles

### Test de Performance de Base

Voici une approche simple pour comparer la performance des modèles :

```python
# simple_bench.py - Basé sur les motifs de l'Échantillon 03
import time
import requests
import json

def test_model_response(model_name, prompt="Explain edge AI in one sentence."):
    """Test a single model with a prompt and measure response time."""
    start_time = time.time()
    
    try:
        response = requests.post(
            "http://localhost:8000/v1/chat/completions",
            headers={"Content-Type": "application/json"},
            json={
                "model": model_name,
                "messages": [{"role": "user", "content": prompt}],
                "max_tokens": 64
            },
            timeout=30
        )
        
        elapsed = time.time() - start_time
        
        if response.status_code == 200:
            result = response.json()
            return {
                "model": model_name,
                "latency_sec": round(elapsed, 3),
                "response": result["choices"][0]["message"]["content"],
                "status": "success"
            }
        else:
            return {
                "model": model_name,
                "status": "error",
                "error": f"HTTP {response.status_code}"
            }
            
    except Exception as e:
        return {
            "model": model_name,
            "status": "error", 
            "error": str(e)
        }

# Tester le modèle en cours d'exécution
if __name__ == "__main__":
    # Tester avec différents modèles (lancer d'abord chaque modèle)
    test_models = ["phi-4-mini", "qwen2.5-7b", "deepseek-r1-7b"]
    
    print("Model Performance Test")
    print("=" * 50)
    
    for model in test_models:
        print(f"\nTesting {model}...")
        print("Note: Make sure this model is running first with 'foundry model run {model}'")
        
        result = test_model_response(model)
        
        if result["status"] == "success":
            print(f"✅ {model}: {result['latency_sec']}s")
            print(f"   Response: {result['response'][:100]}...")
        else:
            print(f"❌ {model}: {result['error']}")
```

### Évaluation Manuelle de la Qualité

Pour chaque modèle, testez avec des prompts cohérents et évaluez manuellement :

**Prompts de Test :**
1. "Expliquez l’informatique quantique en termes simples."
2. "Écrivez une fonction Python pour trier une liste."
3. "Quels sont les avantages et inconvénients du télétravail ?"
4. "Résumez les bénéfices de l’IA en périphérie."

**Critères d’Évaluation :**
- **Précision** : L’information est-elle correcte ?
- **Clarté** : L’explication est-elle facile à comprendre ?
- **Complétude** : La question est-elle entièrement traitée ?
- **Vitesse** : Quelle est la rapidité de la réponse ?
