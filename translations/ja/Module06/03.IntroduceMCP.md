# セクション03 - Model Context Protocol（MCP）統合

## MCP（Model Context Protocol）についての紹介

Model Context Protocol（MCP）は、AIアプリケーションを外部システムに接続するためのオープンソース標準です。MCPを使用することで、ClaudeやChatGPTのようなAIアプリケーションは、データソース（例：ローカルファイル、データベース）、ツール（例：検索エンジン、計算機）、ワークフロー（例：専門的なプロンプト）に接続し、重要な情報へアクセスしタスクを実行できるようになります。

MCPは、<strong>AIアプリケーションのためのUSB-Cポート</strong>のようなものと考えてください。USB-Cが電子機器を接続するための標準化された方法を提供するのと同様に、MCPはAIアプリケーションを外部システムに接続するための標準的な方法を提供します。

### MCPで何が可能になるのか？

MCPはAIアプリケーションに強力な機能を解放します：

- **パーソナライズされたAIアシスタント**：エージェントがGoogleカレンダーやNotionにアクセスし、より個別化されたAIアシスタントとして機能可能
- <strong>高度なコード生成</strong>：Claude CodeがFigma設計からウェブアプリ全体を生成可能
- <strong>エンタープライズデータ統合</strong>：企業チャットボットが組織内の複数のデータベースに接続し、チャットを通じてデータ分析を支援
- <strong>クリエイティブワークフロー</strong>：AIモデルがBlender上で3Dデザインを作成し、3Dプリンターで出力可能
- <strong>リアルタイム情報アクセス</strong>：最新情報のために外部データソースに接続
- <strong>複雑な多段階操作</strong>：複数のツールやシステムを組み合わせた洗練されたワークフローの実行

### なぜMCPが重要なのか？

MCPはエコシステム全体に利益をもたらします：

<strong>開発者向け</strong>：MCPはAIアプリケーションやエージェントの構築・統合にかかる開発時間と複雑さを軽減します。

**AIアプリケーション向け**：MCPはデータソース、ツール、アプリのエコシステムへのアクセスを提供し、機能を拡張しエンドユーザー体験を向上させます。

<strong>エンドユーザー向け</strong>：MCPにより、データにアクセスし必要に応じて代理で行動できるより高性能なAIアプリケーションやエージェントが実現します。

## MCPにおける小型言語モデル（SLMs）

小型言語モデルは、AI展開の効率的なアプローチを示し、いくつかの利点を提供します：

### SLMの利点
- <strong>リソース効率</strong>：低い計算要件
- <strong>高速応答時間</strong>：リアルタイムアプリケーションにおける低遅延  
- <strong>コスト効果</strong>：最小限のインフラニーズ
- <strong>プライバシー</strong>：データ送信なしでローカルで実行可能
- <strong>カスタマイズ</strong>：特定ドメイン向けに簡単に微調整可能

### なぜSLMはMCPと相性が良いのか

SLMはMCPと組み合わせることで、外部ツールにより推論機能が強化され、小型パラメータ数の制約を機能性拡張で補完する強力なコンビネーションを生み出します。

## Python MCP SDK概要

Python MCP SDKはMCP対応アプリケーション構築の基盤を提供します。SDKには以下が含まれます：

- <strong>クライアントライブラリ</strong>：MCPサーバーへの接続用
- <strong>サーバーフレームワーク</strong>：カスタムMCPサーバー作成用
- <strong>プロトコルハンドラー</strong>：通信管理用
- <strong>ツール統合</strong>：外部関数実行用

### MCPアーキテクチャ概要

MCPは<strong>クライアント-サーバーアーキテクチャ</strong>に基づいています。MCPホスト（Claude CodeやClaude DesktopなどのAIアプリケーション）が1つ以上のMCPサーバーへ接続し、MCPホストは各MCPサーバーに対して1つのMCPクライアントを作成してこれを実現します。

#### 主要な参加者

- **MCPホスト**：1つまたは複数のMCPクライアントを管理・調整するAIアプリケーション
- **MCPクライアント**：MCPサーバーとの接続を維持し、MCPホストが使用するコンテキストを取得するコンポーネント
- **MCPサーバー**：MCPクライアントにコンテキストを提供するプログラム

#### 2層アーキテクチャ

MCPには2つの明確な層があります：

<strong>データ層</strong>：クライアント-サーバー通信のためのJSON-RPCベースのプロトコルを定義し、以下を含みます：
- ライフサイクル管理（接続初期化、機能交渉）
- コアプリミティブ（ツール、リソース、プロンプト）
- クライアント機能（サンプリング、引き出し、ログ）
- ユーティリティ機能（通知、進捗追跡）

<strong>トランスポート層</strong>：通信メカニズムとチャネルを定義し、
- **STDIOトランスポート**：ローカルプロセス用の標準入出力ストリームを使用（最適性能、ネットワーク負荷なし）
- **ストリーム可能HTTPトランスポート**：リモートサーバー用にHTTP POSTとオプションのServer-Sent Eventsを使用（標準HTTP認証対応）

### MCPコアプリミティブ

MCPはAIアプリケーションと共有可能なコンテキスト情報の種類と実行可能なアクションの範囲を示すプリミティブを定義します。

#### サーバープリミティブ

MCPはサーバーが公開できる3つのコアプリミティブを定義します：

<strong>ツール</strong>：AIアプリケーションが呼び出してアクションを実行できる関数
- 例：ファイル操作、API呼び出し、データベースクエリ
- メソッド：`tools/list`、`tools/call`
- 動的な検出と実行をサポート

<strong>リソース</strong>：AIアプリケーションにコンテキスト情報を提供するデータソース
- 例：ファイル内容、データベースレコード、API応答
- メソッド：`resources/list`、`resources/read`
- 構造化データへのアクセスを可能にする

<strong>プロンプト</strong>：言語モデルとの対話を構造化するための再利用可能なテンプレート
- 例：システムプロンプト、少数例示
- メソッド：`prompts/list`、`prompts/get`
- AI対話パターンの標準化

#### クライアントプリミティブ

MCPはより豊かな対話を可能にするためのクライアントが公開可能なプリミティブも定義します：

<strong>サンプリング</strong>：サーバーがクライアントのAIアプリケーションから言語モデルの補完を要求可能
- メソッド：`sampling/complete`
- モデルに依存しないサーバー開発を可能にする
- ホストの言語モデルへのアクセスを提供

<strong>引き出し</strong>：サーバーがユーザーから追加情報の要求可能
- メソッド：`elicitation/request`
- ユーザーの対話と確認を可能にする
- 動的な情報収集をサポート

<strong>ログ</strong>：サーバーがクライアントにログメッセージを送信可能
- デバッグや監視目的で使用
- サーバーの動作を可視化

### MCPプロトコルのライフサイクル

#### 初期化と機能交渉

MCPは状態保持型プロトコルであり、ライフサイクル管理が必要です。初期化プロセスは以下の重要な目的を果たします：

1. <strong>プロトコルバージョン交渉</strong>：クライアントとサーバーが互換性のあるプロトコルバージョン（例："2025-06-18"）を使用することを確認
2. <strong>機能検出</strong>：各パーティがサポートする機能やプリミティブを宣言
3. **ID交換**：識別およびバージョン情報の提供

```python
# 初期化リクエストの例
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # クライアントはユーザーインタラクションをサポートしています
      "sampling": {}      # クライアントはLLMの補完を提供できます
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### ツール検出と実行

初期化後、クライアントはツールを検出し実行可能です：

```python
# 利用可能なツールを発見する
tools_response = await session.list_tools()

# ツールを実行する
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### リアルタイム通知

MCPは動的な更新のためにリアルタイム通知をサポートします：

```python
# ツールが変更されたときにサーバーが通知を送信します
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# クライアントはツールリストをリフレッシュして応答します
await session.list_tools()  # 更新されたツールを取得します
```

### ステップ4：プログラム的な使用

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # MCPサーバーのパラメータを設定する
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # MCPクライアントとプロセスツールを作成する
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # ツールの機能で応答を生成する
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# 自動化を実行する
result = asyncio.run(automated_interaction())
print(result)
```

## 高度な機能

### マルチバックエンドサポート

実装例はOllamaとvLLMの両バックエンドをサポートし、要件に応じて選択可能です：

- **Ollama**：ローカル開発やテストに適している
- **vLLM**：本番環境や高スループットシナリオ向けに最適化されている

### 柔軟な接続プロトコル

以下の2つの接続モードをサポートします：

**STDIOモード**：直接的なプロセス通信
- 低遅延
- ローカルツールに適している
- 簡単なセットアップ

**SSEモード**：HTTPベースのストリーミング
- ネットワーク対応可能
- 分散システムに向いている
- リアルタイム更新

### ツール統合機能

システムは多様なツールと統合可能です：
- ウェブ自動化（Playwright）
- ファイル操作
- API連携
- システムコマンド
- カスタム関数

## エラーハンドリングとベストプラクティス

### 包括的なエラー管理

実装には以下の頑健なエラーハンドリングが含まれます：

**接続エラー：**
- MCPサーバーの障害
- ネットワークタイムアウト
- 接続問題

**ツール実行エラー：**
- ツールの欠落
- パラメーター検証
- 実行失敗

**応答処理エラー：**
- JSON解析問題
- フォーマット不一致
- LLM応答の異常

### ベストプラクティス

1. <strong>リソース管理</strong>：非同期コンテキストマネージャーを使用
2. <strong>エラーハンドリング</strong>：包括的なtry-catchブロックを実装
3. <strong>ログ管理</strong>：適切なログレベルを有効化
4. <strong>セキュリティ</strong>：入力を検証し出力をサニタイズ
5. <strong>パフォーマンス</strong>：接続プーリングとキャッシュを使用

## まとめ

MCP統合されたSLMは、AIアプリケーション開発におけるパラダイムシフトを示します。小型モデルの効率性と外部ツールの強力さを組み合わせることで、開発者はリソース効率が良く高機能なインテリジェントシステムを作成できます。

Model Context Protocolは、USB-Cが電子機器の共通接続規格を提供するように、AIアプリケーションと外部システムを接続する標準的な方法を提供します。この標準化により以下が可能になります：

- <strong>シームレスな統合</strong>：多様なデータソースやツールにAIモデルを接続
- <strong>エコシステムの成長</strong>：一度構築すれば複数のAIアプリケーションで利用可能
- <strong>機能拡張</strong>：外部機能でSLMの能力を強化
- <strong>リアルタイム更新</strong>：動的で応答性の高いAIアプリケーションを支援

主要なポイント：
- MCPはAIアプリケーションと外部システムを橋渡しするオープン標準
- プロトコルはツール、リソース、プロンプトをコアプリミティブとしてサポート
- リアルタイム通知が動的で応答性のあるアプリケーションを可能に
- 適切なライフサイクル管理とエラーハンドリングが本番利用に必須
- エコシステムは包括的なSDKと開発ツールを提供
