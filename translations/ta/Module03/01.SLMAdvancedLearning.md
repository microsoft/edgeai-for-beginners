SLM களை திறம்படப் பயன்படுத்துவது, மேம்படுத்துவது மற்றும் செயல்படுத்துவது செயல்திறனை அடிப்படையாக்கு எடு-அடிப்படைய AI தீர்வுகளை கட்டுவதற்கு அவசியம்.

## அறிமுகம்

இந்த பாடத்தில், சிறிய மொழி மாதிரிகள் (SLMs) மற்றும் அவற்றின் முன்னேற்ற செயலாக்கக் கொள்கைகளை ஆராய்வோம். SLMக்களின் அடிப்படை கருத்துக்களை, அவற்றின் அளவு எல்லைகள் மற்றும் வகைப்படுத்தல், மேம்படுத்துதல் முறைகள் மற்றும் எட்ஜ் கணினி சூழலுக்கு நடைமுறை அமல் கொள்கைகள் பற்றி அறிந்து கொள்வோம்.

## கற்றல் குறிக்கோள்கள்

இந்த பாடத்தின் முடிவில் நீங்கள் செய்யக்கூடியவை:

- 🔢 சிறிய மொழி மாதிரிகளின் அளவு எல்லைகள் மற்றும் வகைப்படுத்தல்களை புரிந்துகொள்வது.
- 🛠️ எட்ஜ் சாதனங்களில் SLM களை செயல்படுத்த முக்கிய மேம்படுத்தும் நுட்பங்களை அடையாளம் காண்பது.
- 🚀 SLM களுக்கான முன்னேற்றப்பட்ட அளவீட்டு மற்றும் சுருக்கல் கொள்கைகளை கற்றுக்கொள்வது.

## SLM அளவு எல்லைகள் மற்றும் வகைப்படுத்தலைக் கண்டறிதல்

சிறிய மொழி மாதிரிகள் (SLMs) AI மாதிரிகள் ஆகும். அவை இயற்கை மொழி உள்ளடக்கங்களை குறைந்த அளவிலான அளவைகள் கொண்டு செயலாக்க, புரிந்துகொள்ள மற்றும் உருவாக்க வடிவமைக்கப்பட்டவை. பெரிய மொழி மாதிரிகள் (LLMs) நூற்றுகணக்கான பில்லியன்கள் முதல் டிரில்லியன்கள் வரை அளவுகளை கொண்டிருப்பினும், SLMகள் திறமையாகவும் எட்ஜ் பயன்பாட்டுக்குமானதாக வடிவமைக்கப்பட்டுள்ளன.

அளவு வகைப்படுத்தல் கட்டமைப்பு SLMக்களின் வேறுபட்ட வகைகளையும் அவற்றின் பொருத்தமான பயன்பாடுகளையும் புரிந்துகொள்ள உதவுகிறது. இதன் மூலம் குறிப்பிட்ட எட்ஜ் கணினி சூழலுக்கு சரியான மாதிரியை தேர்வு செய்வதில் உதவுகிறது.

### அளவு வகைப்படுத்தல் கட்டமைப்பு

அளவு எல்லைகளைப் புரிந்துகொள்வது வெவ்வேறு எட்ஜ் கணினி சூழலுக்கு பொருத்தான மாதிரிகளைத் தேர்ந்தெடுப்பதில் உதவும்:

- **🔬 மைக்ரோ SLM கள்**: 100M - 1.4B அளவுகள் (மொபைல் சாதனங்களுக்கு மிக இலகுவானவை)
- **📱 சிறிய SLM கள்**: 1.5B - 13.9B அளவுகள் (சமநிலைப்பட்ட திறன் மற்றும் திறமைகள்)
- **⚖️ மத்திய SLM கள்**: 14B - 30B அளவுகள் (பெரிய மொழி மாதிரிகளின் திறனுக்கு நெருங்கும் போது திறமையை பராமரிக்கும்)

சரியான எல்லை ஆராய்ச்சி சமூகத்தில் மாறுபடும், ஆனால் பெரும்பாலான பயனாளர்கள் 30 பில்லியனுக்கு குறைவான அளவுகளை "சிறிய" என்று கருதுகிறார்கள், சில மூலம் 10 பில்லியன் அளவையும் குறைந்ததாகக் கணக்கிடுகின்றன.

### SLMகளின் முக்கிய நன்மைகள்

SLMகள் எட்ஜ் கணினி பயன்பாடுகளுக்கு மிக ஏற்றதாக சில அடிப்படைக் நன்மைகளை வழங்குகின்றன:

**செயல்பாட்டு திறன்**: குறைந்த அளவுகளால் விரைவான கணிப்பு நேரங்களை வழங்குவதால் நேரடி பயன்பாடுகளுக்கு சிறந்தவை. குறைந்த கணினி வளங்களைப் பயன்படுத்தி வளக் குறைந்த சாதனங்களில் செயல்படுத்த இது உதவுகிறது. குறைந்த ஆற்றல் செலவு மற்றும் குறைந்த கார்பன் பாதிப்புடன் செயல்படுகின்றன.

**அமல்படுத்தும் தற்கொலைத்தன்மை**: இவை இணைய இணைக்கும் தேவையின்றி சாதனத்தில் உள்ள AI திறன்களை வழங்குகின்றன, உள்ளூரில் செயலாக்கத்தால் தனியுரிமை மற்றும் பாதுகாப்பு மேம்படுத்தப்படுகிறது, குறிப்பிட்ட துறை பயன்பாடுகளுக்கு தனிப்பயனாக்கக்கூடியவை மற்றும் பல்வேறு எட்ஜ் கணினி சூழல்களுக்கு பொருத்தமானவை.

**செலவினைக் குறைக்கும் திறன்**: LLMகளைவிட குறைந்த செலவில் பயிற்சி மற்றும் அமல்படுத்தல் சாதிக்கின்றன, செயல்பாட்டு செலவுகள் குறைவு மற்றும் எட்ஜ் பயன்பாடுகளுக்கான குறைந்த வலய இடைவெளி கோரிக்கைகள்.

### Llama.cpp மேம்படுத்தல் கட்டமைப்பு

Llama.cpp எட்ஜ் செயல்பாட்டிற்கு அதிக திறனுள்ள அளவீடு நுட்பங்களை வழங்குகிறது:

**அளவீடு முறைகள்**: இந்த கட்டமைப்பு பல அளவீடு நிலைகளுக்கு ஆதரவளிக்கிறது: Q4_0 (4-பிட் அளவீடு மிகச்சிறந்த அளவு குறைப்பு - Qwen3-0.6B மொபைல் அமலுக்கு சிறந்தவை), Q5_1 (5-பிட் அளவீடு தரம் மற்றும் சுருக்கு சமநிலை - Phi-4-mini-3.8B எட்ஜ் கணிப்பு), மற்றும் Q8_0 (8-பிட் அளவீடு மூல தரத்திற்கு நெருங்கியது - Google Gemma3 உற்பத்திக்கு பரிந்துரைக்கப்பட்டது). கடின சுருக்க நிலைகளுக்கு BitNET 1-பிட் அளவீடு வழங்குகிறது.

**அமைப்புரை நன்மைகள்**: SIMD விரைந்து செயலாக்கத்துடன் CPU-இல் மிகச்சிறந்த கணிப்பு, நினைவக திறன் உயர்த்திய மாதிரி ஏற்றலும் செயல்பாடும், x86, ARM மற்றும் Apple Silicon மேம்பாட்டுத் தொழில்நுட்பங்களுக்கு இன்டிகிரேஷன்.

**நடைமுறை செயல்படு உதாரணம்**:

```bash
# llama.cpp ஐ நகலெடுத்து கட்டமைக்கவும்
git clone https://github.com/ggerganov/llama.cpp.git
cd llama.cpp
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . --config Release

# Hugging Face இல் இருந்து Phi-4-mini மொเดலை GGUF வடிவில் மாற்றவும்
# முதலில், Hugging Face இலிருந்து மொடல் பதிவிறக்கவும்
cd ..
python convert.py --outtype f16 --outfile phi-4-mini.gguf /path/to/downloaded/phi-4-mini/model

# மொடலை 4-பிட் துல்லியத்துடன் (Q4_0) அளவிடவும்
./build/bin/quantize phi-4-mini.gguf phi-4-mini-q4_0.gguf q4_0

# செயல்திறனைச் சரிபார்க்க மொடலை பரிசோதிக்கவும்
./build/bin/llama-bench -m phi-4-mini-q4_0.gguf -p "Write a function to calculate the Fibonacci sequence"

# அளவிடப்பட்ட மொடலை கொண்டு கணிப்பொறி இயக்கவும்
./build/bin/main -m phi-4-mini-q4_0.gguf -n 512 -p "Explain quantum computing in simple terms"
```

### Microsoft Olive மேம்படுத்தல் தொகுப்பு

Microsoft Olive உற்பத்தி சூழலுக்காக முழுமையான மாதிரி மேம்படுத்தல் பணிகள் கொண்டது:

**மேம்படுத்தல் நுட்பங்கள்**: தானாகத் துல்லியத்தை தேர்ந்தெடுக்கும் dynamic quantization (Qwen3 தொடர் மாதிரிகளுக்கு சிறந்தது), பிணைய மேம்படுத்தல் மற்றும் இயக்கி இணைப்பு (Google Gemma3 கட்டமைப்புக்கு), CPU, GPU மற்றும் NPU க்கான சாதனத்திற்கேந்தான சிறப்புமிக்க மேம்படுத்தல்கள் (ARM சாதனங்களில் Phi-4-mini-3.8B க்கு விசேட ஆதரவு), பல கட்ட தள மேம்படுத்தல்களுடன். BitNET மாதிரிகள் 1-பிட் அளவீடு வேலைப்பாடுகளுக்கான சிறப்பான அலவணக்கத் திறன்கள் தேவை.

**பணிசெயல் தானியக்கம்**: மேம்படுத்துதல் வேறுபாடுகளில் தானாக பயிற்சி நடத்துதல் மூலம் தரம் பாதுகாக்கப்படுகிறது. PyTorch மற்றும் ONNX போன்ற பிரபல ML அமைப்புகளுடன் ஒருங்கிணைந்து மேகம் மற்றும் எட்ஜ் செயல்பாடு மேம்படுத்தல்கள் கிடைக்கின்றன.

**நடைமுறை செயல்படு உதாரணம்**:

```python
# SLM க்கான Microsoft Olive மேம்படுத்தல் பணியை
from olive.model import PyTorchModel, ONNXModel
from olive.workflows import run_workflow
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

# பணியமைப்பை வரையறு
def create_olive_config(model_id="microsoft/phi-4-mini-instruct"):
    # மாடலை ஏற்றவும் மாதிரி உள்ளீடுகளை உருவாக்கவும்
    tokenizer = AutoTokenizer.from_pretrained(model_id)
    model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype=torch.float16)
    
    # தடம் பதிப்பதற்கான மாதிரி உள்ளீடுகளை உருவாக்கவும்
    sample_text = "Explain the concept of edge computing"
    inputs = tokenizer(sample_text, return_tensors="pt")
    
    # முதலில் ONNX ஆக ஏற்றுமதி செய்க
    model_path = f"{model_id.split('/')[-1]}.onnx"
    torch.onnx.export(
        model,
        (inputs["input_ids"],),
        model_path,
        input_names=["input_ids"],
        output_names=["logits"],
        dynamic_axes={
            "input_ids": {0: "batch", 1: "sequence"},
            "logits": {0: "batch", 1: "sequence"}
        },
        opset_version=15
    )
    
    # Olive மேம்படுத்தல் அமைப்பை உருவாக்கு
    config = {
        "input_model": ONNXModel(model_path),
        "systems": {
            "local_system": {
                "type": "LocalSystem"
            }
        },
        "passes": {
            # கிராப் மேம்படுத்தல் நடை
            "graph_optimization": {
                "type": "OrtTransformersOptimization",
                "config": {
                    "optimization_options": {
                        "enable_gelu": True,
                        "enable_layer_norm": True,
                        "enable_attention": True,
                        "use_multi_head_attention": True
                    }
                }
            },
            # INT8 க்கான அளவீட்டு நடை
            "quantization": {
                "type": "OrtQuantization",
                "config": {
                    "quant_mode": "static",
                    "activation_type": "int8",
                    "weight_type": "int8",
                    "op_types_to_quantize": ["MatMul", "Add", "Conv"]
                },
                "disable_search": True
            }
        },
        "engine": {
            "log_severity_level": 0,
            "cache_dir": "./cache"
        }
    }
    
    return config

# மேம்படுத்தல் பணியை இயக்கவும்
config = create_olive_config()
result = run_workflow(config)

# மேம்படுத்திய மாடலை சேமி
optimized_model = result.optimized_model
optimized_model.save("./optimized_phi4_mini")

# செயல்திறன் ஒப்பீட்டு போதுரு
print(f"Original model size: {os.path.getsize(model_path) / (1024 * 1024):.2f} MB")
print(f"Optimized model size: {os.path.getsize('./optimized_phi4_mini/model.onnx') / (1024 * 1024):.2f} MB")
```

BitNET 1-பிட் செயல்பாடுகளுக்கான சிறப்பு கணிப்பு கருவிகள் தேவை.

**நிறுவன ஒருங்கிணைப்பு**: OpenAI இணக்க API முகவரிகள், Kubernetes அமல்படுத்தல், கண்காணிப்பு மற்றும் ஆராய்ச்சி ஒருங்கிணைப்பு, தானாக அளவுகோல் மாற்றுகையின் நிறுவன நிலை தீர்வுகள்.

எட்ஜ் செயல்பாட்டிற்கு SLM தேர்வு செய்யும்போது பின்வரும் அம்சங்களை கருத்தில் கொள்ளுங்கள்:

**பயன்பாட்டு பொருத்தம்**: முறைப்படி மாதிரி திறன்களை தனிப்பட்ட பயன்பாடு தேவைகளுடன் பொருந்தச் சரிபார்க்கவும், பதில் தரம், கணிப்பு வேகம், நினைவகக் கட்டுப்பாடுகள் மற்றும் ஆஃப்லைன் இயங்குதாள் தேவைகள் போன்ற அம்சங்களை கவனிக்கவும்.

### மேம்படுத்தல் கொள்கை தேர்வு

**அளவீடு அணுகும் முறை**: தர செயல்திறன் மற்றும் சாதன கட்டுப்பாடுகளை பொறுத்து சான்றுதரமான அளவீடு நிலைகளைத் தேர்வு செய்யவும். அதிகபட்ச சுருக்கத்திற்கு Q4_0 (Qwen3-0.6B மொபைல் அமலுக்கு சிறந்தது), தர-சுருக்கு சமநிலை Q5_1 (Phi-4-mini-3.8B மற்றும் Google Gemma3 க்கு பொருந்தும்), மற்றும் மூல தரத்திற்கு நெருங்கிய Q8_0 (Qwen3-4B உற்பத்தி சூழலுக்கு பரிந்துரைக்கப்பட்டது). BitNET இன் 1-பிட் அளவீடு சிறப்பு பயன்பாடுகளுக்கு கடுமையான சுருக்கு அளவீடு.

**கட்டமைப்பு தேர்வு**: இலக்கு சாதன மற்றும் செயல்பாட்டு தேவைகள் அடிப்படையில் மேம்படுத்தல் கட்டமைப்புகளை தேர்ந்தெடுக்கவும். CPU செயல்பாட்டிற்காக Llama.cpp, முழுமையான மேம்படுத்தல் பணிகளுக்கு Microsoft Olive, மற்றும் Apple சாதனங்களுக்கு Apple MLX பயன்படுத்தவும்.

## நடைமுறை மாதிரி உதாரணங்கள் மற்றும் பயன்பாடுகள்

### உண்மை உலக செயல்பாடு தரவுகள்

**மொபைல் பயன்பாடுகள்**: Qwen3-0.6B சிறிய நினைவக புள்ளியுடன் ஸ்மார்ட் போன் உரையாடல் பயன்பாடுகளில் சிறந்தது, Google Gemma3 டேப்லெட் கல்வி கருவிகளுக்கு சமநிலைப்பட்ட செயல்திறன் வழங்குகிறது. Phi-4-mini-3.8B மொபைல் உற்பத்தித் திறனுக்கு மேம்பட்ட யூகத் திறன்களை வழங்குகிறது.

**மேஷின்கள் மற்றும் எட்ஜ் கணினி**: Qwen3-1.7B மேஷின் உதவியாளர் பயன்பாடுகளுக்கு சிறந்த செயல்திறன், Phi-4-mini-3.8B முன்னேற்றமான குறியீட்டு உருவாக்க திறன், Qwen3-4B தொழில்நுட்ப அலுவலக சூழலுக்கு நுணுக்கமான ஆவண பகுப்பாய்வு திறன்களை வழங்குகிறது.

**ஆராய்ச்சி மற்றும் பரிசோதனை**: BitNET மாதிரிகள் அகாடமிக் ஆராய்ச்சிக்கும் கடுமையான வளக் கட்டுப்பாட்டு பயன்பாடுகளுக்கும் உயர்நிலை குறுகிய துல்லிய கணிப்புகளை அனுமதிக்கின்றன.

### செயல்திறன் அளவைகள் மற்றும் ஒப்பீடுகள்

**கணிப்பு வேகம்**: Qwen3-0.6B மொபைல் CPU களில் மிக வேகமான கணிப்புகளை வழங்குகிறது, Google Gemma3 பொதுவான பயன்பாடுகளுக்கு சமநிலைப்பட்ட வேகம்-தரம் விகிதம், Phi-4-mini-3.8B சிக்கலான பணிகளுக்கு மேம்பட்ட யூக வேகம், BitNET சிறப்பு ஹார்ட்வேர் உடன் அதிகபட்ச வாயிலைக் கொண்டது.

**நினைவக தேவைகள்**: மாதிரி நினைவக அளவுகள் Qwen3-0.6B (1GB கீழ் அளவீடு), Phi-4-mini-3.8B (3-4GB அளவீடு), BitNET பரிசோதனை அமைப்புகளில் 500MB கீழ் அடைவு.

## சவால்கள் மற்றும் கவனப்படுத்தல்கள்

### செயல்திறன் வருமானங்கள்

SLM செயல்பாட்டில் மாதிரி அளவு, கணிப்பு வேகம் மற்றும் வெளியீட்டு தரம் ஆகியவற்றின் இடையேயான சமஜாதிக்கத்தை கவனமாக பரிசீலிக்க வேண்டும். உதாரணமாக, Qwen3-0.6B மிக வேகமான மற்றும் திறமையான சேவை வழங்கும், ஆனால் Phi-4-mini-3.8B அதிக வளம் தேவைப்படுவதனால் சிறந்த யூகதிறன் வழங்குகிறது. Google Gemma3 பெரும்பான்மையான பொதுப் பயன்பாடுகளுக்கான சமநிலை சார்ந்தது.

### சாதன பொருத்தம்

வெவ்வேறு எட்ஜ் சாதனங்களை கட்டளையிடும் திறன்கள் மற்றும் கட்டுப்பாடுகள் வெவ்வேறு. Qwen3-0.6B அடிப்படை ARM செயலி சாதனங்களில் சிறப்பாக இயங்கும், Google Gemma3 மிதமான கணினி வளங்களை கோருகிறது, Phi-4-mini-3.8B உயர் தர எட்ஜ் ஹார்ட்வேர் பயன்பாட்டுக்கு உகந்தது. BitNET மாதிரிகள் சிறப்பு 1-பிட் கருவிகளுக்காக மற்றவற்றைத் தேவைப்படுத்துகின்றன.

### பாதுகாப்பு மற்றும் தனியுரிமை

SLMகள் உள்ளூர் செயலாக்கத்தால் அதிகரிக்கப்பட்ட தனியுரிமையை வழங்குகின்றன, ஆனால் மாதிரிகள் மற்றும் தரவை பாதுகாப்பதற்கான சரியான பாதுகாப்பு நடவடிக்கைகள் எட்ஜ் சூழலில் செயல்படுத்தப்பட வேண்டும். இது Phi-4-mini-3.8B மற்றும் பன்மொழி பயன்பாடுகளில் உள்ள Qwen3 தொடர் மாதிரிகள் போன்றவற்றின் நிறுவுதலில் முக்கியம்.

## SLM வளர்ச்சியில் எதிர்கால பாய்ச்சல்கள்

SLM துறையில் மாதிரி கட்டமைப்புகள், மேம்படுத்தல் நுட்பங்கள் மற்றும் செயல்படுத்தல் கொள்கைகள் மேம்படும். எதிர்கால வளர்ச்சியில் திறமையான கட்டமைப்புக்கள், மேம்பட்ட அளவீடு முறைகள் மற்றும் எட்ஜ் ஹார்ட்வேர் துரிதப்படுத்திகளுடன் சிறந்த ஒருங்கிணைப்பு அடங்கும்.

இந்த பாய்ச்சல்களை புரிந்து வளர்ந்து வரும் தொழில்நுட்பங்களை கவனித்து SLM வளர்ச்சி மற்றும் செயல்படுத்தல் சிறந்த நடைமுறைகளுடன் தங்குவது அவசியம்.
