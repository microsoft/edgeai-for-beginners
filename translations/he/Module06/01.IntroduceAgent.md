# סוכני בינה מלאכותית ומודלים שפתיים קטנים: מדריך מקיף

## מבוא

במדריך זה נחקור סוכני בינה מלאכותית ומודלים שפתיים קטנים (SLMs) ואסטרטגיות יישום מתקדמות לסביבות מחשוב קצה. נכסה את המושגים היסודיים של בינה מלאכותית סוכנייתית, טכניקות אופטימיזציה ל-SLM, אסטרטגיות פריסה מעשיות למכשירים עם משאבים מוגבלים, ו-Microsoft Agent Framework לבניית מערכות סוכנים מוכנות לייצור.

נוף הבינה המלאכותית עובר שינוי פרדיגמה בשנת 2025. בעוד 2023 הייתה שנת הצ'טבוטים, ו-2024 חוותה פריחה של 'קופיילוטים', שנת 2025 שייכת לסוכני בינה מלאכותית — מערכות חכמות שחושבות,(reason), מתכננות, משתמשות בכלים ומבצעות משימות עם מינימום קלט אנושי, ומונעות יותר ויותר באמצעות מודלים שפתיים קטנים יעילים. Microsoft Agent Framework מופיעה כפתרון מוביל לבניית מערכות חכמות אלו עם יכולות מבוססות קצה בלתי מקוונות.

## הבנת סוכני בינה מלאכותית: יסודות וסיווגים

### הגדרה ומושגים מרכזיים

סוכן בינה מלאכותית (AI) מתייחס למערכת או תוכנה שיכולים לבצע משימות באופן אוטונומי בשמו של משתמש או מערכת אחרת על ידי עיצוב זרימת העבודה שלו ושימוש בכלים זמינים. בניגוד לבינה מלאכותית מסורתית שמגיבה רק לשאלות, סוכן יכול לפעול באופן עצמאי כדי להשיג מטרות.

### מסגרת סיווג סוכנים

הבנת גבולות הסוכן מסייעת בבחירת סוגי סוכנים מתאימים לתרחישי מחשוב שונים:

- **🔬 סוכני רפלקס פשוטים**: מערכות מבוססות כללים המגיבות לתפיסות מיידיות (תרמוסטטים, אוטומציה בסיסית)
- **📱 סוכנים מבוססי מודל**: מערכות המחזיקות מצב פנימי וזיכרון (רובוטים שואבי אבק, מערכות ניווט)
- **⚖️ סוכני מבוססי מטרה**: מערכות המתכננות ומבצעות רצפי פעולות להשגת יעדים (מתכנני מסלולים, מתזמני משימות)
- **🧠 סוכנים לומדים**: מערכות אדפטיביות שמשפרות ביצועים עם הזמן (מערכות המלצה, עוזרים מותאמים אישית)

### יתרונות מרכזיים של סוכני בינה מלאכותית

סוכני בינה מלאכותית מציעים כמה יתרונות בסיסיים שהופכים אותם לאידיאליים ליישומי מחשוב קצה:

**אוטונומיה תפעולית**: הסוכנים מספקים ביצוע משימות באופן עצמאי ללא פיקוח אנושי מתמשך, מה שהופך אותם למתאימים ליישומים בזמן אמת. הם מצריכים השגחה מינימלית תוך שמירה על התנהגות אדפטיבית, ומאפשרים פריסה על מכשירים עם משאבים מוגבלים עם עומס תפעולי מופחת.

**גמישות בפריסה**: מערכות אלו מאפשרות יכולות בינה מלאכותית במכשיר ללא צורך בחיבור אינטרנט, משפרות פרטיות ואבטחה באמצעות עיבוד מקומי, ניתנות להתאמה ליישומים תחומיים שונים ומתאימות לסביבות מחשוב קצה שונות.

**יעילות עלותית**: מערכות סוכנים מציעות פריסה חסכונית לעומת פתרונות מבוססי ענן, עם עלויות תפעול מופחתות ודרישות רוחב פס נמוכות ליישומי קצה.

## אסטרטגיות מתקדמות למודלים שפתיים קטנים

### יסודות SLM (מודל שפה קטן)

מודל שפה קטן (SLM) הוא מודל שפה שיכול להתאים למכשיר אלקטרוני צרכני רגיל ולבצע חיזוי עם זמן אחזור נמוך מספיק על מנת להיות פרקטי בעת מימוש בקשות סוכניות מצד משתמש יחיד. במונחים מעשיים, SLM בדרך כלל מכילים פחות מ-10 מיליארד פרמטרים.

**תכונות גילוי פורמט**: SLM מציעים תמיכה מתקדמת ברמות כימות שונות, תאימות חוצה פלטפורמות, אופטימיזציה לביצועים בזמן אמת, ויכולת פריסה בקצה. משתמשים יכולים ליהנות מפרטיות מוגברת באמצעות עיבוד מקומי ותמיכה ב-WebGPU לפריסת דפדפן.

**אוספי רמות כימות**: פורמטים פופולריים ל-SLM כוללים Q4_K_M לדחיסה מאוזנת ביישומים ניידים, סדרת Q5_K_S לפריסת קצה ממוקדת איכות, Q8_0 לדיוק קרוב למקור במכשירי קצה רבי עוצמה, ופורמטים ניסיוניים כמו Q2_K לתרחישים עם משאבים זעומים.

### GGUF (פורמט אוניברסלי GGML) לפריסת SLM

GGUF משמש כפיתוח ראשי לפריסת מודלים שפתיים קטנים מקוימים על מעבדי CPU ומכשירי קצה, מותאם במיוחד ליישומים סוכניים:

**תכונות מותאמות לסוכן**: הפורמט מספק משאבים מקיפים להמרה ופריסה של SLM עם תמיכה משופרת בקריאה לכלים, יצירת פלט מובנה ושיחות רב-סיבוביות. תאימות חוצה פלטפורמות מבטיחה התנהגות עקבית של הסוכן במכשירי קצה שונים.

**אופטימיזציית ביצועים**: GGUF מאפשר שימוש יעיל בזיכרון לזרימות עבודה סוכניות, תומך בטעינה דינמית של מודלים למערכות סוכנים מרובות ומספק חיזוי אופטימלי לאינטראקציות סוכניות בזמן אמת.

### מסגרות SLM מותאמות לקצה

#### אופטימיזציה של Llama.cpp לסוכנים

Llama.cpp מספק טכניקות כימות מתקדמות המותאמות במיוחד לפריסת SLM סוכנית:

**כימות ייחודי לסוכנים**: המסגרת תומכת ב-Q4_0 (אופטימלי לפריסת סוכנים ניידים עם הפחתת גודל של 75%), Q5_1 (איזון איכות-דחיסה לסוכני חיזוי קצה), ו-Q8_0 (איכות קרובה למקור למערכות סוכנים בייצור). פורמטים מתקדמים מאפשרים סוכנים דחוסים במיוחד לתרחישי קצה קיצוניים.

**יתרונות יישום**: חיזוי מותאם CPU עם האצת SIMD מספק ביצוע סוכני חיסכון בזיכרון. תאימות חוצה פלטפורמות על x86, ARM ו-Apple Silicon מאפשרת יכולות פריסה אוניברסליות.

#### מסגרת Apple MLX לסוכני SLM

Apple MLX מספקת אופטימיזציה מקומית שנועדה במיוחד לסוכנים מונעי SLM במכשירי Apple Silicon:

**אופטימיזציית סוכן ל-Apple Silicon**: המסגרת משתמשת בארכיטקטורת זיכרון מאוחדת עם שילוב Metal Performance Shaders, דיוק מעורב אוטומטי לחיזוי סוכנים, ורוחב פס זיכרון מותאם למערכות סוכנים מרובות. סוכני SLM מציגים ביצועים יוצאי דופן בשבבים מסדרת M.

**תכונות פיתוח**: תמיכת API בפייתון וסוויפט עם אופטימיזציות ייחודיות לסוכנים, הפרשנות אוטומטית ללמידת סוכנים ואינטגרציה חלקה עם כלי פיתוח אפל מספקים סביבת פיתוח סוכנים מקיפה.

#### ONNX Runtime לסוכני SLM חוצה פלטפורמות

ONNX Runtime מספק מנוע חיזוי אוניברסלי המאפשר לסוכני SLM לפעול בעקביות על פני פלטפורמות חומרה ומערכות הפעלה מגוונות:

**פריסה אוניברסלית**: ONNX Runtime מבטיח התנהגות עקבית של סוכני SLM על מערכות Windows, Linux, macOS, iOS ו-Android. התאימות החוצה פלטפורמות מאפשרת למפתחים לכתוב פעם אחת ולפרוס בכל מקום, ומפחיתה באופן משמעותי את עומס הפיתוח והתחזוקה ליישומים רב-פלטפורמיים.

**אפשרויות האצת חומרה**: המסגרת מספקת ספקי ביצוע מותאמים לקונפיגורציות חומרה שונות כולל CPU (Intel, AMD, ARM), GPU (NVIDIA CUDA, AMD ROCm), ומאיצים מיוחדים (Intel VPU, Qualcomm NPU). סוכני SLM יכולים לנצל אוטומטית את החומרה הטובה ביותר הזמינה ללא שינוי קוד.

**תכונות מוכנות לייצור**: ONNX Runtime מציעה תכונות ברמת ארגונים הנחוצות לפריסת סוכנים בייצור כולל אופטימיזציית גרפים לחיזוי מהיר יותר, ניהול זיכרון לסביבות עם משאבים מוגבלים, וכלי פרופיילינג מקיפים לניתוח ביצועים. המסגרת תומכת ב-API בפייתון וב-C++ לאינטגרציה גמישה.


## השוואה מתקדמת בין SLM ל-LLM במערכות סוכניות

### יתרונות SLM ביישומים סוכניים

**יעילות תפעולית**: SLM מציעים הפחתת עלויות של פי 10-30 לעומת LLM למשימות סוכניות, מאפשרים תגובות סוכניות בזמן אמת בהיקפים גדולים. הם מספקים זמני חיזוי מהירים יותר בזכות מורכבות חישובית מופחתת, והופכים אותם לאידיאליים ליישומים סוכניים אינטראקטיביים.

**יכולת פריסת קצה**: SLM מאפשרים ביצוע סוכני במכשיר ללא תלות באינטרנט, פרטיות משופרת באמצעות עיבוד סוכני מקומי, והתאמה ליישומים סוכניים תחומיים שונים המתאימים לסביבות מחשוב קצה מגוונות.

**אופטימיזציה ייחודית לסוכנים**: SLM מצטיינים בקריאה לכלים, יצירת פלט מובנה, וזרימות עבודה לקבלת החלטות שגרתיות המרכיבות 70-80% ממשימות סוכנים טיפוסיות.

### מתי להשתמש ב-SLM לעומת LLM במערכות סוכניות

**מתאים במיוחד ל-SLM**:
- **משימות סוכניות חוזרות**: הזנת נתונים, מילוי טפסים, קריאות API שגרתיות
- **אינטגרציית כלים**: שאילתות בסיס נתונים, פעולות קבצים, אינטראקציות מערכת
- **זרימות עבודה מובנות**: עקיבה אחרי תהליכים סוכניים מוגדרים מראש
- **סוכנים תחומיים**: שירות לקוחות, תזמון, ניתוח בסיסי
- **עיבוד מקומי**: פעילויות סוכניות רגישות לפרטיות

**עדיף ל-LLM**:
- **היסק מורכב**: פתרון בעיות חדשות, תכנון אסטרטגי
- **שיחות פתוחות**: צ'אט כללי, דיונים יצירתיים
- **משימות ידע רחב**: מחקר שדורש ידע כללי עצום
- **תרחישים חדשים**: טיפול במצבים סוכניים חדשים לחלוטין

### ארכיטקטורת סוכן היברידית

הגישה האופטימלית משלבת SLM ו-LLM במערכות סוכניות הטרוגניות:

**אורקסטרציה חכמה של סוכנים**:
1. **SLM כראשי**: לטפל ב-70-80% ממשימות סוכניות שגרתיות באופן מקומי
2. **LLM כשנדרש**: להעביר שאילתות מורכבות למודלים גדולים מבוססי ענן
3. **SLM מתמחים**: מודלים קטנים שונים לתחומים סוכניים שונים
4. **אופטימיזציית עלויות**: למזער קריאות יקרות ל-LLM באמצעות ניתוב חכם

## אסטרטגיות פריסת סוכני SLM לייצור

### Foundry Local: ריצה ארגונית מוכוונת מחשוב קצה

Foundry Local (https://github.com/microsoft/foundry-local) משמש כפתרון הדגל של מיקרוסופט לפריסת מודלים שפתיים קטנים בסביבות מחשוב קצה לייצור. הוא מספק סביבת ריצה מלאה שמיועדת במיוחד לסוכנים מונעי SLM עם תכונות ארגוניות ויכולות אינטגרציה חלקה.

**ארכיטקטורה מרכזית ותכונות**:
- **API התואם ל-OpenAI**: תאימות מלאה עם OpenAI SDK ואינטגרציות Agent Framework
- **אופטימיזציית חומרה אוטומטית**: בחירה אינטליגנטית של וריאנטים של מודלים בהתאם לחומרה זמינה (CUDA GPU, Qualcomm NPU, CPU)
- **ניהול מודלים**: הורדה, מטמון וניהול מחזור חיים אוטומטיים של מודלי SLM
- **זיהוי שירות**: גילוי שירות ללא צורך בקונפיגורציה למסגרות סוכנים
- **אופטימיזציית משאבים**: ניהול זיכרון אינטליגנטי ויעילות צריכת חשמל לפריסת קצה

#### התקנה וקינפוג

**התקנה חוצה פלטפורמות**:
```bash
# Windows (מומלץ)
winget install Microsoft.FoundryLocal

# macOS
brew tap microsoft/foundrylocal
brew install foundrylocal

# Linux (התקנה ידנית)
wget https://github.com/microsoft/foundry-local/releases/latest/download/foundry-local-linux.tar.gz
tar -xzf foundry-local-linux.tar.gz
sudo mv foundry-local /usr/local/bin/
```

**התחלה מהירה לפיתוח סוכנים**:
```bash
# הפעל שירות עם טעינת מודל אוטומטית
foundry model run phi-4-mini

# אמת את מצב השירות ונקודת הקצה
foundry service status

# הצג רשימת מודלים זמינים
foundry model ls

# בדוק את נקודת הקצה של ה-API
curl http://localhost:<port>/v1/models
```

#### אינטגרציה עם Agent Framework

**אינטגרציית Foundry Local SDK**:
```python
from foundry_local import FoundryLocalManager
from microsoft_agent_framework import Agent, Config
import openai

# אתחול Foundry Local עם ניהול שירות אוטומטי
manager = FoundryLocalManager("phi-4-mini")

# הגדר לקוח OpenAI לאינפרנס מקומי
client = openai.OpenAI(
    base_url=manager.endpoint,
    api_key=manager.api_key  # נוצר אוטומטית לשימוש מקומי
)

# יצירת סוכן עם Foundry Local כ backend
agent_config = Config(
    name="production-agent",
    model_provider="foundry-local",
    model_id=manager.get_model_info("phi-4-mini").id,
    endpoint=manager.endpoint,
    api_key=manager.api_key
)

agent = Agent(config=agent_config)
```

**בחירת מודל אוטומטית ואופטימיזציית חומרה**:
```python
# כאשרפעילFoundry Local בוחר אוטומטית את גרסת הדגם האופטימלית
models_by_use_case = {
    "lightweight_routing": "qwen2.5-0.5b",      # 500MB, מהיר מאוד
    "general_conversation": "phi-4-mini",       # 2.4GB, מאוזן
    "complex_reasoning": "phi-4",               # 7GB, בעל יכולת גבוהה
    "code_assistance": "qwen2.5-coder-0.5b"    # 500MB, מותאם לקוד
}

# Foundry Local מטפל בזיהוי חומרה וכימות
for use_case, model_alias in models_by_use_case.items():
    manager = FoundryLocalManager(model_alias)
```

```python
class FoundryResourceManager:
    def __init__(self):
        self.model_instances = {}
        self.resource_limits = {
            "max_memory_gb": 8,
            "max_concurrent_models": 3,
            "cpu_threshold": 80
        }
    
    def auto_scale_models(self, demand_metrics: dict):
        """Automatically scale models based on demand."""
        current_memory = self.get_total_memory_usage()
        
        # הקטן אם השימוש בזיכרון גבוה
        if current_memory > self.resource_limits["max_memory_gb"] * 0.8:
            self.scale_down_idle_models()
        
        # הגדל אם הביקוש גבוה והמשאבים מתירים
        for model_alias, demand in demand_metrics.items():
            if demand > 0.8 and len(self.model_instances) < self.resource_limits["max_concurrent_models"]:
                self.load_model_instance(model_alias)
    
    def load_model_instance(self, alias: str) -> FoundryLocalManager:
        """Load a new model instance if resources allow."""
        if alias not in self.model_instances:
            try:
                manager = FoundryLocalManager(alias)
                self.model_instances[alias] = manager
                logging.info(f"Loaded model instance: {alias}")
                return manager
            except Exception as e:
                logging.error(f"Failed to load model {alias}: {e}")
                return None
        return self.model_instances[alias]
    
    def scale_down_idle_models(self):
        """Remove idle model instances to free resources."""
        idle_models = []
        
        for alias, manager in self.model_instances.items():
            if manager.get_idle_time() > 300:  # 5 דקות חוסר פעילות
                idle_models.append(alias)
        
        for alias in idle_models:
            self.model_instances[alias].shutdown()
            del self.model_instances[alias]
            logging.info(f"Scaled down idle model: {alias}")
```

```python
import asyncio
import logging
from typing import Dict, Optional
from microsoft_agent_framework import Agent, Config

class OllamaProductionService:
    def __init__(self, models_config: Dict[str, str]):
        self.models_config = models_config
        self.base_url = "http://localhost:11434"
        self.agents = {}
        self.metrics = {
            "requests_processed": 0,
            "errors": 0,
            "model_usage": {model: 0 for model in models_config.keys()}
        }
        self._initialize_production_agents()
    
    def _initialize_production_agents(self):
        """Initialize production agents with health checks."""
        for agent_type, model_name in self.models_config.items():
            try:
                # ודא שהמודל זמין
                self._ensure_model_ready(model_name)
                
                # צור סוכן ייצור
                config = Config(
                    name=f"production-{agent_type}",
                    model_provider="ollama",
                    model_id=model_name,
                    endpoint=f"{self.base_url}/v1",
                    api_key="ollama",
                    max_tokens=512,
                    temperature=0.1,
                    timeout=30.0
                )
                
                agent = Agent(config=config)
                
                # הוסף כלים לייצור בהתאם לסוג הסוכן
                self._add_production_tools(agent, agent_type)
                
                self.agents[agent_type] = agent
                logging.info(f"Initialized {agent_type} agent with model {model_name}")
                
            except Exception as e:
                logging.error(f"Failed to initialize {agent_type} agent: {e}")
    
    def _ensure_model_ready(self, model_name: str):
        """Ensure model is pulled and ready for use."""
        try:
            # בדוק אם המודל קיים
            response = requests.get(f"{self.base_url}/api/tags")
            models = response.json().get('models', [])
            
            model_exists = any(model['name'] == model_name for model in models)
            
            if not model_exists:
                logging.info(f"Pulling model {model_name}...")
                pull_response = requests.post(f"{self.base_url}/api/pull", 
                    json={"name": model_name})
                
                if pull_response.status_code != 200:
                    raise Exception(f"Failed to pull model {model_name}")
                    
        except Exception as e:
            raise Exception(f"Model setup failed for {model_name}: {e}")
    
    def _add_production_tools(self, agent: Agent, agent_type: str):
        """Add tools based on agent type."""
        if agent_type == "customer_service":
            @agent.tool
            def lookup_customer(customer_id: str) -> dict:
                """Look up customer information."""
                # דמה חיפוש במסד הנתונים
                return {"customer_id": customer_id, "status": "active", "tier": "premium"}
            
            @agent.tool
            def create_support_ticket(issue: str, priority: str = "medium") -> str:
                """Create a support ticket."""
                ticket_id = f"TICK-{hash(issue) % 10000:04d}"
                return f"Created ticket {ticket_id} with priority {priority}"
        
        elif agent_type == "technical_support":
            @agent.tool
            def run_diagnostics(system_info: str) -> dict:
                """Run system diagnostics."""
                return {"status": "healthy", "issues": [], "recommendations": []}
            
            @agent.tool
            def access_knowledge_base(query: str) -> str:
                """Search technical knowledge base."""
                return f"Knowledge base results for: {query}"
    
    async def process_request(self, request: str, agent_type: str = "customer_service") -> dict:
        """Process user request with monitoring and error handling."""
        start_time = time.time()
        
        try:
            if agent_type not in self.agents:
                raise ValueError(f"Agent type {agent_type} not available")
            
            agent = self.agents[agent_type]
            response = await agent.chat_async(request)
            
            # עדכן מדדים
            self.metrics["requests_processed"] += 1
            self.metrics["model_usage"][agent_type] += 1
            
            processing_time = time.time() - start_time
            
            self._log_interaction(request, response, "success", processing_time, agent_type)
            
            return {
                "response": response,
                "status": "success",
                "processing_time": processing_time,
                "agent_type": agent_type
            }
            
        except Exception as e:
            self.metrics["errors"] += 1
            processing_time = time.time() - start_time
            
            self._log_interaction(request, str(e), "error", processing_time, agent_type)
            
            return {
                "response": "I'm experiencing technical difficulties. Please try again.",
                "status": "error",
                "error": str(e),
                "processing_time": processing_time
            }

        # בייצור, זה היה כותב למערכת רישום נאותה
        log_entry = {
            "timestamp": time.time(),
            "agent_type": agent_type,
            "request_length": len(request),
            "response_length": len(response),
            "status": status,
            "processing_time": processing_time
        }
```

```python
    async def collect_metrics(self) -> dict:
        """Collect comprehensive metrics from Ollama service."""
        metrics = {
            "timestamp": time.time(),
            "service_status": "unknown",
            "models": {},
            "performance": {},
            "resources": {}
        }
        
        try:
            # בדוק את בריאות השירות
            health_response = requests.get(f"{self.base_url}/api/tags", timeout=5)
            metrics["service_status"] = "healthy" if health_response.status_code == 200 else "unhealthy"
            
            if metrics["service_status"] == "healthy":
                # קבל מידע על הדגם
                models_data = health_response.json().get('models', [])
                for model in models_data:
                    model_name = model['name']
                    metrics["models"][model_name] = {
                        "size_gb": model.get('size', 0) / (1024**3),
                        "modified": model.get('modified_at', ''),
                        "digest": model.get('digest', '')[:12]  # סיכום קצר
                    }
                
                # בדוק את ביצועי האינפרנס
                start_time = time.time()
                test_response = requests.post(f"{self.base_url}/api/generate", 
                    json={
                        "model": list(metrics["models"].keys())[0] if metrics["models"] else "",
                        "prompt": "Hello",
                        "stream": False
                    }, timeout=10)
                
                if test_response.status_code == 200:
                    inference_time = (time.time() - start_time) * 1000
                    metrics["performance"] = {
                        "inference_time_ms": inference_time,
                        "tokens_per_second": self._calculate_tokens_per_second(test_response.json()),
                        "last_successful_inference": time.time()
                    }
            
        except Exception as e:
            metrics["service_status"] = "error"
            metrics["error"] = str(e)
        
        self.metrics_history.append(metrics)
        
        # שמור רק את 100 הערכים האחרונים של המדדים
        if len(self.metrics_history) > 100:
            self.metrics_history = self.metrics_history[-100:]
        
        return metrics
    
    def _calculate_tokens_per_second(self, response_data: dict) -> float:
        """Calculate approximate tokens per second from response."""
        try:
            # העריך את מספר הטוקנים (אומדן גס)
            response_text = response_data.get('response', '')
            estimated_tokens = len(response_text.split())
            
            # קבל מידע על זמני אם זמין
            eval_duration = response_data.get('eval_duration', 0)
            if eval_duration > 0:
                # המרת ננו-שניות לשניות
                duration_seconds = eval_duration / 1e9
                return estimated_tokens / duration_seconds if duration_seconds > 0 else 0
        except:
            pass
        return 0
    
    def check_alerts(self, current_metrics: dict) -> List[dict]:
        """Check current metrics against alert thresholds."""
        alerts = []
        
        # בדוק את זמן התגובה
        if current_metrics.get('performance', {}).get('inference_time_ms', 0) > self.alert_thresholds['response_time_ms']:
            alerts.append({
                "type": "performance",
                "message": f"High response time: {current_metrics['performance']['inference_time_ms']:.0f}ms",
                "severity": "warning"
            })
        
        # בדוק את מצב השירות
        if current_metrics.get('service_status') != 'healthy':
            alerts.append({
                "type": "availability",
                "message": f"Service unhealthy: {current_metrics.get('error', 'Unknown error')}",
                "severity": "critical"
            })
        
        return alerts
    
    def get_performance_summary(self, minutes: int = 60) -> dict:
        """Get performance summary for the last N minutes."""
        cutoff_time = time.time() - (minutes * 60)
        recent_metrics = [m for m in self.metrics_history if m['timestamp'] > cutoff_time]
        
        if not recent_metrics:
            return {"error": "No recent metrics available"}
        
        # חשב ממוצעים
        response_times = [m.get('performance', {}).get('inference_time_ms', 0) 
                         for m in recent_metrics if m.get('performance')]
        
        healthy_checks = sum(1 for m in recent_metrics if m.get('service_status') == 'healthy')
        uptime_percent = (healthy_checks / len(recent_metrics)) * 100 if recent_metrics else 0
        
        return {
            "period_minutes": minutes,
            "total_checks": len(recent_metrics),
            "uptime_percent": uptime_percent,
            "avg_response_time_ms": sum(response_times) / len(response_times) if response_times else 0,
            "max_response_time_ms": max(response_times) if response_times else 0,
            "min_response_time_ms": min(response_times) if response_times else 0
        }
```

```python
from microsoft_agent_framework import Agent, Config
import openai
import subprocess
import time
import requests
from typing import Optional, Dict, Any

class VLLMManager:
    def __init__(self, model_name: str, 
                 host: str = "localhost", 
                 port: int = 8000,
                 gpu_memory_utilization: float = 0.8,
                 max_model_len: int = 4096):
        self.model_name = model_name
        self.host = host
        self.port = port
        self.base_url = f"http://{host}:{port}"
        self.gpu_memory_utilization = gpu_memory_utilization
        self.max_model_len = max_model_len
        self.process = None
        self.client = None
        
    def start_server(self) -> bool:
        """Start VLLM server with optimized settings for agents."""
        try:
            cmd = [
                "python", "-m", "vllm.entrypoints.openai.api_server",
                "--model", self.model_name,
                "--host", self.host,
                "--port", str(self.port),
                "--gpu-memory-utilization", str(self.gpu_memory_utilization),
                "--max-model-len", str(self.max_model_len),
                "--trust-remote-code",
                "--disable-log-requests",  # הפחת רישום לפעילים
                "--served-model-name", self.get_served_model_name()
            ]
            
            self.process = subprocess.Popen(cmd, 
                stdout=subprocess.PIPE, 
                stderr=subprocess.PIPE)
            
            # המתן כדי שהשרת יתחיל
            max_retries = 30
            for _ in range(max_retries):
                if self.health_check():
                    self.client = openai.OpenAI(base_url=f"{self.base_url}/v1")
                    return True
                time.sleep(2)
                
            return False
            
        except Exception as e:
            print(f"Failed to start VLLM server: {e}")
            return False
    
    def get_served_model_name(self) -> str:
        """Get a clean model name for serving."""
        return self.model_name.replace("/", "--")
    
    def health_check(self) -> bool:
        """Check if VLLM server is healthy."""
        try:
            response = requests.get(f"{self.base_url}/health", timeout=5)
            return response.status_code == 200
        except:
            return False
    
    def get_openai_client(self) -> openai.OpenAI:
        """Get OpenAI-compatible client for VLLM."""
        if not self.client:
            self.client = openai.OpenAI(base_url=f"{self.base_url}/v1")
        return self.client
    
    def get_model_info(self) -> Dict[str, Any]:
        """Get model information and statistics."""
        try:
            response = requests.get(f"{self.base_url}/v1/models")
            if response.status_code == 200:
                return response.json()
        except:
            pass
        return {}
    
    def shutdown(self):
        """Shutdown VLLM server."""
        if self.process:
            self.process.terminate()
            self.process.wait()
```

```python
        """Select optimal agent based on request complexity and current load."""
        complexity_mapping = {

            "moderate": "balanced", 
            "complex": "capable"
        }

        if (preferred_category in self.agents and 
            current_load.get(preferred_category, 0) < 10):  # מקסימום 10 מתחברים במקביל לכל סוכן
            return preferred_category
        
        # מעבר לסוכן הזמין והפחות עמוס
        available_agents = [(cat, load) for cat, load in current_load.items() 
                          if cat in self.agents and load < 10]
        
        if available_agents:
            return min(available_agents, key=lambda x: x[1])[0]
        
        return "balanced"  # ברירת מחדל למעבר חזרה

            task = self._process_single_request(request, agent_category)
            tasks.append(task)

                "status": "error",
                "error": str(e),
                "agent_used": agent_category,
                "processing_time": time.time() - start_time
            }
```

```python
            if metrics.average_latency_ms > self.alert_thresholds["latency_max_ms"]:
                recommendations.append({
                    "instance": instance_name,
                    "type": "scale_up",
                    "reason": f"High latency: {metrics.average_latency_ms:.0f}ms",
                    "suggestion": "Consider adding tensor parallelism or increasing GPU memory"
                })
            
            # המלצה על ניצול GPU גבוה
            if metrics.gpu_utilization_percent > self.alert_thresholds["gpu_utilization_max"]:
                recommendations.append({
                    "instance": instance_name,
                    "type": "scale_out",
                    "reason": f"High GPU utilization: {metrics.gpu_utilization_percent:.1f}%",
                    "suggestion": "Consider adding additional GPU instances"
                })
            
            # המלצה על ניצול נמוך
            if (metrics.gpu_utilization_percent < 20 and 
                metrics.requests_per_second < 1):
                recommendations.append({
                    "instance": instance_name,
                    "type": "scale_down",
                    "reason": f"Low utilization: {metrics.gpu_utilization_percent:.1f}% GPU, {metrics.requests_per_second:.1f} RPS",
                    "suggestion": "Consider consolidating workloads or reducing resources"
                })
        
        return recommendations
```

**תיאום קצה-לענן**: יישם דפוסי הסלמה חכמים שבהם סוכני קצה מטפלים במשימות שגרתיות, סוכני ענן מספקים הסקה מורכבת כאשר יש חיבור, והעברה חלקה בין עיבוד קצה לענן שומרת על רציפות.

#### אסטרטגיות בחירת מודל

**הקצאת מודל מבוססת משימה**: Microsoft Agent Framework מאפשר בחירה חכמה של מודלים בהתבסס על מורכבות ודרישות המשימה:

### שיטות עבודה מומלצות עבור Microsoft Agent Framework

#### קווי מנחה לפיתוח

1. **התחל פשוט**: התחל בתרחישי סוכן יחיד לפני בניית מערכות סוכנים מורכבות מרובות
2. **בחירת גודל מודל נכון**: בחר את המודל הקטן ביותר שעומד בדרישות הדיוק שלך
3. **עיצוב כלי**: צור כלים ממוקדים לייעודים בודדים במקום כלים רב-פונקציונליים מורכבים
4. **תפעול שגיאות**: יישם דעיכה מחושבת לתרחישי אופליין וכשלים במודלים
5. **בדיקות**: בדוק סוכנים לעומק בתנאי אופליין וסביבות עם משאבים מוגבלים

#### שיטות עבודה מומלצות לפריסה

1. **פריסה הדרגתית**: פרוס לקבוצות משתמשים קטנות תחילה, הפעל ניטור מדדי ביצועים מקרוב
2. **ניטור משאבים**: התקן התראות עבור זיכרון, CPU וסף זמני תגובה
3. **אסטרטגיות גיבוי**: תמיד הכן תוכניות גיבוי לכשלים במודלים או גמר משאבים
4. **אבטחה תחילה**: יישם בקרות אבטחה מההתחלה, לא במועד מאוחר
5. **תיעוד**: שמור תיעוד ברור של יכולות ומגבלות הסוכן

### מפת דרכים עתידית ואינטגרציה

Microsoft Agent Framework ממשיכה להתפתח עם אופטימיזציית SLM משופרת, כלים משופרים לפריסת קצה, ניהול משאבים טוב יותר לסביבות מוגבלות, ואקוסיסטם כלים מורחב לתרחישים ארגוניים נפוצים.

**תכונות מתוכננות**:
- **AutoML לאופטימיזציית סוכנים**: כיוונון אוטומטי של SLMים למשימות סוכן ספציפיות
- **רשת Mesh בקצה**: תיאום בין פריסות סוכני קצה מרובות
- **טלמטריה מתקדמת**: ניטור וניתוח משופרים לביצועי סוכנים
- **בנאי סוכנים חזותי**: כלים לפיתוח סוכנים ללא קוד/קוד נמוך

## שיטות מומלצות ליישום סוכני SLM

### קווי הנחיה לבחירת SLM לסוכנים

בבחירת SLMים לפריסת סוכנים, יש לשקול את הגורמים הבאים:

**שיקולי גודל מודל**: בחר מודלים דחוסים במיוחד כמו Q2_K ליישומי סוכנים ניידים קיצוניים, מודלים מאוזנים כמו Q4_K_M לתרחישי סוכנים כלליים, ומודלים בעלי דיוק גבוה כמו Q8_0 ליישומי סוכנים בעלי דרישות איכות קריטיות.

**התאמת מקרה השימוש לסוכן**: התאם את יכולות ה-SLM לדרישות הסוכן הספציפיות, תוך התחשבות בשמירת דיוק להחלטות הסוכן, מהירות אינפרנציה לאינטראקציות בזמן אמת, מגבלות זיכרון לפריסת סוכני קצה ודרישות פעולה אופליין למיקוד בפרטיות.

### בחירת אסטרטגיית אופטימיזציה לסוכני SLM

**גישה לכימות עבור סוכנים**: בחר רמות כימות מתאימות בהתבסס על דרישות איכות הסוכן ומגבלות החומרה. שקול Q4_0 לדחיסה מקסימלית בסוכנים ניידים, Q5_1 לאיזון איכות-דחיסה בסוכנים כלליים, ו-Q8_0 לאיכות קרובה למקור ביישומי סוכנים קריטיים.


**בחירת מסגרות לפריסת סוכנים**: בחר מסגרות אופטימיזציה בהתבסס על חומרת היעד ודרישות הסוכן. השתמש ב-Llama.cpp לפריסת סוכנים מותאמת ל-CPU, Apple MLX ליישומים של סוכנים במעבדי Apple Silicon, ו-ONNX לתאימות סוכנים בין פלטפורמות שונות.

## המרה מעשית ושימושים של סוכני SLM

### תרחישי פריסה של סוכנים בעולם האמיתי

**יישומי סוכנים ניידים**: פורמטים מסוג Q4_K מצטיינים ביישומי סוכנים בסמארטפונים עם טביעת זיכרון מזערית, בעוד ש-Q8_0 מספק איזון בין ביצועים למערכות סוכנים בטאבלטים. פורמטים מסוג Q5_K מציעים איכות מעולה לסוכני פרודוקטיביות ניידים.

**מיחשוב סוכנים במחשב שולחני וקצה**: Q5_K מספק ביצועים מיטביים ליישומי סוכנים במחשב שולחני, Q8_0 מספק איכות גבוהה להסקת מסקנות בסביבות עבודה, ו-Q4_K מאפשר עיבוד יעיל במכשירי קצה.

**סוכנים למחקר וניסויים**: פורמטים מתקדמים של מדידה מאפשרים חקירת הסקה בדיוק נמוך במיוחד לסוכנים למחקר אקדמי ויישומי הוכחת רעיון הדורשים מגבלות משאבים קיצוניות.

### מדדי ביצועים של סוכני SLM

**מהירות הסקת סוכנים**: Q4_K משיג זמני תגובה מהירים ביותר על מעבדים ניידים, Q5_K מספק יחס מהירות-איכות מאוזן ליישומים כלליים, Q8_0 מציע איכות מעולה למשימות סוכנים מורכבות, ופורמטים ניסויים מספקים תפוקה מקסימלית לחומרה מיוחדת לסוכנים.

**דרישות זיכרון לסוכנים**: רמות הכימות עבור סוכנים נעות מ-Q2_K (פחות מ-500MB לדגמי סוכנים קטנים) עד Q8_0 (כ-50% מהגודל המקורי), עם תצורות ניסוי שמגיעות לכיווץ מקסימלי לסביבות סוכנים עם מגבלות משאבים.

### תאימות חומרה לסוכני SLM

מכשירי קצה שונים מציעים יכולות מגוונות לפריסת סוכני SLM. Q4_K פועל ביעילות על מעבדים בסיסיים לסוכנים פשוטים, Q5_K דורש משאבי חישוב מתונים לביצועים מאוזנים, ו-Q8_0 מרוויח מחומרה מתקדמת ליכולות סוכנים מתקדמות.

בעוד שסוכני SLM מאפשרים עיבוד מקומי לשיפור הפרטיות, יש ליישם אמצעי אבטחה נאותים להגנה על דגמי הסוכנים והנתונים בסביבות קצה. זה חשוב במיוחד בפריסת פורמטים מדויקים בסביבות ארגוניות או פורמטים מכווצים ביישומים המטפלים בנתונים רגישים.

### שלב 3: צור את הסוכן הראשון שלך עם Microsoft Agent Framework

**הגדרת סוכן בסיסית**:
```python
from microsoft_agent_framework import Agent, Config
from foundry_local import FoundryLocalManager

# אתחול חיבור Foundry מקומי
foundry = FoundryLocalManager("phi-4-mini")

# יצירת תצורת סוכן
config = Config(
    name="my-first-agent",
    model_provider="foundry-local",
    model_alias="phi-4-mini",
    offline_mode=True
)

# יצירה וקונפיגורציה של הסוכן
agent = Agent(
    config=config,
    model_endpoint=foundry.endpoint,
    api_key=foundry.api_key
)

# הגדרת כלי פשוט
@agent.tool
def get_current_time() -> str:
    """Get the current time."""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

# בדוק את הסוכן
response = agent.chat("What time is it?")
print(response)
```

### שלב 5: יישום פריסת קצה עם Microsoft Agent Framework

**הגדרות משאבים**:
```python
from microsoft_agent_framework import ResourceConfig

# תצורה לפריסת קצה
resource_config = ResourceConfig(
    max_memory_usage="2GB",
    max_concurrent_agents=2,
    model_cache_size="1GB",
    auto_unload_idle_models=True,
    power_management=True
)

agent = Agent(
    config=config,
    resource_limits=resource_config
)
```

**פריסת אמצעי בטיחות לסוכני קצה**:
- **אימות קלט מקומי**: בדיקת בקשות ללא תלות בענן
- **סינון פלט במצב לא מחובר**: ודא שהתגובות עומדות בסטנדרטים איכותיים מקומית
- **בקרות אבטחה בקצה**: יישום אבטחה ללא צורך בחיבור אינטרנט
- **מעקב מקומי**: מעקב אחר ביצועים וסימון בעיות באמצעות טלמטריה בקצה

### שלב 6: מדידה ואופטימיזציה של ביצועי סוכני קצה
- **שיעורי השלמת משימות סוכן**: מעקב אחר שיעורי הצלחה בתרחישים לא מחוברים
- **זמני תגובת סוכן**: הבטחת זמני תגובה תת-שנייה לפריסת קצה
- **שימוש במשאבים**: מעקב אחר זיכרון, מעבד, וסוללה במכשירי קצה
- **יעילות עלותית**: השוואת עלויות פריסת קצה אל מול אופציות מבוססות ענן
- **אמינות במצב לא מחובר**: מדידת ביצועי סוכן בעת הפסקות רשת

## מסקנות מרכזיות ליישום סוכני SLM

1. **SLMs מספיקים לסוכנים**: לרוב המשימות הסוכניות, דגמים קטנים מציגים ביצועים זהים לגדולים עם יתרונות משמעותיים
2. **יעילות עלות בסוכנים**: ריצה של סוכני SLM זולה פי 10-30, מה שהופך אותם לכלכליים לפריסה רחבה
3. **התמחות עובדת בסוכנים**: SLMs מותאמים במיוחד מבצעים לעיתים טוב יותר LLMs כלליים ביישומים ספציפיים
4. **ארכיטקטורת סוכן היברידית**: השתמש ב-SLM למשימות שגרתיות, ב-LLM להסקה מורכבת בעת הצורך
5. **Microsoft Agent Framework מאפשר פריסה בתפעול**: מספק כלים ברמת ארגון לבנייה, פריסה וניהול של סוכני קצה
6. **עקרונות עיצוב מועדפים לקצה**: סוכנים עם יכולות עבודה לא מקוונת ועיבוד מקומי מבטיחים פרטיות ואמינות
7. **אינטגרציה של Foundry Local**: חיבור חלק בין Microsoft Agent Framework להסקת דגמים מקומית
8. **העתיד הוא סוכני SLM**: דגמי שפה קטנים עם מסגרות פרודקשן הם עתיד ה-AI הסוכני, מאפשרים פריסה דמוקרטית ויעילה
