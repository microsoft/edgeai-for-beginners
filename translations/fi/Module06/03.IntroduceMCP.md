# Osa 03 - Model Context Protocol (MCP) -integraatio

## Johdanto MCP:hen (Model Context Protocol)

Model Context Protocol (MCP) on avoimen lähdekoodin standardi, joka yhdistää tekoälysovellukset ulkoisiin järjestelmiin. MCP:n avulla tekoälysovellukset kuten Claude tai ChatGPT voivat yhdistää tietolähteisiin (esim. paikalliset tiedostot, tietokannat), työkaluihin (esim. hakukoneet, laskimet) ja työnkulkuihin (esim. erikoistuneet kehotteet) — mahdollistaen tärkeiden tietojen saatavuuden ja tehtävien suorittamisen.

Ajattele MCP:tä kuin **USB-C-porttina tekoälysovelluksille**. Aivan kuten USB-C tarjoaa standardoidun tavan kytkeä elektronisia laitteita, MCP tarjoaa standardoidun tavan yhdistää tekoälysovellukset ulkoisiin järjestelmiin.

### Mitä MCP Mahdollistaa?

MCP avaa tehokkaita ominaisuuksia tekoälysovelluksille:

- **Personoidut tekoälyassistentit**: Agentit voivat käyttää Google-kalenteriasi ja Notioniasi toimiakseen henkilökohtaisempana tekoälyavustajana
- **Kehittynyt koodin generointi**: Claude Code voi generoida kokonaisen web-sovelluksen Figma-suunnitelman perusteella
- **Yritystiedon integrointi**: Yrityskäyttöön suunnatut chatbotit voivat yhdistää useisiin tietokantoihin organisaatiossa, mahdollistaen datan analysoinnin chatin avulla
- **Luovat työnkulut**: Tekoälymallit voivat luoda 3D-malleja Blenderillä ja tulostaa ne 3D-tulostimella
- **Reaaliaikainen tiedonsaanti**: Yhdistä ulkoisiin tietolähteisiin ajantasaisen tiedon saamiseksi
- **Monivaiheiset monimutkaiset toiminnot**: Suorita monimutkaisia työnkulkuja yhdistämällä useita työkaluja ja järjestelmiä

### Miksi MCP On Tärkeä?

MCP tarjoaa hyötyjä koko ekosysteemissä:

**Kehittäjille**: MCP vähentää kehitysaikaa ja monimutkaisuutta tekoälysovelluksen tai agentin rakentamisessa tai integroinnissa.

**Tekoälysovelluksille**: MCP tarjoaa pääsyn ekosysteemiin, johon kuuluu tietolähteitä, työkaluja ja sovelluksia, jotka parantavat ominaisuuksia ja loppukäyttäjäkokemusta.

**Loppukäyttäjille**: MCP johtaa kyvykkäämpiin tekoälysovelluksiin tai agenteihin, jotka voivat käyttää tietojasi ja tarvittaessa suorittaa toimenpiteitä puolestasi.

## Pienet kielimallit (SLM) MCP:ssä

Pienet kielimallit tarjoavat tehokkaan lähestymistavan tekoälyn käyttöönottoon, ja niillä on useita etuja:

### SLM:ien hyödyt
- **Resurssitehokkuus**: Alhaisemmat laskentaresurssivaatimukset
- **Nopeammat vasteajat**: Pienempi viive reaaliaikaisissa sovelluksissa  
- **Kustannustehokkuus**: Minimaaliset infrastruktuuritarpeet
- **Yksityisyys**: Voidaan ajaa paikallisesti ilman tietojen siirtoa
- **Mukautettavuus**: Helpompi hienosäätää tiettyihin toimialoihin

### Miksi SLM:t Toimivat Hyvin MCP:n Kanssa

SLM:t yhdistettynä MCP:hen muodostavat tehokkaan kokonaisuuden, jossa mallin päättelykyvyt täydentyvät ulkoisilla työkaluilla, korvaten pienemmän parametrimäärän parannetulla toiminnallisuudella.

## Python MCP SDK:n yleiskatsaus

Python MCP SDK tarjoaa perustan MCP-ominaisuudet sisältävien sovellusten rakentamiseen. SDK sisältää:

- **Asiakaskirjastot**: MCP-palvelimiin yhdistämiseen
- **Palvelinrunko**: Räätälöityjen MCP-palvelimien luomiseen
- **Protokollakäsittelijät**: Viestinnän hallintaan
- **Työkalujen integraatio**: Ulkoisten toimintojen suorittamiseen

## Käytännön toteutus: Phi-4 MCP -asiakas

Tutkitaan todellista toteutusta Microsoftin Phi-4-mini mallilla, joka on integroitu MCP-ominaisuuksilla.

### MCP-arkkitehtuurin yleiskatsaus

MCP noudattaa **asiakas-palvelin -arkkitehtuuria**, jossa MCP-isäntä (tekoälysovellus kuten Claude Code tai Claude Desktop) muodostaa yhteydet yhteen tai useampaan MCP-palvelimeen. MCP-isäntä luo kullekin MCP-palvelimelle yhden MCP-asiakasohjelman.

#### Keskeiset osapuolet

- **MCP-isäntä**: Tekoälysovellus, joka koordinoi ja hallinnoi yhtä tai useampaa MCP-asiakasta
- **MCP-asiakas**: Komponentti, joka ylläpitää yhteyttä MCP-palvelimeen ja hankkii kontekstin MCP-isännän käyttöön
- **MCP-palvelin**: Ohjelma, joka tarjoaa kontekstin MCP-asiakkaille

#### Kaksikerroksinen arkkitehtuuri

MCP koostuu kahdesta erillisestä kerroksesta:

**Datan kerros**: Määrittelee JSON-RPC-pohjaisen protokollan asiakas-palvelin -viestintään, sisältäen:
- Elinkaaren hallinnan (yhteyden alustus, ominaisuuksien neuvottelu)
- Keskeiset primitiivit (työkalut, resurssit, kehotteet)
- Asiakasominaisuudet (otanta, tiedon keruu, lokitus)
- Hyötyominaisuudet (ilmoitukset, etenemisen seuranta)

**Kuljetuskerros**: Määrittelee viestintämekanismit ja kanavat:
- **STDIO-kuljetus**: Käyttää standardisyötäntö/tuotantovirtaa paikallisille prosesseille (optimaalinen suorituskyky, ei verkkokuormitusta)
- **Virtaava HTTP-kuljetus**: Käyttää HTTP POST:ia valinnaisilla Server-Sent Events -päivityksillä etäpalvelimille (tukee tavallista HTTP-todennusta)

```
┌─────────────────────────────────────┐
│           MCP Host                  │
│     (AI Application)                │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Client 1                │
│  ┌─────────────────────────────────┐ │
│  │        Data Layer               │ │
│  │  ├── Lifecycle Management       │ │
│  │  ├── Primitives (Tools/Resources)│ │
│  │  └── Notifications              │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │      Transport Layer           │ │
│  │  ├── STDIO Transport           │ │
│  │  └── HTTP Transport            │ │
│  └─────────────────────────────────┘ │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Server 1                │
│    (Local/Remote Context Provider)  │
└─────────────────────────────────────┘
```

### MCP:n ydinkomponentit

MCP määrittelee primitiivit, jotka kuvaavat, millaista kontekstuaalista tietoa voidaan jakaa tekoälysovelluksille ja millaisia toimintoja voidaan suorittaa.

#### Palvelinprimitiivit

MCP määrittelee kolme ydinkomponenttia, joita palvelimet voivat tarjota:

**Työkalut**: Suoritettavat funktiot, joita tekoälysovellukset voivat kutsua toimenpiteiden suorittamiseksi
- Esimerkkejä: tiedostotoiminnot, API-kutsut, tietokantakyselyt
- Metodit: `tools/list`, `tools/call`
- Tukevat dynaamista löytämistä ja suorittamista

**Resurssit**: Tietolähteet, jotka tarjoavat kontekstuaalista tietoa tekoälysovelluksille
- Esimerkkejä: tiedostojen sisältö, tietokantatiedot, API-vastaukset
- Metodit: `resources/list`, `resources/read`
- Mahdollistavat pääsyn jäsenneltyyn dataan

**Kehotteet**: Uudelleenkäytettävät mallipohjat, jotka auttavat rakenteistamaan vuorovaikutusta kielimallien kanssa
- Esimerkkejä: järjestelmän kehotteet, muutama esimerkki
- Metodit: `prompts/list`, `prompts/get`
- Standardoivat tekoälyvuorovaikutuskuvioita

#### Asiakasprimitiivit

MCP määrittelee myös primitiivit, joita asiakkaat voivat tarjota monipuolisemman vuorovaikutuksen mahdollistamiseksi:

**Otanta**: Mahdollistaa palvelimille pyynnön kielimallin täydennyksistä asiakkaan tekoälysovellukselle
- Metodi: `sampling/complete`
- Mahdollistaa mallista riippumattoman palvelinkehityksen
- Tarjoaa pääsyn isännän kielimalliin

**Tiedonkeruu**: Mahdollistaa palvelimille pyynnön lisätiedoista käyttäjiltä
- Metodi: `elicitation/request`
- Mahdollistaa käyttäjävuorovaikutuksen ja vahvistuksen
- Tukee dynaamista tiedonkeruuta

**Lokitus**: Mahdollistaa palvelimille lokiviestien lähettämisen asiakkaille
- Käytetään virheenkorjaukseen ja valvontaan
- Tarjoaa näkyvyyden palvelintoimintoihin

### MCP-protokollan elinkaarimalli

#### Alustus ja ominaisuuksien neuvottelu

MCP on tilallinen protokolla, joka vaatii elinkaaren hallintaa. Alustusprosessilla on useita kriittisiä tarkoituksia:

1. **Protokollaversioiden neuvottelu**: Varmistaa, että sekä asiakas että palvelin käyttävät yhteensopivia protokollaversioita (esim. "2025-06-18")
2. **Ominaisuuksien löytyminen**: Kumpikin osapuoli ilmoittaa tuetut ominaisuudet ja primitiivit
3. **Identiteetin vaihto**: Antaa tunnistetiedot ja versionumerot

```python
# Esimerkki alustuspyyntö
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # Asiakas tukee käyttäjän vuorovaikutusta
      "sampling": {}      # Asiakas voi tarjota LLM-valmisteluja
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### Työkalujen löytäminen ja suorittaminen

Alustuksen jälkeen asiakkaat voivat löytää ja suorittaa työkaluja:

```python
# Löydä käytettävissä olevat työkalut
tools_response = await session.list_tools()

# Suorita työkalu
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### Reaaliaikaiset ilmoitukset

MCP tukee reaaliaikaisia ilmoituksia dynaamisille päivityksille:

```python
# Palvelin lähettää ilmoituksen, kun työkalut muuttuvat
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# Asiakas vastaa päivittämällä työkaluluettelon
await session.list_tools()  # Hanki päivitetyt työkalut
```

### Vaihe 4: Ohjelmallinen käyttö

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # Määritä MCP-palvelimen parametrit
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # Luo MCP-asiakas ja käsittele työkalut
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # Luo vastaus työkalujen ominaisuuksilla
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# Suorita automaatio
result = asyncio.run(automated_interaction())
print(result)
```

## Edistyneet ominaisuudet

### Monitaustajärjestelmän tuki

Toteutus tukee sekä Ollama- että vLLM-taustajärjestelmiä, jolloin voit valita tarpeidesi mukaan:

- **Ollama**: Sopii paremmin paikalliseen kehitykseen ja testaukseen
- **vLLM**: Optimoitu tuotantoon ja suureen läpimenoaikaan

### Joustavat yhteysprotokollat

Tuetaan kahta yhteystilaa:

**STDIO-tila**: Suora prosessiviestintä
- Pienempi viive
- Sopii paikallisille työkaluille
- Yksinkertainen käyttöönotto

**SSE-tila**: HTTP-pohjainen suoratoisto
- Verkkotukeva
- Parempi hajautetuille järjestelmille
- Reaaliaikaiset päivitykset

### Työkalujen integrointimahdollisuudet

Järjestelmä voi integroitua erilaisiin työkaluihin:
- Verkkoyhteyksien automaatio (Playwright)
- Tiedostotoiminnot
- API-kutsut
- Järjestelmäkomennot
- Räätälöidyt funktiot

## Yhteenveto

SLM:t integroituna MCP:hen edustavat paradigman muutosta tekoälysovellusten kehityksessä. Yhdistämällä pienten mallien tehokkuus ulkoisten työkalujen voimaan kehittäjät voivat luoda älykkäitä järjestelmiä, jotka ovat sekä resurssitehokkaita että erittäin kykeneviä.

Model Context Protocol tarjoaa standardoidun tavan yhdistää tekoälysovellukset ulkoisiin järjestelmiin, aivan kuten USB-C tarjoaa universaalin liitäntästandardin elektronisille laitteille. Tämä standardointi mahdollistaa:

- **Saumaton integraatio**: Yhdistä tekoälymallit monipuolisiin tietolähteisiin ja työkaluihin
- **Ekosysteemin kasvu**: Rakenna kerran, käytä monissa tekoälysovelluksissa
- **Parannetut ominaisuudet**: Laajenna SLM:ien toimintoja ulkoisilla ominaisuuksilla
- **Reaaliaikaiset päivitykset**: Tue dynaamisia, reagoivia tekoälysovelluksia

Keskeiset opit:
- MCP on avoin standardi, joka yhdistää tekoälysovellukset ja ulkoiset järjestelmät
- Protokolla tukee työkaluja, resursseja ja kehotteita ydinkomponenteina
- Reaaliaikaiset ilmoitukset mahdollistavat dynaamiset ja reagoivat sovellukset
- Asianmukainen elinkaaren hallinta ja virheiden käsittely ovat välttämättömiä tuotantokäytössä
- Ekosysteemi tarjoaa kattavat SDK:t ja kehitystyökalut
