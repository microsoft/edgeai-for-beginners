# 3 skyrius – Modelio konteksto protokolo (MCP) integracija

## Įvadas į MCP (Modelio konteksto protokolą)

Modelio konteksto protokolas (MCP) yra atvirojo kodo standartas, skirtas AI programoms jungtis prie išorinių sistemų. Naudojant MCP, AI programos, tokios kaip Claude ar ChatGPT, gali prisijungti prie duomenų šaltinių (pvz., vietinių failų, duomenų bazių), įrankių (pvz., paieškos variklių, skaičiuotuvų) ir darbo procesų (pvz., specializuotų užklausų)—leisdamas joms pasiekti svarbią informaciją ir atlikti užduotis.

Galvokite apie MCP kaip apie **USB-C jungtį AI programoms**. Kaip USB-C suteikia standartizuotą būdą jungti elektroninius įrenginius, taip MCP suteikia standartizuotą būdą jungti AI programas prie išorinių sistemų.

### Ką gali įgalinti MCP?

MCP atveria galingas galimybes AI programoms:

- **Personalizuoti AI asistentai**: agentai gali pasiekti jūsų Google kalendorių ir Notion, veikiant kaip labiau personalizuotas AI asistentas
- **Pažangi kodo generacija**: Claude Code gali sugeneruoti visą žiniatinklio programą naudojant Figma dizainą
- **Įmonių duomenų integracija**: įmonių chatbot’ai gali prisijungti prie kelių duomenų bazių visoje organizacijoje, leidžiant vartotojams analizuoti duomenis su pokalbiu
- **Kūrybiniai darbo procesai**: AI modeliai gali kurti 3D dizainus Blender programoje ir juos atspausdinti naudodami 3D spausdintuvą
- **Realaus laiko informacijos prieiga**: prisijungimas prie išorinių duomenų šaltinių siekiant gauti naujausią informaciją
- **Sudėtingos daugiapakopės operacijos**: sudėtingų darbo procesų atlikimas derinant kelis įrankius ir sistemas

### Kodėl MCP svarbus?

MCP suteikia naudos visai ekosistemai:

**Kūrėjams**: MCP sumažina vystymo laiką ir sudėtingumą kuriant arba integruojantis su AI programa ar agentu.

**AI programoms**: MCP suteikia prieigą prie ekosistemos duomenų šaltinių, įrankių ir programų, kurios pagerina galimybes ir naudotojo patirtį.

**Galutiniams vartotojams**: MCP sukuria labiau pajėgias AI programas ar agentus, kurie gali pasiekti jūsų duomenis ir prireikus atlikti veiksmus jūsų vardu.

## Mažieji kalbos modeliai (SLM) MCP kontekste

Mažieji kalbos modeliai yra efektyvus AI diegimo būdas, turintis keletą privalumų:

### SLM privalumai
- **Išteklių efektyvumas**: mažesni skaičiavimo reikalavimai
- **Greitesnis atsakas**: sumažinta delsos riba realaus laiko programoms  
- **Kaina**: minimalūs infrastruktūros poreikiai
- **Privatumas**: gali veikti vietoje be duomenų perdavimo
- **Individualizavimas**: lengviau pritaikyti specifinėms sritims

### Kodėl SLM gerai veikia su MCP

SLM kartu su MCP sukuria galingą kombinaciją, kur modelio mąstymo galimybės yra papildytos išoriniais įrankiais, kompensuodamos jų mažesnį parametrų skaičių didesnėmis funkcijomis.

## Praktinis įgyvendinimas: Phi-4 MCP klientas

Apžvelkime realų įgyvendinimą naudojant Microsoft Phi-4 mini modelį, integruotą su MCP galimybėmis.

### MCP architektūros apžvalga

MCP remiasi **klientas-serveris architektūra**, kur MCP pagrindinė programa (AI programa, pvz., Claude Code ar Claude Desktop) užmezga ryšius su vienu arba keliais MCP serveriais. MCP pagrindinė programa tai pasiekia kurdama po vieną MCP klientą kiekvienam MCP serveriui.

#### Pagrindiniai dalyviai

- **MCP pagrindinė programa (host)**: AI programa, kuri koordinuoja ir valdo vieną arba kelis MCP klientus
- **MCP klientas**: komponentas, kuris palaiko ryšį su MCP serveriu ir gauna kontekstą MCP pagrindinei programai naudoti
- **MCP serveris**: programa, teikianti kontekstą MCP klientams

#### Dviejų sluoksnių architektūra

MCP sudarytas iš dviejų skirtingų sluoksnių:

**Duomenų sluoksnis**: apibrėžia JSON-RPC pagrįstą protokolą klientas-serveris komunikacijai, apimantį:
- Gyvavimo ciklo valdymą (jungties inicializavimas, galimybių derinimas)
- Pagrindines prietaisų rinkinių priemones (įrankiai, ištekliai, užklausos)
- Kliento funkcijos (pavyzdžių generavimas, papildoma informacija, registravimas)
- Naudingumo funkcijos (pranešimai, pažangos sekimas)

**Perdavimo sluoksnis**: apibrėžia komunikacijos mechanizmus ir kanalus:
- **STDIO perdavimas**: naudoja standartines įvesties/išvesties srautus vietiniams procesams (optimalus našumas, be tinklo resursų sąnaudų)
- **Streamable HTTP perdavimas**: naudoja HTTP POST su opcionaliais serverio siunčiamais įvykiais (Server-Sent Events) nuotoliniams serveriams (palaiko standartinę HTTP autentifikaciją)

```
┌─────────────────────────────────────┐
│           MCP Host                  │
│     (AI Application)                │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Client 1                │
│  ┌─────────────────────────────────┐ │
│  │        Data Layer               │ │
│  │  ├── Lifecycle Management       │ │
│  │  ├── Primitives (Tools/Resources)│ │
│  │  └── Notifications              │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │      Transport Layer           │ │
│  │  ├── STDIO Transport           │ │
│  │  └── HTTP Transport            │ │
│  └─────────────────────────────────┘ │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Server 1                │
│    (Local/Remote Context Provider)  │
└─────────────────────────────────────┘
```

### MCP pagrindinės priemonės

MCP apibrėžia priemones, kurios nurodo, kokio tipo kontekstinė informacija gali būti dalinama su AI programomis ir kokius veiksmus galima atlikti.

#### Serverio priemonės

MCP apibrėžia tris pagrindines priemones, kurias serveriai gali teikti:

**Įrankiai**: vykdomos funkcijos, kurias AI programos gali iškviesti veiksmams atlikti
- Pavyzdžiai: failų operacijos, API kvietimai, duomenų bazių užklausos
- Metodai: `tools/list`, `tools/call`
- Palaiko dinaminį atradimą ir vykdymą

**Ištekliai**: duomenų šaltiniai, teikiantys kontekstinę informaciją AI programoms
- Pavyzdžiai: failų turinys, duomenų bazių įrašai, API atsakymai
- Metodai: `resources/list`, `resources/read`
- Leidžia prieigą prie struktūrizuotų duomenų

**Užklausos (Prompts)**: pakartotiniai šablonai, padedantys struktūrizuoti sąveikas su kalbos modeliais
- Pavyzdžiai: sistemos užklausos, keletas pavyzdžių (few-shot)
- Metodai: `prompts/list`, `prompts/get`
- Standartizuoja AI sąveikos modelius

#### Kliento priemonės

MCP taip pat apibrėžia priemones, kurias klientai gali teikti, leidžiančias turtingesnes sąveikas:

**Pavyzdžių generavimas (Sampling)**: leidžia serveriams prašyti kalbos modelio išbaigimų iš kliento AI programos
- Metodas: `sampling/complete`
- Galimybė kurti nepriklausomus nuo modelio serverius
- Suteikia prieigą prie pagrindinės programos kalbos modelio

**Papildoma informacija (Elicitation)**: leidžia serveriams prašyti papildomos informacijos iš vartotojų
- Metodas: `elicitation/request`
- Leidžia vartotojo sąveiką ir patvirtinimą
- Palaiko dinaminį informacijos rinkimą

**Registravimas (Logging)**: leidžia serveriams siųsti žurnalo pranešimus klientams
- Naudojama klaidų nustatymui ir stebėjimui
- Suteikia matomumą serverio veiklai

### MCP protokolo gyvavimo ciklas

#### Inicializacija ir galimybių derinimas

MCP yra būsenų protokolas, kuriam reikalingas gyvavimo ciklo valdymas. Inicializacijos procesas atlieka kelias svarbias funkcijas:

1. **Protokolo versijos derinimas**: užtikrina, kad tiek klientas, tiek serveris naudoja suderinamas protokolo versijas (pvz., "2025-06-18")
2. **Galimybių atradimas**: kiekviena šalis deklaruoja palaikomas funkcijas ir priemones
3. **Tapatybės apsikeitimas**: teikia identifikavimo ir versijavimo informaciją

```python
# Inicializavimo užklausos pavyzdys
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # Klientas palaiko vartotojo sąveiką
      "sampling": {}      # Klientas gali pateikti LLM užbaigimus
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### Įrankių atradimas ir vykdymas

Po inicializacijos klientai gali atrasti ir vykdyti įrankius:

```python
# Atraskite turimus įrankius
tools_response = await session.list_tools()

# Vykdyti įrankį
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### Realiojo laiko pranešimai

MCP palaiko realiojo laiko pranešimus dinamiškiems atnaujinimams:

```python
# Serveris siunčia pranešimą, kai keičiasi įrankiai
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# Klientas atsako atnaujindamas įrankių sąrašą
await session.list_tools()  # Gauti atnaujintus įrankius
```

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # Konfigūruoti MCP serverio parametrus
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # Sukurti MCP klientą ir apdoroti įrankius
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # Sugeneruoti atsakymą su įrankių galimybėmis
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# Vykdyti automatizavimą
result = asyncio.run(automated_interaction())
print(result)
```

## Pažangios funkcijos

### Daugiapagrindė palaikymas (multi-backend)

Įgyvendinimas palaiko tiek Ollama, tiek vLLM užnugarius, leidžiančius pasirinkti pagal jūsų poreikius:

- **Ollama**: geriau vietiniam vystymui ir testavimui
- **vLLM**: optimizuotas produkcijai ir didelio pralaidumo scenarijams

### Lanksčios ryšio protokolų galimybės

Palaikomi du jungtis režimai:

**STDIO režimas**: tiesioginis procesų ryšys
- Mažesnė delsos riba
- Tinka vietiniams įrankiams
- Paprastas nustatymas

**SSE režimas**: HTTP pagrindu veikiantis transliavimas
- Tinklo galimybės
- Geriau paskirstytoms sistemoms
- Realaus laiko atnaujinimai

### Įrankių integravimo galimybės

Sistema gali integruotis su įvairiais įrankiais:
- Žiniatinklio automatizavimas (Playwright)
- Failų operacijos
- API sąveikos
- Sistemos komandos
- Pasirinktines funkcijos

## Klaidų tvarkymas ir geriausios praktikos

### Visapusiškas klaidų valdymas

Įgyvendinimas apima tvirtą klaidų tvarkymą šiose srityse:

**Ryšio klaidos:**
- MCP serverio gedimai
- Tinklo laiko limitai
- Ryšio problemos

**Įrankių vykdymo klaidos:**
- Trūkstami įrankiai
- Parametrų patikrinimas
- Vykdymo gedimai

**Atsakymų apdorojimo klaidos:**
- JSON analizės problemos
- Formato neatitikimai
- LLM atsakymų anomalijos

### Geriausios praktikos

1. **Išteklių valdymas**: naudokite asinchroninius konteksto valdymo įrankius
2. **Klaidų tvarkymas**: įgyvendinkite visapusiškas try-catch blokų struktūras
3. **Registravimas**: įjunkite tinkamus registravimo lygius
4. **Saugumas**: tikrinkite įvestis ir valykite išvestis
5. **Veikimo efektyvumas**: naudokite ryšio jungčių kaupimą ir kešavimą

## Išvada

MCP integruoti mažieji kalbos modeliai ženklina paradigmų pokytį AI programų kūrime. Sujungdami mažų modelių efektyvumą su išorinių įrankių galia, kūrėjai gali kurti intelektualias sistemas, kurios yra tiek išteklius tausojančios, tiek labai pajėgios.

Modelio konteksto protokolas suteikia standartizuotą būdą jungti AI programas prie išorinių sistemų, panašiai kaip USB-C suteikia universalią jungties sąsają elektroniniams įrenginiams. Ši standartizacija leidžia:

- **Sklandžią integraciją**: jungti AI modelius prie įvairių duomenų šaltinių ir įrankių
- **Ekosistemos augimą**: sukurti vieną kartą, naudoti keliose AI programose
- **Pagerintas galimybes**: praplėsti SLM funkcionalumą su išorinėmis galimybėmis
- **Realaus laiko atnaujinimus**: palaikyti dinamiškas, reaguojančias AI programas

Pagrindiniai išsinešimai:
- MCP yra atviro standarto protokolas, jungiantis AI programas su išorinėmis sistemomis
- Protokolas palaiko įrankius, išteklius ir užklausas kaip pagrindines priemones
- Realaus laiko pranešimai leidžia dinamiškas ir reaguojančias programas
- Tinkamas gyvavimo ciklo valdymas ir klaidų tvarkymas būtini gamybai
- Ekosistema aprūpinta išsamiomis SDK ir vystymo įrankiais
