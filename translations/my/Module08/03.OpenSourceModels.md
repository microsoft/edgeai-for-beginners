# ‌အစည်းအဝေး ၃: ဖွင့်လှစ်-မူရင်း မော်ဒယ် ရှာဖွေရေးနှင့် စီမံခန့်ခွဲမှု

## အနှစ်ချုပ်

‌ဤအစည်းအဝေးသည် Foundry Local ဖြင့် လက်တွေ့ မော်ဒယ် ရှာဖွေရေးနှင့် စီမံခန့်ခွဲမှုကို ဦးတည်ပါသည်။ သင်သည် ရနိုင်သော မော်ဒယ်များစာရင်းဖော်ရန်၊ အမျိုးမျိုးသော ရွေးချယ်မှုများကို စမ်းသပ်ရန်နှင့် အခြေခံ လုပ်ဆောင်မှုထူးခြားချက်များကို နားလည်ရန် သင်ယူမည်ဖြစ်သည်။ ဤနည်းလမ်းသည် foundry CLI ဖြင့် လက်တွေ့ ရှာဖွေမှုကို အထူးထားပြီး သင့်အသုံးပြုနိုင်မှုအတွက် မှန်ကန်သော မော်ဒယ်များကို ရွေးချယ်ပေးရန် အထောက်အကူပြုပါသည်။

## သင်ယူမှုရည်ရွယ်ချက်များ

- မော်ဒယ် ရှာဖွေရေးနှင့် စီမံခန့်ခွဲမှုအတွက် foundry CLI ကုဒ်စီမံခန့်ခွဲမှုများကို ကျွမ်းကျင်ရန်
- မော်ဒယ် များ၏ cache နှင့် ဒေသဆိုင်ရာသိုလှောင်မှုပုံစံများကို နားလည်ရန်
- အမျိုးမျိုးသော မော်ဒယ် များကို များစွာအမြန် စမ်းသပ်နှင့် နှိုင်းယှဉ်ရန် သင်ယူရန်
- မော်ဒယ် ရွေးချယ်မှုနှင့် မျှတမှုစာရင်း အလုပ်လုပ်ပုံများကို တည်ဆောက်ရန်
- Foundry Local မှ တဆင့် ရရှိနိုင်သော မော်ဒယ်များ၏ တိုးတက်လာသော စနစ်ကြီးကို ရှာဖွေဖို့

## မတိုင်မီလိုအပ်ချက်များ

- အစည်းအဝေး ၁: Foundry Local ဖြင့် စတင်ခြင်း ပြီးစီးထားရန်
- Foundry Local CLI ကို 설치ပြီး အသုံးပြုနိုင်ရန်
- မော်ဒယ်ဒေါင်းလုပ်များအတွက် လုံလောက်သော သိုလှောင်မှုနေရာရှိရန် (မော်ဒယ်များသည် 1GB မှ 20GB+ အထိရှိနိုင်ပါသည်)
- မော်ဒယ်အမျိုးအစားများနှင့် အသုံးပြုမှုအကြောင်း အခြေခံနားလည်မှုရှိရန် - Foundry Local နှင့် Source Models

## အနှစ်ချုပ်

‌ဤအစည်းအဝေးသည် ဖွင့်လှစ်-မူရင်း မော်ဒယ်များကို Foundry L ပေါ်သို့ ယူဆောင်လာခြင်း: စသည်ဖြင့်

### လက်တွေ့ လေ့ကျင့်ခန်း: မော်ဒယ် ရှာဖွေရေးနှင့် နှိုင်းယှဉ်ခြင်း

Sample 03 ကို အခြေခံ၍ သင့်ရဲ့ မော်ဒယ် အကဲဖြတ်ရေး စာမျက်နှာကို တည်ဆောက်ပါ။

```cmd
REM create_model_test.cmd
@echo off
echo Model Discovery and Testing Script
echo =====================================

echo.
echo Step 1: List available models
foundry model list

echo.
echo Step 2: Check what's cached
foundry cache list

echo.
echo Step 3: Start phi-4-mini for testing
foundry model run phi-4-mini --verbose

echo.
echo Step 4: Test with a simple prompt
curl -X POST http://localhost:8000/v1/chat/completions ^
  -H "Content-Type: application/json" ^
  -d "{\"model\":\"phi-4-mini\",\"messages\":[{\"role\":\"user\",\"content\":\"Hello, please introduce yourself.\"}],\"max_tokens\":100}"

echo.
echo Model test complete!
```

### သင့်တာဝန်

1. **Sample 03 စာမျက်နှာကို လည်ပတ်ပါ**: `samples\03\list_and_bench.cmd`
2. **မော်ဒယ် များကို မတူညီစွာ စမ်းသပ်ပါ**: အနည်းဆုံး ၃ မော်ဒယ် စမ်းသပ်ပါ
3. **လုပ်ဆောင်ချက်ကို နှိုင်းယှဉ်ပါ**: အမြန်နှုန်းနှင့် တုံ့ပြန်မှုအရည်အသွေး မတူညီမှုများ မှတ်တမ်းတင်ပါ
4. **ရလဒ်များကို စာတမ်းတင်ပါ**: ရိုးရှင်းသော နှိုင်းယှဉ်မှုဇယားတစ်ရပ် ဖန်တီးပါ

### နမူနာ နှိုင်းယှဉ်ရေးဖော်ပြချက်

```
Model Comparison Results:
========================
phi-4-mini:        Fast (~2s), good for general chat
qwen2.5-7b:       Slower (~5s), better reasoning  
deepseek-r1:      Medium (~3s), excellent for code

Recommendation: Start with phi-4-mini for development, 
switch to qwen2.5-7b for production reasoning tasks.
```

## အပိုင်း ၇: ပြဿနာဖြေရှင်းမှုနှင့် အကောင်းဆုံး လေ့လာမှုများ

### အများဆုံး ဖြစ်တတ်သော ပြသနာများနှင့် ဖြေရှင်းနည်းများ

**မော်ဒယ် မတက်နိုင်ခြင်း:**
```cmd
REM Check service status
foundry service status

REM Restart service if needed
foundry service stop
foundry service start

REM Try with verbose output
foundry model run phi-4-mini --verbose
```

**မှတ်ဉာဏ်မလုံလောက်ခြင်း:**
- အသေးစား မော်ဒယ်များဖြင့် စတင်ပါ (`phi-4-mini`)
- နောက် ကျန် အက်ပလီကေးရှင်းများကို ပိတ်ပါ
- အမြဲတမ်း မှတ်ဉာဏ် ကန့်သတ်ချက်များကို ထိတွေ့နေရင် RAM တိုးတက်မှု လုပ်ပါ

**အလုပ်လုပ်ချိန် နှေးကွေးခြင်း:**
- မော်ဒယ် ပြည့်စုံစွာ load ဖြစ်ပြီးဖြစ်ကြောင်း သေချာစေပါ (verbose output ကို စစ်ဆေးပါ)
- မလိုအပ်သော နောက်ခံ application များ ပိတ်ပါ
- ပိုမိုလျင်မြန်သော သိုလှောင်မှု (SSD) ကို ရွေးပါ

### အကောင်းဆုံး လေ့လာမှုများ

1. **အသေးစားမှ စတင်ပါ**: `phi-4-mini` ဖြင့် စတင်ကာ စနစ်တကျ စစ်ဆေးပါ
2. **တစ်ကြိမ်မှာ မော်ဒယ် တစ်မျိုးသာ**: မော်ဒယ်အသစ် စတင်မည့်အချိန်မှ နောက်ဆုံး မော်ဒယ်များကို ရပ်တန့်ပါ
3. **အရင်းအမြစ်များကို မျက်စိုက်စောင့်ကြည့်ပါ**: မှတ်ဉာဏ်သုံးစွဲမှုကို အစဉ်ကြည့်ရှု
4. **တည်ငြိမ်စွာ စမ်းသပ်ပါ**: တိုးတက်မှု ခြေရာခံချက်များအတွက် တူညီသော prompt များကို အသုံးပြုပါ
5. **ရလဒ်များကို စာတမ်းတင်ပါ**: သင့်အသုံးပြုမှုအတွက် မော်ဒယ်လုပ်ဆောင်ချက်များကို မှတ်တမ်းတင်ပါ

## အပိုင်း ၈: နောက်လှည့်များနှင့် ရင်းမြစ်များ

### အစည်းအဝေး ၄ အတွက် ပြင်ဆင်ခြင်း

- **အစည်းအဝေး ၄ ဦးစားပေး**: ပြုပြင်ထိန်းသိမ်းရေးကိရိယာများနှင့် နည်းပညာများ
- **မတိုင်မီလိုအပ်ချက်များ**: မော်ဒယ်များ ကြိုးစားဖလှယ်မှုနှင့် အခြေခံ အသက်သာစမ်းသပ်မှု ကျွမ်းကျင်မှု
- **အကြံပြုချက်**: ဤအစည်းအဝေးမှ ၂-၃ ခုနှစ်သတ်မှတ်ထားသော မော်ဒယ်များကို ရယူထားပါ

### နောက်ထပ် သတင်းအချက်အလက်များ

- **[Foundry Local စာတမ်းများ](https://learn.microsoft.com/azure/ai-foundry/foundry-local/)**: တရားဝင် စာတမ်းများ
- **[CLI ကိုးကားစာမျက်နှာ](https://learn.microsoft.com/azure/ai-foundry/foundry-local/reference/reference-cli)**: ကွန်မန့္ အပြည့်အစုံ
- **[Model Mondays](https://aka.ms/model-mondays)**: အပတ်စဉ် မော်ဒယ် ဖော်ပြချက်များ
- **[Foundry Local GitHub](https://github.com/microsoft/Foundry-Local)**: အသိုင်းအဝိုင်းနှင့် ပြဿနာများ
- **[Sample 03: မော်ဒယ် ရှာဖွေရေး](samples/03/README.md)**: လက်တွေ့ နမူနာ စာမျက်နှာ

### အဓိက သင်ယူနိုင်ချက်များ

✅ **မော်ဒယ် ရှာဖွေရေး**: ရနိုင်သော မော်ဒယ်များကို `foundry model list` ဖြင့် ရှာဖွေပါ  
✅ **အမြန် စမ်းသပ်ခြင်း**: အမြန် သုံးသပ်ရန် `list_and_bench.cmd` ပုံစံ  
✅ **လုပ်ဆောင်ချက် ကြည့်ရှုခြင်း**: အခြေခံ အရင်းအမြစ် သုံးစွဲမှုနှင့် တုံ့ပြန်ချိန်တိုင်းတာမှု  
✅ **မော်ဒယ် ရွေးချယ်မှု**: အသုံးပြုမှုအလိုက် မော်ဒယ် ရွေးချယ်ရာ လက်တွေ့ လမ်းညွှန်ချက်များ  
✅ **Cache စီမံခန့်ခွဲမှု**: သိုလှောင်မှုနှင့် သန့်ရှင်းရေး နည်းလမ်းများနားလည်မှု  

သင်သည် Foundry Local ၏ ပေါ့ပါးလွယ်ကူသော CLI လမ်းကြောင်းဖြင့် သင့် AI application များအတွက် သင့်တော်သော မော်ဒယ်များကို ရှာဖွေ၊ စမ်းသပ်နှင့် ရွေးချယ်နိုင်သော လက်တွေ့ ကျွမ်းကျင်မှုများ ရရှိပါပြီ။: အသိုင်းအဝိုင်း မော်ဒယ် ရွေးချယ်ခြင်း၊ Hugging Face ပါဝင်မှု ပေါင်းစည်းခြင်း၊ နှင့် “သင်၏ ကိုယ်ပိုင် မော်ဒယ် ယူဆောင်မှု” (BYOM) နည်းလမ်းများကို ဖော်ပြထားပါသည်။ မော်ဒယ် Mondays စီးရီးဖြင့် ဆက်တိုက်သင်ယူမှုနှင့် မော်ဒယ် ရှာဖွေရေးကိုလည်း တွေ့ရှိကြမည် ဖြစ်သည်။

## သင်ယူမှုရည်ရွယ်ချက်များ
- ဒေသဆိုင်ရာ ထုတ်လွှင့်မှုအတွက် ဖွင့်လှစ်-မူရင်း မော်ဒယ်များ ရှာဖွေရေးနှင့် အကဲဖြတ်ခြင်း
- Foundry Local ထဲတွင် Hugging Face မော်ဒယ်များ စုစည်း ထုတ်လွှင့်ခြင်းနှင့် လည်ပတ်ခြင်း
- တိကျမှန်ကန်မှု၊ နောက်ကျမှုနှင့် အရင်းအမြစ် လိုအပ်ချက်များ အတွက် မော်ဒယ် ရွေးချယ်မှု မူဝါဒများ အသုံးချခြင်း
- Cache နှင့် ဗားရှင်း တိုးပွားမှုဖြင့် ဒေသဆိုင်ရာ မော်ဒယ်များ စီမံခန့်ခွဲခြင်း

## အပိုင်း ၁: Foundry CLI ဖြင့် မော်ဒယ် ရှာဖွေရေး

### မော်ဒယ် စီမံခန့်ခွဲမှု အခြေခံ ကွန်မန့္များ

foundry CLI သည် မော်ဒယ် ရှာဖွေရေးနှင့် စီမံခန့်ခွဲမှုအတွက် ရိုးရှင်းသက်သာသော ကွန်မန့္လမ်းညွှန်ချက်များပေးသည်။

```cmd
REM List all available models in the catalog
foundry model list

REM List cached (downloaded) models
foundry cache list

REM Check cache directory location
foundry cache ls
```

### သင့် ပထမဆုံး မော်ဒယ်များကို လည်ပတ်ခြင်း

လုပ်ဆောင်ချက်ထူးခြားချက်များကို နားလည်ရန် လူကြိုက်များပြီး စမ်းသပ်ပြီးသား မော်ဒယ်များဖြင့် စတင်ပါ။

```cmd
REM Run Phi-4-Mini (lightweight, fast)
foundry model run phi-4-mini --verbose

REM Run Qwen 2.5 7B (larger, more capable)
foundry model run qwen2.5-7b --verbose

REM Run DeepSeek (specialized for coding)
```

## အပိုင်း ၅: ရိုးရှင်းသော မော်ဒယ် စမ်းသပ်မှု

### အခြေခံ လုပ်ဆောင်ချက် စမ်းသပ်မှု

မော်ဒယ် လုပ်ဆောင်ချက်များကို နှိုင်းယှဉ်ရန် ရိုးရှင်းသော နည်းလမ်း:

```python
# simple_bench.py - နမူနာ 03 ပုံစံအခြေခံသည်
import time
import requests
import json

def test_model_response(model_name, prompt="Explain edge AI in one sentence."):
    """Test a single model with a prompt and measure response time."""
    start_time = time.time()
    
    try:
        response = requests.post(
            "http://localhost:8000/v1/chat/completions",
            headers={"Content-Type": "application/json"},
            json={
                "model": model_name,
                "messages": [{"role": "user", "content": prompt}],
                "max_tokens": 64
            },
            timeout=30
        )
        
        elapsed = time.time() - start_time
        
        if response.status_code == 200:
            result = response.json()
            return {
                "model": model_name,
                "latency_sec": round(elapsed, 3),
                "response": result["choices"][0]["message"]["content"],
                "status": "success"
            }
        else:
            return {
                "model": model_name,
                "status": "error",
                "error": f"HTTP {response.status_code}"
            }
            
    except Exception as e:
        return {
            "model": model_name,
            "status": "error", 
            "error": str(e)
        }

# လက်ရှိ အသုံးပြုနေသော မော်ဒယ်ကို စမ်းသပ်ပါ
if __name__ == "__main__":
    # မီလ်အသစ်များဖြင့် စမ်းသပ်ပါ (မော်ဒယ်တိုင်းကို ပထမဦးစွာ စတင်ပါ)
    test_models = ["phi-4-mini", "qwen2.5-7b", "deepseek-r1-7b"]
    
    print("Model Performance Test")
    print("=" * 50)
    
    for model in test_models:
        print(f"\nTesting {model}...")
        print("Note: Make sure this model is running first with 'foundry model run {model}'")
        
        result = test_model_response(model)
        
        if result["status"] == "success":
            print(f"✅ {model}: {result['latency_sec']}s")
            print(f"   Response: {result['response'][:100]}...")
        else:
            print(f"❌ {model}: {result['error']}")
```
