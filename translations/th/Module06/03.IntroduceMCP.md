# ส่วนที่ 03 - การบูรณาการ Model Context Protocol (MCP)

## บทนำสู่ MCP (Model Context Protocol)

Model Context Protocol (MCP) คือมาตรฐานโอเพนซอร์สสำหรับการเชื่อมต่อแอปพลิเคชัน AI กับระบบภายนอก โดยใช้ MCP แอปพลิเคชัน AI เช่น Claude หรือ ChatGPT สามารถเชื่อมต่อกับแหล่งข้อมูล (เช่น ไฟล์ในเครื่อง, ฐานข้อมูล) เครื่องมือ (เช่น เครื่องมือค้นหา, เครื่องคิดเลข) และเวิร์กโฟลว์ (เช่น คำถามเฉพาะทาง) ซึ่งทำให้สามารถเข้าถึงข้อมูลสำคัญและปฏิบัติงานได้

ลองคิดว่า MCP เป็นเหมือน **พอร์ต USB-C สำหรับแอปพลิเคชัน AI** เช่นเดียวกับที่ USB-C มาตรฐานในการเชื่อมต่ออุปกรณ์อิเล็กทรอนิกส์ MCP ก็เป็นมาตรฐานสำหรับการเชื่อมต่อแอปพลิเคชัน AI กับระบบภายนอก

### MCP ช่วยให้ทำอะไรได้บ้าง?

MCP เปิดประสิทธิภาพที่ทรงพลังสำหรับแอปพลิเคชัน AI:

- **ผู้ช่วย AI ส่วนบุคคล**: ตัวแทนสามารถเข้าถึงปฏิทิน Google และ Notion ของคุณ ทำหน้าที่เป็นผู้ช่วย AI ที่มีความเป็นส่วนตัวมากขึ้น  
- **การสร้างโค้ดขั้นสูง**: Claude Code สามารถสร้างเว็บแอปทั้งหมดโดยใช้การออกแบบจาก Figma  
- **การรวมข้อมูลองค์กร**: แชทบอทองค์กรสามารถเชื่อมต่อกับหลายฐานข้อมูลทั่วองค์กร ให้ผู้ใช้วิเคราะห์ข้อมูลได้ผ่านแชท  
- **เวิร์กโฟลว์สร้างสรรค์**: โมเดล AI สร้างการออกแบบ 3 มิติบน Blender และพิมพ์ออกมาด้วยเครื่องพิมพ์ 3 มิติ  
- **การเข้าถึงข้อมูลแบบเรียลไทม์**: เชื่อมต่อกับแหล่งข้อมูลภายนอกเพื่อข้อมูลที่อัปเดต  
- **การดำเนินการหลายขั้นตอนที่ซับซ้อน**: ปฏิบัติงานแบบเวิร์กโฟลว์ซับซ้อนโดยผสานหลายเครื่องมือและระบบ  

### ทำไม MCP ถึงสำคัญ?

MCP ให้ประโยชน์ในหลายมิติ:

**สำหรับนักพัฒนา**: MCP ลดเวลาพัฒนาและความซับซ้อนเมื่อสร้างหรือรวมกับแอปพลิเคชันหรือเอเจนต์ AI  

**สำหรับแอปพลิเคชัน AI**: MCP ให้การเข้าถึงระบบนิเวศของแหล่งข้อมูล เครื่องมือ และแอปต่าง ๆ ที่ช่วยเพิ่มประสิทธิภาพและปรับปรุงประสบการณ์ผู้ใช้  

**สำหรับผู้ใช้งาน**: MCP ส่งผลให้อุปกรณ์ AI หรือเอเจนต์มีความสามารถมากขึ้น สามารถเข้าถึงข้อมูลของคุณและปฏิบัติการแทนเมื่อจำเป็น  

## โมเดลภาษาเล็ก (SLMs) ใน MCP

โมเดลภาษาเล็กเป็นวิธีการที่มีประสิทธิภาพในการนำ AI มาใช้ โดยมีข้อดีหลายอย่าง:

### ข้อดีของ SLMs
- **ประหยัดทรัพยากร**: ต้องการการประมวลผลต่ำกว่า  
- **ตอบสนองรวดเร็ว**: ลดความหน่วงสำหรับแอปพลิเคชันแบบเรียลไทม์  
- **คุ้มค่า**: จำเป็นต้องใช้อินฟราสตรัคเจอร์น้อย  
- **ความเป็นส่วนตัว**: สามารถรันในเครื่องโดยไม่ต้องส่งข้อมูลออก  
- **ปรับแต่งได้ง่าย**: ปรับจูนได้ง่ายสำหรับโดเมนเฉพาะ  

### ทำไม SLMs ถึงเหมาะกับ MCP

SLMs เมื่อนำมาคู่กับ MCP จะเป็นการผสมผสานที่ทรงพลังที่ความสามารถในการให้เหตุผลของโมเดลจะเสริมด้วยเครื่องมือภายนอก ชดเชยจำนวนพารามิเตอร์ที่น้อยด้วยฟังก์ชันการทำงานที่เพิ่มขึ้น  

## ภาพรวม Python MCP SDK

Python MCP SDK เป็นฐานสำหรับการสร้างแอปพลิเคชันที่รองรับ MCP โดย SDK ประกอบด้วย:

- **ไลบรารีสำหรับไคลเอนต์**: สำหรับเชื่อมต่อกับเซิร์ฟเวอร์ MCP  
- **กรอบการทำงานเซิร์ฟเวอร์**: สำหรับสร้างเซิร์ฟเวอร์ MCP แบบกำหนดเอง  
- **ตัวจัดการโปรโตคอล**: สำหรับบริหารการสื่อสาร  
- **การรวมเครื่องมือ**: สำหรับเรียกใช้ฟังก์ชันภายนอก  

## การนำไปใช้งานจริง: Phi-4 MCP Client

มาดูการนำไปใช้งานจริงโดยใช้โมเดล Phi-4 ขนาดเล็กของ Microsoft ที่รวมกับความสามารถของ MCP  

### ภาพรวมสถาปัตยกรรม MCP

MCP ใช้ **สถาปัตยกรรมแบบไคลเอนต์-เซิร์ฟเวอร์** ที่เจ้าภาพ MCP (แอป AI เช่น Claude Code หรือ Claude Desktop) สร้างการเชื่อมต่อกับหนึ่งหรือมากกว่าเซิร์ฟเวอร์ MCP เจ้าภาพ MCP จะสร้างไคลเอนต์ MCP หนึ่งตัวสำหรับแต่ละเซิร์ฟเวอร์ MCP  

#### ผู้เข้าร่วมหลัก

- **เจ้าภาพ MCP**: แอป AI ที่ประสานและจัดการไคลเอนต์ MCP หนึ่งตัวหรือมากกว่า  
- **ไคลเอนต์ MCP**: ส่วนประกอบที่รักษาการเชื่อมต่อกับเซิร์ฟเวอร์ MCP และรับบริบทจากเซิร์ฟเวอร์ MCP เพื่อให้เจ้าภาพใช้  
- **เซิร์ฟเวอร์ MCP**: โปรแกรมที่ให้บริบทแก่ไคลเอนต์ MCP  

#### สถาปัตยกรรมสองชั้น

MCP ประกอบด้วยสองชั้นแยกกัน:

**ชั้นข้อมูล**: กำหนดโปรโตคอลแบบ JSON-RPC สำหรับการสื่อสารระหว่างไคลเอนต์กับเซิร์ฟเวอร์ รวมถึง:
- การจัดการวงจรชีวิต (การเริ่มต้นการเชื่อมต่อ, การเจรจาขีดความสามารถ)  
- พื้นฐานหลัก (เครื่องมือ, ทรัพยากร, คำถามนำ)  
- ฟีเจอร์ของไคลเอนต์ (การสุ่ม, การขอข้อมูล, การบันทึก)  
- ฟีเจอร์อรรถประโยชน์ (การแจ้งเตือน, การติดตามความก้าวหน้า)  

**ชั้นการขนส่ง**: กำหนดกลไกและช่องทางการสื่อสาร:
- **การขนส่ง STDIO**: ใช้สตรีมอินพุต/เอาต์พุตมาตรฐานสำหรับกระบวนการท้องถิ่น (ประสิทธิภาพดีที่สุด, ไม่มีภาระเครือข่าย)  
- **การขนส่ง HTTP แบบสตรีมมิ่ง**: ใช้ HTTP POST พร้อมกับ Server-Sent Events ทางเลือกสำหรับเซิร์ฟเวอร์ระยะไกล (รองรับการยืนยันตัวตน HTTP มาตรฐาน)  

```
┌─────────────────────────────────────┐
│           MCP Host                  │
│     (AI Application)                │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Client 1                │
│  ┌─────────────────────────────────┐ │
│  │        Data Layer               │ │
│  │  ├── Lifecycle Management       │ │
│  │  ├── Primitives (Tools/Resources)│ │
│  │  └── Notifications              │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │      Transport Layer           │ │
│  │  ├── STDIO Transport           │ │
│  │  └── HTTP Transport            │ │
│  └─────────────────────────────────┘ │
└─────────────────┬───────────────────┘
                  │
┌─────────────────┴───────────────────┐
│         MCP Server 1                │
│    (Local/Remote Context Provider)  │
└─────────────────────────────────────┘
```

### MCP Core Primitives

MCP กำหนด primitives ที่ระบุประเภทของข้อมูลบริบทที่สามารถแชร์กับแอป AI และช่วงของการกระทำที่สามารถปฏิบัติได้

#### Server Primitives

MCP กำหนดสาม primitives หลักที่เซิร์ฟเวอร์สามารถเปิดเผยได้:

**เครื่องมือ**: ฟังก์ชันที่สามารถเรียกใช้โดยแอป AI เพื่อทำงานต่าง ๆ
- ตัวอย่าง: การจัดการไฟล์, การเรียก API, การค้นฐานข้อมูล  
- เมธอด: `tools/list`, `tools/call`  
- รองรับการค้นหาและเรียกใช้งานแบบไดนามิก  

**ทรัพยากร**: แหล่งข้อมูลที่ให้บริบทแก่แอป AI  
- ตัวอย่าง: เนื้อหาไฟล์, ระเบียนฐานข้อมูล, การตอบกลับ API  
- เมธอด: `resources/list`, `resources/read`  
- เปิดโอกาสให้เข้าถึงข้อมูลที่มีโครงสร้าง  

**คำถามนำ (Prompts)**: แม่แบบที่ใช้ซ้ำได้ซึ่งช่วยจัดโครงสร้างปฏิสัมพันธ์กับโมเดลภาษา  
- ตัวอย่าง: คำถามระบบ, ตัวอย่าง few-shot  
- เมธอด: `prompts/list`, `prompts/get`  
- มาตรฐานรูปแบบการโต้ตอบ AI  

#### Client Primitives

MCP ยังกำหนด primitives ที่ไคลเอนต์สามารถเปิดเผยเพื่อให้ปฏิสัมพันธ์ที่หลากหลายขึ้น:

**การสุ่มตัวอย่าง (Sampling)**: ให้เซิร์ฟเวอร์ขอผลการตอบจากโมเดลภาษาของแอป AI ของไคลเอนต์  
- เมธอด: `sampling/complete`  
- สนับสนุนการพัฒนาเซิร์ฟเวอร์ไม่ขึ้นกับโมเดล  
- ให้การเข้าถึงโมเดลภาษาของเจ้าภาพ  

**การขอข้อมูลเพิ่มเติม (Elicitation)**: ให้เซิร์ฟเวอร์ขอข้อมูลเพิ่มเติมจากผู้ใช้  
- เมธอด: `elicitation/request`  
- สนับสนุนการโต้ตอบและการยืนยันจากผู้ใช้  
- รองรับการเก็บข้อมูลแบบไดนามิก  

**การบันทึก (Logging)**: ให้เซิร์ฟเวอร์ส่งข้อความบันทึกไปยังไคลเอนต์  
- ใช้สำหรับการดีบักและติดตามระบบ  
- ให้ความโปร่งใสในการดำเนินงานของเซิร์ฟเวอร์  

### วงจรชีวิตโปรโตคอล MCP

#### การเริ่มต้นและการเจรจาขีดความสามารถ

MCP เป็นโปรโตคอลที่มีสถานะ จำเป็นต้องบริหารจัดการวงจรชีวิต การเริ่มต้นมีวัตถุประสงค์สำคัญหลายประการ:

1. **การเจรจาเวอร์ชันโปรโตคอล**: เพื่อให้แน่ใจว่าไคลเอนต์และเซิร์ฟเวอร์ใช้เวอร์ชันโปรโตคอลที่เข้ากันได้ (เช่น "2025-06-18")  
2. **การค้นหาขีดความสามารถ**: แต่ละฝ่ายประกาศฟีเจอร์และ primitives ที่รองรับ  
3. **การแลกเปลี่ยนตัวตน**: ให้ข้อมูลการระบุตัวและเวอร์ชัน  

```python
# ตัวอย่างคำขอเริ่มต้น
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "elicitation": {},  # ลูกค้าสนับสนุนการโต้ตอบกับผู้ใช้
      "sampling": {}      # ลูกค้าสามารถให้ผลลัพธ์การเติมข้อความ LLM ได้
    },
    "clientInfo": {
      "name": "edge-ai-client",
      "version": "1.0.0"
    }
  }
}
```

#### การค้นหาและใช้งานเครื่องมือ

หลังจากการเริ่มต้น ไคลเอนต์สามารถค้นหาและใช้งานเครื่องมือได้:

```python
# ค้นพบเครื่องมือที่มีอยู่
tools_response = await session.list_tools()

# เรียกใช้เครื่องมือ
result = await session.call_tool(
    "weather_current",
    {
        "location": "San Francisco",
        "units": "imperial"
    }
)
```

#### การแจ้งเตือนแบบเรียลไทม์

MCP รองรับการแจ้งเตือนแบบเรียลไทม์สำหรับการอัปเดตแบบไดนามิก:

```python
# เซิร์ฟเวอร์ส่งการแจ้งเตือนเมื่อเครื่องมือเปลี่ยนแปลง
{
  "jsonrpc": "2.0",
  "method": "notifications/tools/list_changed"
}

# ไคลเอนต์ตอบกลับโดยการรีเฟรชรายการเครื่องมือ
await session.list_tools()  # รับเครื่องมือที่อัปเดตแล้ว
```

## การเริ่มต้น: คู่มือทีละขั้นตอน

### ขั้นตอนที่ 1: การตั้งค่าสภาพแวดล้อม

ติดตั้ง dependencies ที่จำเป็น:
```bash
pip install fastmcp mcp-python-client openai requests pyautogui Pillow
```

### ขั้นตอนที่ 2: การกำหนดค่าพื้นฐาน

ตั้งค่าตัวแปรสภาพแวดล้อมของคุณ:
```python
# การตั้งค่าระบบ
SYSTEM_PROMPT = "You are an AI assistant with some tools."

# การตั้งค่า Ollama (ภายในเครื่อง)
OLLAMA_URL = "http://localhost:11434/api/chat"
OLLAMA_MODEL_ID = "phi4-mini:3.8b-fp16"

# การตั้งค่า vLLM (เซิร์ฟเวอร์)
VLLM_URL = "http://localhost:8000/v1"
VLLM_MODEL_ID = "microsoft/Phi-4-mini-instruct"
```

### ขั้นตอนที่ 3: การรัน MCP Client ตัวแรกของคุณ

**การตั้งค่า Ollama พื้นฐาน:**  
```bash
python ghmodel_mcp_demo.py
```

**การใช้ vLLM Backend:**  
```bash
python ghmodel_mcp_demo.py --env vllm
```

**การเชื่อมต่อ Server-Sent Events:**  
```bash
python ghmodel_mcp_demo.py --run sse
```

**เซิร์ฟเวอร์ MCP แบบกำหนดเอง:**  
```bash
python ghmodel_mcp_demo.py --server /path/to/server.py
```

### ขั้นตอนที่ 4: การใช้งานเชิงโปรแกรม  

```python
import asyncio
from ghmodel_mcp_demo import OllamaClient, Phi4MiniMCPClient

async def automated_interaction():
    # กำหนดค่าพารามิเตอร์เซิร์ฟเวอร์ MCP
    server_params = StdioServerParameters(
        command="npx",
        args=["@playwright/mcp@latest"],
        env=None,
    )
    
    # สร้างไคลเอนต์ MCP และเครื่องมือประมวลผล
    async with Phi4MiniMCPClient(server_params) as mcp_client:
        tools = await process_mcp_tools(mcp_client)
        llm_client = OllamaClient()
        
        # สร้างการตอบกลับด้วยความสามารถของเครื่องมือ
        response, messages = await llm_client.generate_response(
            "Help me automate a web task",
            tools
        )
        return response

# ดำเนินการอัตโนมัติ
result = asyncio.run(automated_interaction())
print(result)
```

## ฟีเจอร์ขั้นสูง

### การรองรับหลาย Backend

การนำไปใช้งานรองรับทั้ง backend ของ Ollama และ vLLM ให้คุณเลือกใช้ตามความต้องการ:

- **Ollama**: เหมาะกับการพัฒนาและทดสอบในเครื่อง  
- **vLLM**: ปรับปรุงสำหรับการใช้งานจริงและความต้องการความเร็วสูง  

### โปรโตคอลการเชื่อมต่อที่ยืดหยุ่น

รองรับสองโหมดการเชื่อมต่อ:

**โหมด STDIO**: การสื่อสารผ่านกระบวนการโดยตรง  
- ความหน่วงต่ำ  
- เหมาะสำหรับเครื่องมือภายในเครื่อง  
- การตั้งค่าง่าย  

**โหมด SSE**: การสตรีมผ่าน HTTP  
- รองรับเครือข่าย  
- เหมาะสำหรับระบบแบบกระจาย  
- อัปเดตแบบเรียลไทม์  

### ความสามารถในการรวมเครื่องมือ

ระบบสามารถรวมกับเครื่องมือต่าง ๆ ได้:
- อัตโนมัติเว็บ (Playwright)  
- การจัดการไฟล์  
- การติดต่อ API  
- คำสั่งระบบ  
- ฟังก์ชันกำหนดเอง  

## การจัดการข้อผิดพลาดและแนวทางปฏิบัติที่ดีที่สุด

### การจัดการข้อผิดพลาดอย่างครอบคลุม

การนำไปใช้งานมีการจัดการข้อผิดพลาดที่แข็งแกร่งสำหรับ:

**ข้อผิดพลาดในการเชื่อมต่อ:**  
- ความล้มเหลวของเซิร์ฟเวอร์ MCP  
- การหมดเวลาของเครือข่าย  
- ปัญหาการเชื่อมต่อ  

**ข้อผิดพลาดในการใช้งานเครื่องมือ:**  
- ขาดเครื่องมือ  
- การตรวจสอบพารามิเตอร์  
- ความล้มเหลวในการประมวลผล  

**ข้อผิดพลาดในการประมวลผลคำตอบ:**  
- ปัญหาการแยก JSON  
- รูปแบบไม่สอดคล้อง  
- ความผิดปกติของคำตอบ LLM  

### แนวทางปฏิบัติที่ดีที่สุด

1. **การจัดการทรัพยากร**: ใช้ async context managers  
2. **การจัดการข้อผิดพลาด**: ใช้ try-catch blocks อย่างครอบคลุม  
3. **การบันทึก**: เปิดใช้งานระดับการบันทึกที่เหมาะสม  
4. **ความปลอดภัย**: ตรวจสอบอินพุตและทำความสะอาดเอาต์พุต  
5. **ประสิทธิภาพ**: ใช้ connection pooling และ caching

## ระบบนิเวศ MCP และการพัฒนา

### ขอบเขตโครงการ MCP

ระบบนิเวศของ Model Context Protocol ประกอบด้วยองค์ประกอบสำคัญหลายอย่าง:

- **[ข้อกำหนด MCP](https://modelcontextprotocol.io/specification/latest)**: ข้อกำหนดอย่างเป็นทางการที่ระบุข้อกำหนดในการนำไปใช้งานสำหรับไคลเอนต์และเซิร์ฟเวอร์  
- **[SDK ของ MCP](https://modelcontextprotocol.io/docs/sdk)**: SDK สำหรับภาษาโปรแกรมต่าง ๆ ที่นำ MCP ไปใช้  
- **เครื่องมือพัฒนา MCP**: เครื่องมือสำหรับพัฒนาเซิร์ฟเวอร์และไคลเอนต์ MCP รวมถึง [MCP Inspector](https://github.com/modelcontextprotocol/inspector)  
- **[การนำเซิร์ฟเวอร์ MCP ไปใช้เป็นตัวอย่าง](https://github.com/modelcontextprotocol/servers)**: ตัวอย่างการใช้งานเซิร์ฟเวอร์ MCP  

### การเริ่มต้นพัฒนากับ MCP

สำหรับการเริ่มสร้างกับ MCP:

**สร้างเซิร์ฟเวอร์**: [สร้างเซิร์ฟเวอร์ MCP](https://modelcontextprotocol.io/docs/develop/build-server) เพื่อเปิดเผยข้อมูลและเครื่องมือของคุณ  

**สร้างไคลเอนต์**: [พัฒนาแอปพลิเคชัน](https://modelcontextprotocol.io/docs/develop/build-client) ที่เชื่อมต่อกับเซิร์ฟเวอร์ MCP  

**เรียนรู้แนวคิด**: [เข้าใจแนวคิดหลัก](https://modelcontextprotocol.io/docs/learn/architecture) และสถาปัตยกรรมของ MCP  

## สรุป

SLMs ที่รวมกับ MCP เป็นการเปลี่ยนแปลงแนวคิดในการพัฒนาแอป AI ด้วยการผสมผสานประสิทธิภาพของโมเดลเล็กกับพลังของเครื่องมือภายนอก นักพัฒนาสามารถสร้างระบบอัจฉริยะที่ประหยัดทรัพยากรและมีความสามารถสูง  

Model Context Protocol ให้วิธีมาตรฐานในการเชื่อมต่อแอป AI กับระบบภายนอก เช่นเดียวกับ USB-C ที่เป็นมาตรฐานการเชื่อมต่ออุปกรณ์อิเล็กทรอนิกส์ มาตรฐานนี้ส่งผลให้เกิด:

- **การบูรณาการอย่างราบรื่น**: เชื่อมต่อโมเดล AI กับแหล่งข้อมูลและเครื่องมือหลากหลาย  
- **การเติบโตของระบบนิเวศ**: สร้างครั้งเดียว ใช้ได้กับแอป AI หลายตัว  
- **ความสามารถที่เพิ่มขึ้น**: เสริม SLMs ด้วยฟังก์ชันภายนอก  
- **อัปเดตแบบเรียลไทม์**: สนับสนุนแอป AI ที่ตอบสนองทันที  

สิ่งที่สำคัญ:
- MCP เป็นมาตรฐานเปิดที่เชื่อมแอป AI และระบบภายนอก  
- โปรโตคอลรองรับเครื่องมือ ทรัพยากร และคำถามนำเป็น primitives หลัก  
- การแจ้งเตือนแบบเรียลไทม์สนับสนุนแอปพลิเคชันแบบไดนามิกและตอบสนอง  
- การจัดการวงจรชีวิตและการจัดการข้อผิดพลาดเป็นสิ่งจำเป็นสำหรับการใช้งานจริง  
- ระบบนิเวศมี SDK และเครื่องมือพัฒนาแบบครบถ้วน
