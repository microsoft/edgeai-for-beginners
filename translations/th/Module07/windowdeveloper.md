# คู่มือการพัฒนา Windows Edge AI

## บทนำ

ยินดีต้อนรับสู่การพัฒนา Windows Edge AI – คู่มือครบวงจรสำหรับการสร้างแอปพลิเคชันอัจฉริยะที่ใช้พลังของ AI บนเครื่องโดยใช้แพลตฟอร์ม Windows AI Foundry ของ Microsoft คู่มือนี้ออกแบบมาโดยเฉพาะสำหรับนักพัฒนา Windows ที่ต้องการผนวกความสามารถ Edge AI ขั้นสูงเข้ากับแอปพลิเคชันของตน ในขณะที่ใช้ประโยชน์จากความเร่งฮาร์ดแวร์ของ Windows ได้อย่างเต็มที่

### ข้อได้เปรียบของ Windows AI

Windows AI Foundry คือแพลตฟอร์มรวมที่เชื่อถือได้และปลอดภัยที่สนับสนุนวงจรชีวิตการพัฒนา AI อย่างเต็มรูปแบบ – ตั้งแต่การเลือกและปรับแต่งโมเดล ไปจนถึงการเพิ่มประสิทธิภาพและการปรับใช้บนสถาปัตยกรรม CPU, GPU, NPU และคลาวด์แบบไฮบริด แพลตฟอร์มนี้ทำให้การพัฒนา AI เป็นประชาธิปไตยโดยการให้:

- **การแยกฮาร์ดแวร์**: การปรับใช้ที่ราบรื่นบนซิลิคอนของ AMD, Intel, NVIDIA และ Qualcomm
- **ความฉลาดบนเครื่อง**: AI ที่รักษาความเป็นส่วนตัวและทำงานทั้งหมดบนฮาร์ดแวร์ในเครื่อง
- **ประสิทธิภาพที่ปรับแต่งได้**: โมเดลที่ถูกปรับแต่งล่วงหน้าสำหรับการกำหนดค่าฮาร์ดแวร์ของ Windows
- **พร้อมใช้งานในองค์กร**: ความปลอดภัยและคุณสมบัติการปฏิบัติตามมาตรฐานระดับผลิตภัณฑ์

### Windows ML 
Windows Machine Learning (ML) ช่วยให้นักพัฒนา C#, C++ และ Python สามารถรันโมเดล AI ONNX บนพีซี Windows ได้โดยตรงผ่าน ONNX Runtime พร้อมการจัดการโปรไวเดอร์การประมวลผลอัตโนมัติสำหรับฮาร์ดแวร์ต่างๆ (CPU, GPU, NPU) [ONNX Runtime](https://onnxruntime.ai/docs/) สามารถใช้กับโมเดลจาก PyTorch, Tensorflow/Keras, TFLite, scikit-learn และเฟรมเวิร์กอื่นๆ


![WindowsML A diagram illustrating an ONNX model going through Windows ML to then reach NPUs, GPUs, and CPUs.l](https://learn.microsoft.com/en-us/windows/ai/images/winml-diagram.png)

Windows ML มีสำเนาการใช้งาน ONNX Runtime ที่แชร์ทั่วทั้ง Windows พร้อมความสามารถในการดาวน์โหลดโปรไวเดอร์การประมวลผล (EPs) แบบไดนามิก

### ทำไมต้อง Windows สำหรับ Edge AI?

**การรองรับฮาร์ดแวร์แบบสากล**
Windows ML ให้การปรับแต่งฮาร์ดแวร์อัตโนมัติทั่วทั้งระบบนิเวศ Windows เพื่อให้แน่ใจว่าแอปพลิเคชัน AI ของคุณทำงานได้ดีที่สุดไม่ว่าจะเป็นสถาปัตยกรรมซิลิคอนพื้นฐานแบบใด

**รันไทม์ AI ในตัว**
เครื่องยนต์อนุมาน Windows ML ที่ติดตั้งมาในตัวช่วยลดความซับซ้อนของการตั้งค่า ช่วยให้นักพัฒนาสามารถมุ่งเน้นที่ตรรกะของแอปพลิเคชันแทนที่จะเป็นโครงสร้างพื้นฐาน

**การปรับแต่งสำหรับ Copilot+ PC**
API ที่สร้างขึ้นโดยเฉพาะสำหรับอุปกรณ์ Windows รุ่นถัดไปที่มีหน่วยประมวลผลประสาทเทียม (NPU) โดยให้ประสิทธิภาพสูงต่อหน่วยพลังงาน

**ระบบนิเวศนักพัฒนา**
เครื่องมือครบครันรวมถึงการผนวกกับ Visual Studio, เอกสารครบถ้วน และแอปตัวอย่างที่เร่งวงจรการพัฒนา

## วัตถุประสงค์การเรียนรู้

เมื่อคุณทำคู่มือการพัฒนา Windows Edge AI นี้เสร็จสิ้น คุณจะเชี่ยวชาญทักษะสำคัญสำหรับการสร้างแอป AI ที่พร้อมสำหรับการใช้งานจริงบนแพลตฟอร์ม Windows

### ความสามารถทางเทคนิคหลัก

**ความเชี่ยวชาญ Windows AI Foundry**
- เข้าใจสถาปัตยกรรมและส่วนประกอบของแพลตฟอร์ม Windows AI Foundry
- นำทางวงจรชีวิตการพัฒนา AI อย่างครบถ้วนในระบบนิเวศ Windows
- นำแนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัยมาใช้กับแอป AI บนเครื่อง
- ปรับแต่งแอปพลิเคชันสำหรับการกำหนดค่าฮาร์ดแวร์ Windows ที่แตกต่างกัน

**ความชำนาญในการผนวก API**
- เชี่ยวชาญ API ของ Windows AI สำหรับแอปพลิเคชันข้อความ, การมองเห็น และมัลติฟังก์ชัน
- นำโมเดลภาษา Phi Silica มาใช้สำหรับการสร้างข้อความและเหตุผล
- ปรับใช้ความสามารถการมองเห็นด้วยคอมพิวเตอร์โดยใช้ API การประมวลผลภาพในตัว
- ปรับแต่งโมเดลที่ฝึกไว้ล่วงหน้าด้วยเทคนิค LoRA (Low-Rank Adaptation)

**การใช้งาน Foundry Local**
- เรียกดู, ประเมินผล และปรับใช้โมเดลภาษาโอเพนซอร์สโดยใช้ Foundry Local CLI
- เข้าใจการเพิ่มประสิทธิภาพโมเดลและการคอนติชั่นสำหรับการปรับใช้ในเครื่อง
- นำความสามารถ AI แบบออฟไลน์มาใช้โดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต
- จัดการวงจรชีวิตและการอัปเดตโมเดลในสภาพแวดล้อมการผลิต

**การปรับใช้ Windows ML**
- นำโมเดล ONNX ที่กำหนดเองมาสู่แอปพลิเคชัน Windows โดยใช้ Windows ML
- ใช้ประโยชน์จากการเร่งฮาร์ดแวร์อัตโนมัติในสถาปัตยกรรม CPU, GPU และ NPU
- นำเสนอการอนุมานแบบเรียลไทม์พร้อมการใช้ทรัพยากรอย่างเหมาะสม
- ออกแบบแอป AI ที่ปรับขนาดได้สำหรับอุปกรณ์ Windows หลากหลายประเภท

### ทักษะการพัฒนาแอปพลิเคชัน

**การพัฒนา Windows ข้ามแพลตฟอร์ม**
- สร้างแอปที่ขับเคลื่อนด้วย AI โดยใช้ .NET MAUI สำหรับการปรับใช้ Windows แบบสากล
- ผนวกความสามารถ AI เข้ากับ Win32, UWP และ Progressive Web Applications
- นำดีไซน์ UI ที่ตอบสนองต่อสถานะการประมวลผล AI มาใช้
- จัดการการประมวลผล AI แบบอะซิงโครนัสด้วยรูปแบบประสบการณ์ผู้ใช้ที่เหมาะสม

**การปรับประสิทธิภาพ**
- วิเคราะห์โปรไฟล์และปรับประสิทธิภาพการอนุมาน AI ในฮาร์ดแวร์ที่ต่างกัน
- นำการจัดการหน่วยความจำที่มีประสิทธิภาพมาใช้สำหรับโมเดลภาษาใหญ่
- ออกแบบแอปพลิเคชันที่ลดประสิทธิภาพอย่างเหมาะสมตามความสามารถของฮาร์ดแวร์
- ใช้กลยุทธ์แคชชิ่งสำหรับการประมวลผล AI ที่ใช้บ่อย

**ความพร้อมสำหรับการผลิต**
- นำกลไกการจัดการข้อผิดพลาดและฟอลแบ็คมาใช้แบบครบถ้วน
- ออกแบบระบบโทรเมทริกและการตรวจสอบเพื่อวัดประสิทธิภาพแอป AI
- นำแนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัยมาใช้สำหรับการจัดเก็บและรันโมเดล AI ในเครื่อง
- วางแผนกลยุทธ์การปรับใช้สำหรับแอปองค์กรและผู้บริโภค

### ความเข้าใจทางธุรกิจและกลยุทธ์

**สถาปัตยกรรมแอป AI**
- ออกแบบสถาปัตยกรรมแบบไฮบริดที่ปรับสมดุลระหว่างการประมวลผล AI บนเครื่องและบนคลาวด์
- ประเมินข้อดีข้อเสียระหว่างขนาดโมเดล, ความแม่นยำ และความเร็วในการอนุมาน
- วางแผนสถาปัตยกรรมการไหลของข้อมูลเพื่อรักษาความเป็นส่วนตัวพร้อมทั้งให้ความฉลาด
- นำเสนอวิธีแก้ AI ที่คุ้มค่าซึ่งขยายตัวได้ตามความต้องการของผู้ใช้

**การวางตำแหน่งทางการตลาด**
- เข้าใจข้อได้เปรียบการแข่งขันของแอป AI ที่เนทีฟสำหรับ Windows
- ระบุกรณีการใช้งานที่ AI บนเครื่องมอบประสบการณ์ผู้ใช้ที่เหนือกว่า
- พัฒนากลยุทธ์การเข้าสู่ตลาดสำหรับแอป Windows ที่เพิ่มประสิทธิภาพ AI
- วางตำแหน่งแอปเพื่อใช้ประโยชน์จากประโยชน์ของระบบนิเวศ Windows

### ข้อกำหนดเบื้องต้นของตัวอย่าง

**ข้อกำหนดระบบ:**
- พีซี Windows 11 รุ่น 24H2 (build 26100) หรือสูงกว่า
- Visual Studio 2022 พร้อม workloads C++ และ .NET
- Windows App SDK 1.8.1 หรือใหม่กว่า
- Python 3.10-3.13 สำหรับตัวอย่าง Python บนอุปกรณ์ x64 และ ARM64

**เฉพาะ Windows AI Foundry:**
- แนะนำใช้ Copilot+ PC สำหรับประสิทธิภาพสูงสุด
- การกำหนดค่า build ARM64 สำหรับตัวอย่าง Windows AI
- ต้องมีตัวตนแพ็คเกจ (แอปไม่แพ็คเกจไม่รองรับแล้ว)

### กระบวนการทำงานตัวอย่างทั่วไป

ตัวอย่าง Windows ML ส่วนใหญ่ใช้รูปแบบมาตรฐานนี้:

1. **เริ่มต้นสภาพแวดล้อม** - สร้างสภาพแวดล้อม ONNX Runtime
2. **ลงทะเบียนโปรไวเดอร์การประมวลผล** - ค้นหาและลงทะเบียนฮาร์ดแวร์เร่งความเร็วที่พร้อมใช้งาน (CPU, GPU, NPU)
3. **โหลดโมเดล** - โหลดโมเดล ONNX และคอมไพล์สำหรับฮาร์ดแวร์เป้าหมาย (ถ้ามี)
4. **เตรียมข้อมูลเข้า** - แปลงภาพ/ข้อมูลเป็นรูปแบบอินพุตของโมเดล
5. **รันอนุมาน** - รันโมเดลและรับการทำนาย
6. **ประมวลผลผลลัพธ์** - ใช้ softmax และแสดงการทำนายที่ดีที่สุด

### ไฟล์โมเดลที่ใช้

| โมเดล | จุดประสงค์ | รวมอยู่ | หมายเหตุ |
|-------|---------|----------|-------|
| SqueezeNet | การจัดประเภทภาพขนาดเบา | ✅ รวมอยู่ | ฝึกไว้ล่วงหน้า พร้อมใช้ |
| ResNet-50 | การจัดประเภทภาพที่มีความแม่นยำสูง | ❌ ต้องแปลงโมเดล | ใช้ [AI Toolkit](https://code.visualstudio.com/docs/intelligentapps/modelconversion) สำหรับแปลงโมเดล |

### การรองรับฮาร์ดแวร์

ตัวอย่างทั้งหมดตรวจจับและใช้ฮาร์ดแวร์ที่มีโดยอัตโนมัติ:
- **CPU** - รองรับได้สากลทั้งอุปกรณ์ Windows ทุกชนิด
- **GPU** - ตรวจจับอัตโนมัติและปรับแต่งสำหรับฮาร์ดแวร์กราฟิกที่พร้อมใช้งาน
- **NPU** - ใช้หน่วยประมวลผลประสาทเทียมบนอุปกรณ์ที่รองรับ (Copilot+ PCs)

## ส่วนประกอบแพลตฟอร์ม Windows AI Foundry

### 1. Windows AI APIs

Windows AI APIs มีความสามารถ AI ที่พร้อมใช้งานทันทีซึ่งขับเคลื่อนโดยโมเดลบนเครื่อง ปรับแต่งเพื่อประสิทธิภาพสูงบนอุปกรณ์ Copilot+ PC โดยต้องการการตั้งค่าขั้นต่ำ

#### หมวดหมู่ API หลัก

**โมเดลภาษา Phi Silica**
- โมเดลภาษาเล็กแต่ทรงพลังสำหรับการสร้างข้อความและเหตุผล
- ปรับแต่งสำหรับการอนุมานแบบเรียลไทม์ด้วยการใช้พลังงานต่ำที่สุด
- รองรับการปรับแต่งเฉพาะด้วยเทคนิค LoRA
- ผสานกับระบบค้นหาความหมายและดึงข้อมูลความรู้ของ Windows

**Windows Computer Vision APIs**
- **การรู้จำข้อความ (OCR)**: ดึงข้อความจากภาพด้วยความแม่นยำสูง
- **Image Super Resolution**: ย่อ/ขยายภาพด้วยโมเดล AI บนเครื่อง
- **Image Segmentation**: ระบุและแยกวัตถุเฉพาะในภาพ
- **Image Description**: สร้างคำบรรยายข้อความละเอียดสำหรับเนื้อหาภาพ
- **Object Erase**: ลบวัตถุที่ไม่ต้องการจากภาพด้วยการเติมภาพเทียมด้วย AI

**ความสามารถมัลติ-โมดอล**
- **การผนวกสายตา-ภาษา**: รวมความเข้าใจข้อความและภาพ
- **การค้นหาความหมาย**: ให้การค้นหาด้วยภาษาธรรมชาติข้ามเนื้อหามัลติมีเดีย
- **การดึงข้อมูลความรู้**: สร้างประสบการณ์การค้นหาที่ชาญฉลาดด้วยข้อมูลในเครื่อง

### 2. Foundry Local

Foundry Local มอบการเข้าถึงอย่างรวดเร็วแก่โมเดลภาษาโอเพนซอร์สที่พร้อมใช้งานบน Windows Silicon ให้ความสามารถในการเรียกดู, ทดสอบ, โต้ตอบ และปรับใช้โมเดลในแอปพลิเคชันท้องถิ่น

#### ตัวอย่างแอป Foundry Local

ที่เก็บ [Foundry Local repository](https://github.com/microsoft/Foundry-Local/tree/main/samples) มีตัวอย่างครบถ้วนในหลายภาษาและเฟรมเวิร์ก แสดงรูปแบบการบูรณาการและกรณีใช้งานต่างๆ

| [electron/foundry-chat](https://github.com/microsoft/Foundry-Local/tree/main/samples/electron/foundry-chat) | JavaScript / Electron | แอปแชทเดสก์ท็อป | แชทรูปแบบข้ามแพลตฟอร์ม, การสลับโมเดลในเครื่อง/คลาวด์, การผนวก OpenAI SDK, สตรีมแบบเรียลไทม์ |

| [rust/hello-foundry-local](https://github.com/microsoft/Foundry-Local/tree/main/samples/rust/hello-foundry-local) | Rust | การรวมระบบ | การใช้งาน SDK ระดับต่ำ, การดำเนินงานแบบอะซิงโครนัส, ลูกค้า HTTP reqwest |

#### หมวดหมู่ตัวอย่างตามกรณีการใช้งาน

**RAG (การสร้างด้วยการดึงข้อมูลเพิ่ม)**
- **dotNET/rag**: การใช้งาน RAG อย่างสมบูรณ์โดยใช้ Semantic Kernel, ฐานข้อมูลเวกเตอร์ Qdrant และ embedding ของ JINA
- **สถาปัตยกรรม**: การนำเข้เอกสาร → การแบ่งชิ้นข้อความ → embedding เวกเตอร์ → การค้นหาความเหมือน → การตอบสนองที่รับรู้บริบท
- **เทคโนโลยี**: Microsoft.SemanticKernel, Qdrant.Client, embedding BERT ONNX, การสตรีมการเติมแชท

**แอปเดสก์ท็อป**
- **electron/foundry-chat**: แอปแชทพร้อมใช้งานจริงที่รองรับการสลับโมเดลท้องถิ่น/คลาวด์
- **ฟีเจอร์**: ตัวเลือกโมเดล, การตอบสนองแบบสตรีม, การจัดการข้อผิดพลาด, การเผยแพร่ข้ามแพลตฟอร์ม
- **สถาปัตยกรรม**: กระบวนการหลัก Electron, การสื่อสาร IPC, สคริปต์ preload ที่ปลอดภัย

**ตัวอย่างการรวม SDK**
- **JavaScript (Node.js)**: การโต้ตอบโมเดลพื้นฐานและการตอบสนองแบบสตรีม
- **Python**: การใช้งาน API ที่เข้ากันได้กับ OpenAI โดยใช้สตรีมแบบอะซิงโครนัส
- **Rust**: การรวมระดับต่ำกับ reqwest และ tokio สำหรับการดำเนินงานอะซิงโครนัส

#### ฟีเจอร์สำคัญ

**แค็ตตาล็อกโมเดล**

- การรวมกับสภาพแวดล้อมพัฒนาที่นิยมและ CI/CD pipelines

- รองรับรูปแบบและการกำหนดค่าโมเดลที่กำหนดเอง
- การให้บริการโมเดลที่มีประสิทธิภาพพร้อมการปรับแต่งฮาร์ดแวร์อัตโนมัติ

### 3. Windows ML

Windows ML ทำหน้าที่เป็นแพลตฟอร์ม AI แกนกลางและรันไทม์การคาดเดาแบบบูรณาการบน Windows ช่วยให้นักพัฒนาสามารถปรับใช้โมเดลที่กำหนดเองอย่างมีประสิทธิภาพบนระบบฮาร์ดแวร์ Windows ที่หลากหลาย

#### ประโยชน์ของสถาปัตยกรรม

**รองรับฮาร์ดแวร์สากล**
- ปรับแต่งอัตโนมัติสำหรับซิลิกอน AMD, Intel, NVIDIA และ Qualcomm
- รองรับการประมวลผลด้วย CPU, GPU และ NPU พร้อมการสลับอย่างโปร่งใส
- การแยกชั้นฮาร์ดแวร์ที่ขจัดงานปรับแต่งเฉพาะแพลตฟอร์ม

**ความยืดหยุ่นของโมเดล**
- รองรับรูปแบบโมเดล ONNX พร้อมการแปลงอัตโนมัติจากเฟรมเวิร์กยอดนิยม
- การปรับใช้โมเดลแบบกำหนดเองที่มีประสิทธิภาพระดับการผลิต
- การรวมกับสถาปัตยกรรมแอป Windows ที่มีอยู่

**การรวมองค์กร**
- เข้ากันได้กับกรอบการรักษาความปลอดภัยและการปฏิบัติตามของ Windows
- รองรับเครื่องมือการเปิดใช้งานและจัดการสำหรับองค์กร
- การรวมกับระบบการจัดการและตรวจสอบอุปกรณ์ Windows

**การปรับแต่งประสิทธิภาพ**
- ทำโปรไฟล์ประสิทธิภาพของแอปบนการกำหนดค่าฮาร์ดแวร์เป้าหมายต่าง ๆ
- ปรับการใช้หน่วยความจำและกลยุทธ์การโหลดโมเดลให้เหมาะสม
- นำพฤติกรรมแบบปรับตัวมาใช้ตามความสามารถฮาร์ดแวร์ที่มีอยู่
- ปรับแต่งประสบการณ์ผู้ใช้สำหรับสถานการณ์ประสิทธิภาพที่แตกต่างกัน

**การเปิดใช้งานจริง**
- แพ็คเกจแอปพร้อมด้วยการพึ่งพาโมเดล AI อย่างเหมาะสม
- นำกลไกการอัปเดตสำหรับโมเดลและตรรกะแอปไปใช้
- กำหนดค่าการตรวจสอบและวิเคราะห์สำหรับสภาพแวดล้อมการผลิต
- วางแผนกลยุทธ์การเปิดตัวสำหรับองค์กรและผู้บริโภค

## ตัวอย่างการนำไปใช้จริง

### ตัวอย่างที่ 1: แอปพลิเคชันประมวลผลเอกสารอัจฉริยะ

สร้างแอป Windows ที่ประมวลผลเอกสารโดยใช้ความสามารถ AI หลายด้าน:

**เทคโนโลยีที่ใช้:**
- Phi Silica สำหรับการสรุปเอกสารและตอบคำถาม
- OCR API สำหรับการแยกข้อความจากเอกสารสแกน
- API คำอธิบายภาพสำหรับการวิเคราะห์แผนภูมิและไดอะแกรม
- โมเดล ONNX แบบกำหนดเองสำหรับการจำแนกเอกสาร

**แนวทางการดำเนินการ:**
- ออกแบบสถาปัตยกรรมแบบโมดูลาร์ด้วยส่วนประกอบ AI ที่ต่อพ่วงได้
- นำการประมวลผลแบบอะซิงโครนัสสำหรับชุดเอกสารขนาดใหญ่ไปใช้
- เพิ่มตัวบ่งชี้ความก้าวหน้าและการรองรับการยกเลิกสำหรับการดำเนินการที่ใช้เวลานาน
- รวมความสามารถออฟไลน์สำหรับการประมวลผลเอกสารที่ละเอียดอ่อน

### ตัวอย่างที่ 2: ระบบบริหารจัดการสินค้าคงคลังค้าปลีก

สร้างระบบสินค้าคงคลังที่ใช้ AI สำหรับแอปค้าปลีก:

**เทคโนโลยีที่ใช้:**
- การแบ่งส่วนภาพสำหรับการระบุสินค้า
- โมเดลวิสัยทัศน์แบบกำหนดเองสำหรับการจำแนกแบรนด์และหมวดหมู่
- การนำ Foundry Local มาปรับใช้กับโมเดลภาษาเฉพาะค้าปลีก
- การรวมกับระบบ POS และสินค้าคงคลังที่มีอยู่

**แนวทางการดำเนินการ:**
- สร้างการรวมกล้องเพื่อการสแกนสินค้าตามเวลาจริง
- นำการรู้จำบาร์โค้ดและสินค้าด้วยภาพไปใช้
- เพิ่มคำถามเกี่ยวกับสินค้าคงคลังด้วยภาษาธรรมชาติโดยใช้โมเดลภาษาท้องถิ่น
- ออกแบบสถาปัตยกรรมที่สามารถขยายขนาดสำหรับการเปิดใช้งานหลายร้าน

### ตัวอย่างที่ 3: ผู้ช่วยเอกสารด้านสุขภาพ

พัฒนาระบบจัดการเอกสารด้านสุขภาพที่รักษาความเป็นส่วนตัว:

**เทคโนโลยีที่ใช้:**
- Phi Silica สำหรับการสร้างบันทึกทางการแพทย์และสนับสนุนตัดสินใจคลินิก
- OCR สำหรับการแปลงบันทึกทางการแพทย์ที่เขียนด้วยลายมือเป็นดิจิทัล
- โมเดลภาษาแพทย์แบบกำหนดเองที่ปรับใช้ผ่าน Windows ML
- การจัดเก็บเวกเตอร์ท้องถิ่นสำหรับการดึงความรู้ทางการแพทย์

**แนวทางการดำเนินการ:**
- ตรวจสอบให้แน่ใจว่าการทำงานเป็นแบบออฟไลน์เต็มรูปแบบเพื่อความเป็นส่วนตัวของผู้ป่วย
- นำการตรวจสอบและแนะนำคำศัพท์ทางการแพทย์ไปใช้
- เพิ่มการบันทึกการตรวจสอบเพื่อปฏิบัติตามกฎระเบียบ
- ออกแบบการรวมกับระบบบันทึกสุขภาพอิเล็กทรอนิกส์ที่มีอยู่

## กลยุทธ์การปรับแต่งประสิทธิภาพ

### การพัฒนาที่รับรู้ฮาร์ดแวร์

**การปรับแต่ง NPU**
- ออกแบบแอปเพื่อใช้ประโยชน์จากความสามารถ NPU บน Copilot+ PC
- นำการย้อนกลับไปใช้ GPU/CPU อย่างนุ่มนวลในอุปกรณ์ที่ไม่มี NPU
- ปรับแต่งรูปแบบโมเดลสำหรับการเร่งความเร็วเฉพาะ NPU
- ตรวจสอบการใช้งาน NPU และลักษณะทางความร้อน

**การจัดการหน่วยความจำ**
- นำกลยุทธ์การโหลดและแคชโมเดลที่มีประสิทธิภาพมาใช้
- ใช้การทำแมปหน่วยความจำสำหรับโมเดลขนาดใหญ่เพื่อลดเวลาการเริ่มต้น
- ออกแบบแอปที่ใส่ใจหน่วยความจำสำหรับอุปกรณ์ที่มีข้อจำกัดทรัพยากร
- นำการควอนไทซ์โมเดลมาใช้สำหรับการปรับแต่งหน่วยความจำ

**ประสิทธิภาพแบตเตอรี่**
- ปรับแต่งการดำเนินงาน AI ให้ใช้พลังงานต่ำที่สุด
- ใช้การประมวลผลแบบปรับตัวตามสถานะแบตเตอรี่
- ออกแบบการประมวลผลพื้นหลังที่มีประสิทธิภาพสำหรับการดำเนินงาน AI อย่างต่อเนื่อง
- ใช้เครื่องมือโปรไฟล์พลังงานเพื่อลดการใช้พลังงาน

### การพิจารณาความสามารถในการปรับขนาด

**มัลติเทรดดิ้ง**
- ออกแบบการดำเนินงาน AI ที่ปลอดภัยสำหรับหลายเธรดเพื่อประมวลผลพร้อมกัน
- นำการแจกจ่ายงานอย่างมีประสิทธิภาพไปใช้บนคอร์ที่มีอยู่
- ใช้รูปแบบ async/await สำหรับการดำเนินงาน AI แบบไม่บล็อก
- วางแผนการปรับแต่งเธรดพูลสำหรับการกำหนดค่าฮาร์ดแวร์ต่างๆ

**กลยุทธ์แคช**
- นำการแคชอัจฉริยะสำหรับการดำเนินงาน AI ที่ใช้บ่อยมาใช้
- ออกแบบกลยุทธ์การล้างแคชสำหรับการอัปเดตโมเดล
- ใช้แคชถาวรสำหรับการเตรียมข้อมูลก่อนประมวลผลที่มีค่าใช้จ่ายสูง
- นำแคชแบบกระจายไปใช้สำหรับสถานการณ์ที่มีผู้ใช้หลายคน

## แนวทางปฏิบัติที่ดีที่สุดด้านความปลอดภัยและความเป็นส่วนตัว

### การปกป้องข้อมูล

**การประมวลผลภายในเครื่อง**
- ตรวจสอบให้แน่ใจว่าข้อมูลที่ละเอียดอ่อนไม่เคยออกจากอุปกรณ์ท้องถิ่น
- ใช้การจัดเก็บที่ปลอดภัยสำหรับโมเดล AI และข้อมูลชั่วคราว
- ใช้คุณสมบัติความปลอดภัยของ Windows สำหรับการแซนด์บ็อกแอป
- ใช้การเข้ารหัสสำหรับโมเดลที่จัดเก็บและผลการประมวลผลกลาง

**ความปลอดภัยของโมเดล**
- ตรวจสอบความสมบูรณ์ของโมเดลก่อนการโหลดและการดำเนินงาน
- นำกลไกการอัปเดตโมเดลที่ปลอดภัยมาใช้
- ใช้โมเดลที่ลงนามเพื่อป้องกันการปลอมแปลง
- ใช้การควบคุมการเข้าถึงสำหรับไฟล์โมเดลและการกำหนดค่า

### การพิจารณาการปฏิบัติตามกฎระเบียบ

**การสอดคล้องกับกฎระเบียบ**
- ออกแบบแอปเพื่อให้สอดคล้องกับ GDPR, HIPAA และข้อกำหนดอื่น ๆ
- นำการบันทึกตรวจสอบสำหรับกระบวนการตัดสินใจ AI มาใช้
- ให้ฟีเจอร์ความโปร่งใสสำหรับผลลัพธ์ที่สร้างโดย AI
- เปิดใช้งานการควบคุมผู้ใช้ในกระบวนการประมวลผลข้อมูล AI

**ความปลอดภัยองค์กร**
- การรวมกับนโยบายความปลอดภัยองค์กรของ Windows
- รองรับการเปิดใช้งานแบบมีการจัดการผ่านเครื่องมือจัดการองค์กร
- นำการควบคุมการเข้าถึงตามบทบาทสำหรับฟีเจอร์ AI มาใช้
- ให้สิทธิ์การดูแลระบบสำหรับฟังก์ชัน AI

## การแก้ไขปัญหาและการดีบัก

### ความท้าทายทั่วไปในการพัฒนา

**ปัญหาการกำหนดค่า Build**
- ตรวจสอบการกำหนดค่าแพลตฟอร์ม ARM64 สำหรับตัวอย่าง Windows AI API
- ตรวจสอบความเข้ากันได้ของเวอร์ชัน Windows App SDK (ต้องการ 1.8.1+)
- ตรวจสอบการกำหนดตัวตนของแพ็คเกจให้ถูกต้อง (จำเป็นสำหรับ Windows AI APIs)
- ตรวจสอบว่าเครื่องมือสร้างรองรับเวอร์ชันเฟรมเวิร์กเป้าหมาย

**ปัญหาการโหลดโมเดล**
- ตรวจสอบความเข้ากันได้ของโมเดล ONNX กับ Windows ML
- ตรวจสอบความสมบูรณ์ของไฟล์โมเดลและข้อกำหนดรูปแบบ
- ตรวจสอบความต้องการความสามารถของฮาร์ดแวร์สำหรับโมเดลเฉพาะ
- ดีบักปัญหาการจัดสรรหน่วยความจำระหว่างการโหลดโมเดล
- ตรวจสอบการลงทะเบียน execution provider สำหรับการเร่งความเร็วฮาร์ดแวร์

**การพิจารณาโหมดเปิดใช้งาน**
- **โหมดแบบมีไฟล์ครบถ้วน**: รองรับเต็มที่กับขนาดการเปิดใช้งานที่ใหญ่กว่า
- **โหมดขึ้นกับ Framework**: ขนาดรอยเท้าเล็กลงแต่ต้องการ runtime ร่วม
- **แอปพลิเคชันที่ไม่มีแพ็กเกจ**: ไม่ได้รับการสนับสนุนสำหรับ Windows AI APIs อีกต่อไป
- ใช้คำสั่ง `dotnet run -p:Platform=ARM64 -p:SelfContained=true` สำหรับการเปิดใช้งาน ARM64 แบบมีไฟล์ครบถ้วน

**ปัญหาด้านประสิทธิภาพ**
- ทำโปรไฟล์ประสิทธิภาพของแอปบนการกำหนดค่าฮาร์ดแวร์ที่แตกต่างกัน
- ระบุคอขวดในสายการประมวลผล AI
- ปรับแต่งกระบวนการเตรียมข้อมูลก่อนและหลังการประมวลผล
- นำการตรวจสอบประสิทธิภาพและการแจ้งเตือนมาใช้

**ความยากลำบากในการรวมระบบ**
- ดีบักปัญหาการรวม API พร้อมการจัดการข้อผิดพลาดที่เหมาะสม
- ตรวจสอบรูปแบบข้อมูลอินพุตและข้อกำหนดการเตรียมข้อมูลก่อนประมวลผล
- ทดสอบกรณีขอบเขตและเงื่อนไขข้อผิดพลาดอย่างละเอียด
- นำการบันทึกแบบครอบคลุมมาใช้เพื่อดีบักปัญหาในสภาพแวดล้อมการผลิต

### เครื่องมือและเทคนิคการดีบัก

**การรวม Visual Studio**
- ใช้ AI Toolkit debugger สำหรับการวิเคราะห์การทำงานของโมเดล
- นำการโปรไฟล์ประสิทธิภาพสำหรับการดำเนินงาน AI มาใช้
- ดีบักการดำเนินงาน AI แบบอะซิงโครนัสพร้อมการจัดการข้อยกเว้นที่เหมาะสม
- ใช้เครื่องมือโปรไฟล์หน่วยความจำสำหรับการปรับแต่ง

**เครื่องมือ Windows AI Foundry**
- ใช้ Foundry Local CLI สำหรับการทดสอบและการตรวจสอบโมเดล
- ใช้เครื่องมือทดสอบ Windows AI API สำหรับการตรวจสอบการรวมระบบ
- นำการบันทึกที่กำหนดเองมาใช้สำหรับการตรวจสอบการทำงาน AI
- สร้างการทดสอบอัตโนมัติสำหรับความน่าเชื่อถือของฟังก์ชัน AI

**การอัปเดตโมเดล**
- นำกลไกการอัปเดตโมเดลที่ราบรื่นมาใช้
- ออกแบบแอปเพื่อปรับตัวกับความสามารถของโมเดลที่ดีขึ้น
- วางแผนสำหรับความเข้ากันได้ย้อนหลังกับโมเดลที่มีอยู่แล้ว
- นำการทดสอบ A/B สำหรับการประเมินประสิทธิภาพโมเดลมาใช้

**วิวัฒนาการของฟีเจอร์**
- ออกแบบสถาปัตยกรรมโมดูลาร์ที่รองรับความสามารถ AI ใหม่
- วางแผนสำหรับการรวม Windows AI API ที่เกิดใหม่
- นำฟีเจอร์แฟลกมาใช้สำหรับการเปิดตัวความสามารถแบบค่อยเป็นค่อยไป
- ออกแบบส่วนต่อประสานผู้ใช้ที่ปรับตัวตามฟีเจอร์ AI ที่เพิ่มขึ้น

## สรุป

การพัฒนา Windows Edge AI เป็นการรวมตัวของความสามารถ AI ที่ทรงพลังกับแพลตฟอร์ม Windows ที่มั่นคง ปลอดภัย และปรับขนาดได้ โดยการเชี่ยวชาญในระบบนิเวศ Windows AI Foundry นักพัฒนาสามารถสร้างแอปอัจฉริยะที่ให้ประสบการณ์ผู้ใช้ที่ยอดเยี่ยมพร้อมกับรักษามาตรฐานสูงสุดด้านความเป็นส่วนตัว ความปลอดภัย และประสิทธิภาพ

การรวมกันของ Windows AI APIs, Foundry Local และ Windows ML มอบรากฐานที่ไม่มีใครเทียบสำหรับการสร้างแอป Windows อัจฉริยะรุ่นถัดไป เมื่อ AI ยังคงพัฒนา แพลตฟอร์ม Windows จะช่วยให้แอปของคุณปรับขนาดตามเทคโนโลยีใหม่ๆ พร้อมกับรักษาความเข้ากันได้และประสิทธิภาพในระบบฮาร์ดแวร์ Windows ที่หลากหลาย

ไม่ว่าคุณจะสร้างแอปสำหรับผู้บริโภค โซลูชันองค์กร หรือเครื่องมือเฉพาะทางอุตสาหกรรม การพัฒนา Windows Edge AI ช่วยให้คุณสร้างประสบการณ์ที่ชาญฉลาด ตอบสนองได้ดี และรวมอย่างลึกซึ้งที่ใช้ประโยชน์เต็มศักยภาพของอุปกรณ์ Windows สมัยใหม่
